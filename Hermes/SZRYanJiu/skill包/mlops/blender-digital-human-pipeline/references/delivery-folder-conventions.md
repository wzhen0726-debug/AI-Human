# 交付文件夹整理规范 (05环节定型, 2026-09-03用户认可)

用户说"整理一下这个文件夹"时:
1. 对齐兄弟环节结构: 主产物.blend在根目录 + scripts/ + logs/ + README.md (+点位指南/测试记录等主题md)
2. 管线/自检脚本全移入scripts/; 删一次性diag_*脚本和被取代的过时脚本; 删*.blend1备份。
3. README.md写: 产物表、脚本表、用法命令、关键规则(血泪教训)。
4. 最终测试数据写入记录md; 整理后提交git+推送。logs/不入git。
5. Windows坑: bash里`2>nul`会在目录里生成字面`nul`文件, 导致git add报"error: open(...nul)"。用python删: os.remove("\\\\?\\"+绝对路径)。本项目已出现3次, 整理时顺手全仓扫。
6. 打点提示图: 用户自己在Blender GUI截图, 不要替他渲染标记点图(视口Empty不入渲染; 造mesh球也被拒)。

## 交付镜像 ↔ 工作版 对账同步 (用户会点名"检查不同步的地方并同步")

场景: 独立出来的演示版/工作版持续迭代, 而交付镜像与方案md 停在更早状态。程序(顺序):

1. **差异清单(先看再动)**: 逐环节对同名文件做哈希对比(只比 py/md/json), 输出四类 —— 相同 / 内容不同 / 仅镜像有 / 仅工作版有。按 `相对路径 → md5前8` 建字典再集合比较, 一次看清谁落后; 日志脚本落 `logs/_sync_check.py` 形态。
2. **脚本同步方向 = 工作版 → 交付镜像**(工作版=当前权威实现)。复制全部 py/json 与同主题 md; **脚本的数据依赖(如 `01a眼窝眼球/3ddfa/` 三 json)一并复制到镜像同级** —— 只搬脚本会让镜像脚本找不到输入。用户的手调工作数据本身不复制、不覆盖、不提交。
3. **镜像 README 加同步注记**: 每个 stage 的 README 顶部插一行"> 本目录脚本已与 <工作版> 同步; 本目录为交付镜像"。纯占位 README("待编写")要么重写为正式文档、要么明确指向方案md对应文件。
4. **复验**: 重跑差异脚本应零"内容不同"; 有意未同步项(历史截图/models/一次性诊断脚本)在记录里列明。部分脚本内含指向工作版的绝对路径属预期(同机运行), 不要顺手改成相对路径。
5. **方案md 侧**: 根索引更新(日期/状态行/结论追加编号); 占位文档补全为正式文档; 阶段档案追加"追加(日期)"节(**保留历史正文不重写**); 项目复盘总记录追加本轮; 并在 `_方案与WBS/` **新建一份《同步记录》文档**(写清: 比对方法、逐环节同步清单与计数、有意未动项)。
6. **skill 镜像**: `bash skill包/sync_skills.sh out`(Hermes 技能目录 → 仓库 skill包; 方向 out = AI 更新后向外同步), 完成后与脚本/文档一起提交推送 —— 三处(镜像脚本/方案md/skill包)一次 commit 说明白。
7. 工作版里被 git 跟踪的手调 json 显示 modified 属正常态: 保持磁盘最新版、**不提交也不回滚**。
