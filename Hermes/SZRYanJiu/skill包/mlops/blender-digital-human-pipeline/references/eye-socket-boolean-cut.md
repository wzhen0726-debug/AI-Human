# 眼窝开孔: 棱柱 boolean EXACT 切割 (替换洪泛删面)

## 何时用
需要眼洞边界**严格贴合手绘/手描轮廓**时。洪泛删面的洞边界只能落在网格边环上,
密网格(0.4mm边)下到轮廓偏差可达 ~0.9mm, 红色材质边界因此有锯齿/尖角。

## ⚠ 重建边界时的三个硬教训(每条都踩过)
1. **bmesh 新建面后必须 `bm.normal_update()` 再读 `f.normal`** —— `bm.faces.new()` 之后 `f.normal` 是惰性/旧值,
   据此做的定向判据会"全部通过"但存盘后绕序仍是反的(实测 R 眼 628/728 面朝后, 而判据报 0 个需翻转)。
2. **绝不写 `ref = -ref` 这类"跟随自身"的定向逻辑** —— 等价于永不翻转。
3. **验证判据必须独立于修复判据**: 修复用"共顶点邻面平均法线", 验证就得换一套,
   例如"正视相机下法线朝后(+Y)=红"(与 Blender 面朝向 overlay 同原理); 同源判据 = 自证陷阱。

## rim 边界顶点的深度取值
不要自己采样:
- 沿 Y `ray_cast`: 洞口范围内射线穿透打到后脑(y 差 ~200mm) → 长刺
- `closest_point_on_mesh`: 取到眼窝深处内壁 → rim 被拽深 ~10mm(用户: "Y轴拉平、眼眶变形")
- **正解**: 沿用【原边界在相同角度上的 y】(角度插值)。原边界本就在表面上, 是唯一真值,
  这样重建只改 XZ(换成平滑手描线), 3D 形态与原来完全一致。

## 程序化/通用性（输入模型会变：头围、眼高、眼间距、眼型）
流程必须对**任意模型**成立，所以代码里不能留 "只对当前这个头成立" 的绝对 mm。做法：

- 新增 `derive_scale(obj, center, side, dl)`（在 `make_eye_socket` 开头调用），由
  ① 头 bbox  ② 该侧 3ddfa 的 `width_mm/height_mm`  推导全部尺度参数，写入模块级全局：
  眼区半径=0.86×眼宽；"眼中心之前" y 阈值=0.29×眼宽；后脑/前脸分界=bbox 前 44%；
  棱柱前后伸出=(眼中心到 bbox 前/后)+20% 头深；带宽=0.035×眼宽；
  细分=0.65×带宽，弧长=0.42×带宽，焊接=0.05×带宽，局部平滑R=2.5×带宽；
  轮廓重采样点数=周长/0.35mm（限 120~600）。
- **绝不能用"网格中位边长"反推带宽**：输入网格 rim 附近中位边长可达 1.3mm（0.3mm 是流水线自己细分后的结果），
  按它推会把带宽放大 4 倍 → 带越删越大 → 边界永不闭环 → 保底重试把网格越修越坏。
  带宽只能按**眼睛自身尺寸**定，与网格密度解耦。
- **两眼必须用完全相同的判据、参数与代码路径 —— 禁止单眼特判**（用户明确要求：怕再出现"只有一只眼"的缺陷）。
  反面教材：`RIM_BAND_VERT_CRIT={L:True,R:False}` 这种"一侧开一侧关"的补丁 —— 两眼地形本来就不同，
  任何单眼特判都会在下一次改动时变成单眼缺陷。地形差异只能靠**对两眼都成立的保守判据**吸收。
- **棱柱后伸只能到 rim 最深处 + ~0.25×眼宽**，绝不能按 bbox 后极算：按 bbox 算的棱柱会**贯穿整个头，把后脑勺也抠出一个洞**（用户实测）。
- 路径支持环境变量覆盖（便于换模型/批量）：`EYE_IN_BLEND` / `EYE_OUT_BLEND` / `EYE_CONTOUR_JSON` / `EYE_DDFA_JSON` / `EYE_SHOT_DIR`。
- **通用性测试方法**：造一个不同尺寸/头型的输入（网格与两份 json **同步**缩放，如 1.15/1.15/1.06），
  用环境变量指过去重跑，再用同一套验收（环度数/折返/转角/间距/轮廓偏差/反面面）对比。
  验收脚本读 `EYE_OUT_BLEND`+`EYE_CONTOUR_JSON`，可复用。

## 为 QR 准备的面型清理（重建完必须做，否则 QR 出错）
重建带的收尾顺序（缺一项用户就能看出来）：
1. ⚠ **缝合带用 Blender 原生 `bmesh.ops.bridge_loops`，不要自己写"逐点配对+三角化"**：
   手写配对在两侧地形不同时必然拉出细长/扭曲面（实测右眼明显更差，用户报修）；官方文档明确支持"两圈顶点数不同"，自带 twist 最优配对。
   做法：内圈（=手描轮廓重采样）建一圈边 + 外圈边界边 → 一起传给 bridge_loops；**桥接不改变内圈位置**，只改两圈之间的面型。
   必须带安全闸：返回面数 < K/2 或最大面 >12mm² → `delete(context='FACES')` 后回退手写路线。实测 176/159 面、最大面 2.7mm²。
2. **n-gon 三角化**：细分/缝合会造出 >4 边面。`bmesh.ops.triangulate(ngon_method='BEAUTY')` 需**迭代到 0**（一轮不够）。
2. **缝合带密度必须与周围皮肤一致**（先量皮肤中位边长 med，再据此推导全部阈值：FINE=0.90×med、ARC=1.40×med、长边细分阈值=1.05×med）。
   把带内细分到 0.62mm 而皮肤是 1.31mm 时，**线框远看就是一条黑带**，用户会当成"黑面/拉伸面"报回来——
   过密与过疏都是错，而"更密=更好"是错的。实测：长边细分从 10643 条→1379 条后，距轮廓各档（0~0.8/0.8~1.6/1.6~3/3~6mm）中位边长 0.55~0.87mm 平缓。
3. **长边细分**：缝合时内圈密/外圈疏会拉出长条（曾到 9.29mm、跨 8.5mm 深度）。阈值取 ~1.05×med，只清真正的长条；
   实测 >3mm 长边从 175 条→0、长宽比 max 60+→15。
4. **退化面清除**：`bmesh.ops.dissolve_degenerate(dist≈0.08mm)` —— **但只能传内部边（`len(e.link_faces)==2`）**：
   溶掉边界边会动到环拓扑，换模型时环上会出微缺口（实测每眼 2 处 1 度顶点，变成"断开"而不是闭环）。
5. **重复顶点**：`remove_doubles(眼区, dist≈0.5×焊接阈值)`；验收=距离<0.02mm 的顶点对为 0。
6. **smooth 标记**：眼区所有面 `f.smooth=True`。
7. ⚠ **任何在"收尾定向"之后新建面的操作（细分/三角化），必须在后面再跑一次定向**：新面绕序可能仍朝后。
8. **环的平滑/曲率修正只能走"轮廓重建"或"逐点校验的微调"，不能整环低通**：
   - ⛔ **整环低通（XZ-only 或三轴一致）会破坏 strip**：环顶点与带内面共用，环被独立挪动后面会 fold ——
     实测 0.35mm 与 0.8mm 位移上限都出 **9 对穿插**。曾有一版这条 pass 因静默 NameError 从未执行、
     却按"已生效"汇报了效果（见"静默失败陷阱"）；真正接上后立即被证伪 → 已停用。
   - ✅ 要"更圆的曲率"时的正解 = **回到轮廓线**（自动谐波搜索 + 全带重建，见"眼角曲率"节）；
     环上只允许**逐点**微调：阈值按该点自身步长算（允许转角 = 2·asin(step/(2R))），
     且每次移动前记录相邻面法线、移动后若被翻（点积<0.5）立即撤销并锁定该点。
   - ⚠ **目标曲率必须由算法自动推导，绝不能依赖用户手画的线**：用户明确反对"总不能每个模型我都画吧"；
     用户画线只是告诉你"要多平滑"，实现必须纯几何（自身低频重建 / 对侧水平参照）。轮廓只需大概对（会被谐波搜索重采样）。
   - 残留原则：环上任何逐顶点平滑**必须按边长加权**（或先按弧长重采样），绝不能按索引域（环顶点间距不均，索引域低通=打阶梯）；
     报数时同时给"环 vs 手描标记点偏差"。
9. **合并类操作（溶边 / 焊接 / 塌边）是"会改坏周围面"的操作，必须带两道闸**：
   ① 改完立刻量**开放边总数**（有增量 = 造出了新洞）；② 先出**用户同倍率的前后渲图**再决定去留。
   只报面质量指标（细长面数 / 长宽比 / 最小面积）会得出"指标全好、用户说错误更多"的结论。
   实测否决：把距轮廓 <3mm 内 <0.3mm 的**内部**短边整体溶掉（`dissolve_degenerate(dist=0.3mm)`）——
   指标很漂亮（穿插 L1/R0→0/0、细长面 129→23、最小面积↑2.3×），但溶了 331/120 条边把周围面全改了形、
   开放边 332→333（多一条 = 微观破洞），用户目视"错误更多了" → 回退。

**定案流水线（用户确认"曲率合适"的现行版）**：
轮廓自动谐波搜索（K 往下搜到角部半径 ≥0.07×眼宽）→ boolean 开洞（棱柱后伸=rim 最深处）→ 删带 →
**bridge_loops 桥接** → n-gon 三角化 → 长边细分（1.05×med）→ 退化清除（0.08mm，只内部边）→
局部松弛（锚定权重 exp(-(d/1.2mm)²)，30 轮，上限 0.45mm）→ 松弛后退化清除+微折角收拢 →
眼角圆化（逐点曲率阈值；向外分量 ≤0.15×皮肤边长；移动前记相邻面法线、被翻即撤销+锁定）→
折叠面翻转（面法线与邻面面积加权平均相反）→ **焊接(remove_doubles)之后必须再跑一次翻转**（焊接会重构面、留下翻面）→
smooth → **面朝向自查渲图（每眼特写+全眼，红只允许在洞口内部；再加俯视 18°/32° 掠射角）** → 交付。
所有尺度参数由 `derive_scale()` 从【头 bbox + 3ddfa 眼宽 + 皮肤中位边长】推导；**不写死 mm、不按眼特判**
（用户要求："要能随动"、"两眼同步改，怕单眼问题"）。
验收数字（现行主模型）：环单一闭环 L162/R156；转角 max L14.7°/R20.8°；真穿插 **0/0**；n-gon 0；
开放边 0（除输入自带）；每版自动打印【环 vs 手描标记点偏差】（中位 ~0.51/0.53mm，集中于眼角曲率处）；面朝向渲图两眼皮肤无红点。

**已证伪的路（别再试）**：
- **把移动过的顶点投回"原始表面"**（`obj.closest_point_on_mesh`）：⑦f/⑦h 动过的顶点会离开表面（最多 ~0.6mm），
  本能做法是投回。实测**灾难**：投回的参考面是【编辑前的原始表面】—— 洞口那片面已被删，
  等于把缝合带顶点拉回"已经挖掉的皮肤"上 → 真穿插 1 → **119 对**、环还断了（2 个 1 度顶点）。
  规则：回投/投影的参考面必须是**当前（完成删面之后）的网格**；对"已删面区域"做回投必然出事。
  悬浮只能靠**把移动量本身压小**来控，不能靠事后投回。
- **`beautify_fill` 局部重三角化**：细长面 129→138（没解决，因它只翻边不挪点，薄处依旧薄），还把 R 引出 1 对穿插。
验收口径（缺一不可）：眼周 8mm 内 n-gon=0、长边>2mm=0、退化面≈0、重复顶点=0、开放边只应存在于 rim 环
（**每次改动都量一遍开放边总数，有增量就是造了新洞**）；**眼球是独立对象** —— "眼球 vs 头部眼区"的 BVH 穿插也要查，
只查头部自身会漏掉"眼球穿出眼睑"这类问题。
一条命令跑完全部项：`scripts/mesh_health_check.py`（env `EYE_OUT_BLEND` + `EYE_CONTOUR_JSON`）。
用户报"穿插叠面 / 黑面"时**先跑这两个新判据再谈几何**：
- **真穿插面对** = BVH 两两重叠，**排除共顶点邻居**后的对数（否则全是邻接面的假阳性）——`scripts/mesh_intersect_check.py`；
- **零面积面 / 极小面积面**（<1e-3 mm²）= 0 ——正模实测 0/0，这是"黑面"的可量化来源。
（以前这两个没有判据，只能靠 vision，而 vision 会把正常密集网格说成"大量细长/破面"。）

**缺陷先定归属再动手**：把同一份体检脚本对 ①输入文件 ②本次改动前的备份 ③当前产物 各跑一遍、比数字 ——
三态里都存在（远距开放边 / 非流形 / 破口）的是**输入自带**的，不要去修；只有当前态新出现的才是本轮引入的 bug。
（实测靠这一步才发现"后脑破口/非流形/远距开放边"全是输入自带，省下一轮瞎修。）

区分"红面是错还是正常"：看它在**轮廓内还是轮廓外**——轮廓内（洞口里看到的后脑/内腔面）红是**正常**的；轮廓外（皮肤上）红才是错的。
**折叠/错乱面(红/黑斑)的修法**: 面法线与"邻面**面积加权**平均"相反 → `f.normal_flip()`(与面朝向叠加同判据, 逐面比对; 别用"与多数法线点积", 侧倾面能骗过);
实测 L 65 / R 68 面翻正后残留 ≈0.1%, 且残留多为 0.002~0.014mm² 退化面(渲染全看不见) → 报数时一并给面积。
**修复阈值与验收阈值必须一致**：按 `normal.y>0.1` 翻正、却按 `>0` 计数 → 永远会报出一批"残差"；先统一阈值，再解释剩下的。
**计数会被微观面虚高**：残留常常只是 0.002~0.014mm² 的退化面（渲染里完全看不见）→ 可见性按**面积 + 与用户同机位的正视叠加渲图**判断，不要只报个数。
**这类细结构不要问 vision**：它会把正常的密集小三角说成"大量细长三角形"（与量测上限 0.86mm 直接矛盾）—— 网格质量一律脚本定量，vision 只做宏观形状的定性复核。
**vision 的可靠用法 = 同设置对侧对比**: 同一灯光/机位/着色(腔体着色 cavity + 正视/25°/45°)把两侧各渲一张,
再让 vision 说"哪张更接近圆顺"——实测能稳定复现用户判断(左"3~5 处尖锐锯齿 + 牵拉褶皱" vs 右"整体圆顺"),
而单张绝对描述会把正常结构说成缺陷。对比渲染脚本: `scripts/rim_curvature_compare.py`。

**每版必做的"面朝向"自查（用户明确要求的验收方式，能抓出数字测不到的“面反了/面乱了”）**:
- 渲一张与 Blender 面朝向 overlay 同原理的图：每面按 `f.normal.dot(相机视向) > 0 → 红, 否则蓝`，对**每只眼**出 ①特写(内眼角/下睑/中部) ②全眼两个倍率。脚本 `scripts/face_orientation_close.py`。
- 判定：红只能出现在**洞口内部**（看到的后脑/内腔面）；蓝色皮肤上一旦有红点/红条/红碎片、或交界处红蓝碎屑状交错 = **面反了或面乱了** ✗。
- 注意：①红不一定就是法线反——也可能是面乱（自交/折叠）导致的朝向错乱；②“洞内红”是正常态，不要修；③特写倍率要盖得住整只眼（半宽≥·~0.05m），否则会漏掉框外的缺陷。
- **数值判据（如 ny>0.1 朝后计数）只当粗筛**：侧倾壁面法线横置，翻没翻 ny 都≈0 → 漏报；最终以相机判据渲图为准，
  且只认「看得见的红」——数值标记里被遮挡的面不是缺陷。Workbench `color_type='MATERIAL'` 取 `mat.diffuse_color`，只设节点 Base Color 渲出来是全灰。
- 镜头方向要用**相机矩阵**算（`cam.matrix_world.to_3x3() @ Vector((0,0,-1))`），不要用世界 -Y 近似（斜视机位会误判）。

## 做法
1. 轮廓点(手描 N 点, XZ)沿 Y 贯穿成一个**封闭棱柱**: 前盖穿到脸前 ~80mm; 后盖只伸到 **rim 最深处 + ~0.25×眼宽**(≈10mm)。
   **不要按 bbox 后极算后盖** —— 棱柱会贯穿整个头, 后脑勺被一起抠出一个洞(用户实测报修)。
2. 棱柱 = 单独 mesh+object, **给它一个专用材质**(如 `SOCKET_CUT_TMP`), 该材质也 append 到头对象上。
3. 头对象上加 BOOLEAN modifier: `operation='DIFFERENCE'`, **`solver='EXACT'`**, object=棱柱 → apply → 删棱柱。
4. 结果 = 头被冲压出一个"竖直壁+平底"的坑。**直接把这个坑当眼窝用**(不要再删壁面去重建曲面碗)。
5. 用材质槽识别 boolean 新面: `f.material_index == cut_slot` → 这些就是坑壁+坑底 → 打 tag/赋 EyeSocket。
6. 删掉临时材质槽, 不然下游材质槽列表被污染。

## 必须做的四件事(每条都对应一次实测失败)
- **棱柱法线用 `bmesh.ops.recalc_face_normals` 重算, 不要依赖点序**(仅限这种**孤立的新建对象**——
  对混有已有区域的工作网格做全局 recalc 会整片翻面, 见 `references/qr-lowpoly-eye-socket.md` 红线 1)。
  左右眼轮廓点序常反向
  (一侧由另一侧镜像) → 棱柱内外翻 → boolean 产出"3面共边"坏拓扑(实测一侧 207 条, 另一侧 0)。
- **新面识别用材质槽, 不要用几何容差**。"顶点到轮廓折线 <0.05mm" 这类判据会漏面(实测漏 47 面, 洞口被堵住)。
- **给旧清理步骤加模式闸门**。为洪泛锯齿边写的 `remove_doubles(0.1mm)` 和 sliver 溶解会把切出来的
  密集边界顶点并掉/溶掉(实测把环溶到只剩 3 个顶点)。boolean 模式: 焊接阈值降到 20µm、跳过 sliver 溶解与 rim 松弛。
- **EXACT solver 能处理非流形输入**。MANIFOLD solver 会在 0.4s 拒绝非流形扫描网格,
  **不要拿 MANIFOLD 的失败给 EXACT 定罪**——190 万面 EXACT 只需 ~8s。

## 效果(实测)
材质交界到轮廓 XZ 偏差: 中位 0.085→**0.047mm**, p90 0.28→**0.10mm**, max 0.89→**0.16mm**;
交界顶点数 84→**225**。坑壁竖直+平底, 深度由棱柱后盖决定 → 天然包住眼球。

## 下游连带改动
- 材质分区/打 tag 的"补红"闸门: 必须"所有顶点在轮廓内"(只判面心会让大三角整面染红戳出边界)。
- QR 端材质传递的"踩碗赋红": 判据必须是**面心踩碗**, 不能是"任一顶点/边中点踩碗"——
  壁面顶边就是轮廓本身, rim 处每个跨界 QR 面都有顶点在壁面上, 用"任一采样点"会把大面整面染红,
  红色戳出轮廓外(实测 5.9mm 等效边长的大面外溢 8.12mm)。改面心后外溢降到 3.1mm。
- 本质限制: QR 逐面赋材质, QR 面尺寸(1.5~3.6mm)与 rim 曲率同量级 → rim 处必有骑跨面, 红/灰二选一。
- **QR 备用参数（用户偏好，当兜底方案）**: 四边形数量 150000 / 自适应大小 95% / 使用材质 关 / 通过角度检测硬边 关 /
  对称性全关 —— 用户实测这套能规避部分 QR 后眼窝形状与破面问题; 但双方一致: 这只是备用, **主路仍是把 rim 环修干净**。
- **QR 步引擎等待的完成判据是 `progress.txt == 2`, 不是进程退出**: 实测引擎产出 `retopo.fbx`+`progress==2` 后仍会常驻不退,
  而 `while proc.poll() is None` 死等会永久挂起; 同时 `Popen(stdout=PIPE)` 不读管道也会把引擎卡死。改用输出落盘 + `progress==2` 即收掉进程,
  再加硬超时兜底(见 `references/quad-remesher-headless-xremesh.md`)。

## 模式二: 环内掏空(高模只留 rim 环 + 空腔, 眼窝在低模上补)
适用: 用户希望高模阶段只管"开一个边界正确的洞", 眼窝形状留到 QR 低模上用少量面补。
- 切完后**删掉 boolean 新面**(=坑壁+坑底, 按材质槽识别) → 环内全空, 无需材质分区/UV 重映射。

- ⚠ **掏空模式是现行为(别再当回归修)**: 01a 交付的高模只有 1 种材质(无 EyeSocket 槽), 02 日志里的"材质分区: 只有1种材质 → 按 UseMaterialIds=0 运行""无EyeSocket槽, 跳过材质传递"是**正常态**; 控制台/旧文档若还写着"眼窝独立材质(供 QR 沿 rim 布线)", 那是**未启用的旧设计**, 不要为它去补材质分区(要恢复材质引导先问用户)。实测掏空模式的 QR 输出眼区干净(>5 边长比仅 1 面), 眼窝质量问题更多出在低模碗工序(见 `qr-socket-bowl.md` §收口两条硬约束)。
- 交付给用户检查的中间件应含: rim 环 + 空腔 + 无多余材质; 顺手核对开放边数 = 两环顶点数(+ 源网格自带小缝)。
- 低模上补碗(QR 后眼窝制作)的完整做法/球体拟合/镜像绕序/多轮自检口径: `references/qr-lowpoly-eye-socket.md`。

## rim 环的 3D 平直度(换角度看"不直"的根因与修法)
环 = 网格边环, 同时继承两个源头:
1. **扫描面微噪声** — 相邻点深度二阶差分 中位 0.11mm / max 0.9~1.1mm;
2. **手描轮廓自身不光滑** — 72 点轮廓 turn mean 5.2° / max 55.4°(可能还有 180° 退化点)。
   而 boolean 切出的边界 XZ 投影**严格等于该轮廓** → 折角被 1:1 复制到环上: 正视图看不出, 一转视角就现形。
**量化**(按顶点序的闭环指标): 3D 相邻边转角 mean/max、深度 y 二阶差分、相对平滑副本的偏移。
注意"相对平滑副本的偏移"里**含平滑本身的收缩**(Laplacian 收缩量与抖动同级) → 别把收缩当抖动, 判定要三个指标一起看。
**高斯窗基线尤其坑**: 高曲率处基线整体向内退 ~κσ²/2(σ=4mm 时平滑区本底就有 ~0.77mm),
能把一段**贴线良好**的环报成"2mm 突刺"(实测那段到手描线只有 0.12~0.47mm)。
⇒ 判环"圆不圆"的主判据 = **转角剖面**(mean/max/>阈值点数, 按弧长窗口) + **同设置对侧对比渲图**;
"相对平滑副本的最大偏移"只当辅助, 且必须扣掉本底。
**修法(按性价比)**
- 轮廓光滑化(**主力**): 等弧长重采样 240 点 + 闭合 DFT 低通只留前 N 次谐波。
  N=8 → 与手描偏差 0.57mm/转角 max 11.5°; N=12 → 0.34mm/14.3°; N=16 → 0.22mm/16.8°。
  选 N 的判据: 让眼角曲率半径 ≈ 解剖上的 ~1mm, 别一味求小(过小会削掉轮廓特征)。
- 环焊接阈值 **< 网格边长/5**(0.3mm 边 → 0.06mm)。用 0.12mm 会把窄颈焊成 X 型自交,
  冒出 4 度环顶点 → 环追踪走不通、量测与渲染全乱。
- 环去刺: 相邻转角 > ~25° 的环顶点, 沿**环上**邻居(不是网格邻居)的中点做几次局部松弛。
**整圈无差别表面去噪 — 否决**(均匀位移、无衰减): 表面被改最多 1.6mm, 转角 max 只从 90° 降到 70°。
**采用: 带锚定衰减的局部松弛**(用户说"不圆 / 加个平滑或松弛 / 微调曲率"时用这套; 实测转角 max 73.4°→59.1°、可见尖锐锯齿消失):
- 选区 = 离轮廓 <2.5mm 的前表面顶点(约 3~4 千个, 只覆盖缝合带 + 一环皮肤); 顶点邻接由 bmesh 边表建、numpy 向量化。
- 权重 `w = exp(-(d轮廓/1.2mm)²)` 作锚定(远处 w→0 不动, 松弛区边缘才不会冒出新的棱——这正是"整圈去噪"失败的机理);
  30 轮 `co += 0.45·w·(邻居均值 - co)`, 循环结束后对**总位移**做硬上限截断(0.45mm)。只动既有顶点, 不改拓扑。
- 代价: 环到手描线的 XZ 偏差会涨(实测 0.33→0.66mm)——"圆顺"必须用这个换, 报数时一起报出来。
- **松弛后必须补两步**: ① 再清一次退化边(松弛把顶点挪近, 实测新造 120/67 条 <0.08mm 边 → 微折角);
  ② 环上 >60° 的微折角顶点朝两侧邻点中点收 35%, 几轮即收敛。
- 对侧眼睛是**质量参照, 不是模板**: 用户说"参考右眼的曲率 / rim 环"= 让指标收敛到对侧水平(如 R 转角 max 21.5°);
  **不要镜像照搬**(用户明确反对对称化糊弄)。手描 L/R 轮廓本就互为镜像(统计几乎相同),
  但两侧网格地形不同 → 同一条轮廓在两侧重建出的环也不同, 只能各自松弛。
- **只低通环的深度 y 剖面 — 否决**: y 二阶差分确实从 0.034 降到 0.007mm, 但 3D 转角**反而恶化**
  (L 5→25 个 >30°、R 0→26 个)。原因: 环顶点 XZ 间距不均(0.07~0.45mm), 在**索引域**做低通等于在弧长上打阶梯。
  **规则: 环上任何逐顶点量的平滑都要按边长加权(或先按弧长重采样), 不能按索引。**
**下限**: 单顶点转角 ≈ 步长/曲率半径(0.3mm 步长 + 1mm 半径 ≈ 17°), 别追求数学意义上的光滑。
**验收纪律(同一个坑踩过两次)**: 平滑类指标(转角/抖动/深度二阶差分)变好**不等于形状对**。
每改一版都要同时给出 ①**形状类硬指标**(洞口轮廓到手描线的 XZ 偏差、被改表面的最大位移) ②**同机位前后对比图**(正视 + 俯视)。
只报角度指标, 就会把"洞口轮廓被拽进 1.5mm""整圈表面被改 1.6mm"这种改坏当成成功交付给用户。

### 只在一处还剩几个折角时怎么分诊
0. **删除/清理类命令在路径重构后必须实跑核实**: `clean` 曾因路径改造被误删核心逻辑 → 变空壳(只扫 .blend1)且 `n` 未初始化(NameError), 到用户真要用时才暴露。删类命令的验收 = 跑一次 + 核对删除清单与保护清单(标记点/手调json/原始文件全在)。
1. 列出环上转角 > 阈值的顶点, 报**相对眼中心**的 dx/dz(→ 内/外眼角、上/下睑) — 通常全挤在同一处。
2. 看这些点的环到手描轮廓 XZ 偏差: ≤0.05mm ⇒ 切割是准的, 问题不在轮廓也不在切割。
3. 量那处**局部表面**在 2~3mm 内的深度跨度: 1mm 以上 ⇒ 是眼睑自身的褶/结节, 环贴上去只能跟着折。
4. **先查环在 XZ 上是否自交(折返尖) —— 这一步优先于看深度**:
   环必须先确认是**简单闭合曲线**, 再谈光滑度。做法: 把环按顶点序投影到 XZ, 相邻线段两两做线段-线段求交
   (跳过相邻段), 数交点。实测: 健康侧 0 处, "那一处折角"所在侧有 **6 处自交**, 全部集中在
   dx/dz ≈ (−6.0, −6.5)mm 的 3mm 内 —— **它才是 3D 转角 37~127° 和"正面看有缺口"的真凶**, 不是深度起伏。
   成因: 切割面沿观察轴(±Y)垂直切, 而表面在那处有个 ~1.2mm 高、近垂直的鼓包 → 边界"绕鼓包出去又折回"。
   判定顺序: 有折返 ⇒ 先修折返, **别去调平滑参数** —— 间距均匀化/深度低通只会把折返暴露得更凶
   (实测 max 转角 37.7° → 77° → 127°)。
5. **再判定是不是本质矛盾, 是就别再换切割算法**: 环的每个点必须落在表面上 → 表面在那处有台阶时,
   跨台阶只能二选一 —— 深度跳(=折角) 或 XZ 偏离(=洞口轮廓被咬一口)。换切割方向、换扫出方式都绕不开。
   实测否决: 让切割方向**跟随局部表面法向**(轮廓每点沿 Y 射线取命中点法向, 再沿法向扫出切割体) →
   每点方向不同 → 相邻切割壁互相穿插 → boolean 出垃圾(一侧洞口直接消失: 删 1332 面/环 0 顶点; 另一侧破环)。
6. 然后只有三条路, 各有代价, **让用户选, 别自己推进**:
   - 接受(残留是 ~0.4mm 半径的转弯, 只有放大才可见);
   - 手描轮廓在那一小段往里挪(**轮廓是用户的权威数据, 不能自己改**, 要改让用户在 GUI 里挪点);
   - 允许那处表面改 ~1mm(环能顺, 但下睑外观真的会变)。
   **程序化局部内收的实测(方案 2)**: 半径 4mm/内收 1.5mm 把转角 max 37.7°→28.7°、>30° 顶点 5→0(指标全过),
   但洞口轮廓在那一段被拽进 1.5mm, 正面/俯视一眼可见 → 用户直接否决。
   ⇒ 内收只能取 ≤0.5mm 量级, 且**必须先把同机位正面/俯视对比图给用户看形状**, 指标过了不算数;
   做成配置表(`RIM_LOCAL_INSET = [(side, dx_mm, dz_mm, 半径mm, 内收mm)]`), 手描 json 一个字节都不动。

### 折返尖怎么修(实测清单 — 别再从零试这些)
- **逐点法向扫出切割体 — 否决**: 每点方向不同 → 相邻切割壁互相穿插 → boolean 出垃圾(删 1332 面、环顶点归 0)。
  规则: 扫出体的方向场必须连续, 逐点独立方向必然自交。
- **同一顶点数的等弧长重采样 — 否决**: 间距确实变均匀(0.12~0.35mm), 但环顶点沿环被挪动最多 **3.03mm**;
  边界顶点与皮肤面**共用**, 沿环拖动 = 把相邻面拽变形。规则: 边界顶点均匀化只能靠**增删顶点**
  (拆长边/并退化短边), 不能靠"沿环重新分布"。
- **拆长边+并短边(只增删顶点)+ 深度按弧长低通 — 条件不成立**: 间距/抖动确实改善(L 中位抖动 0.129→0.076mm),
  但只要环本身是折返的, 均匀化只会把折返顶成更大的尖角(37.7→77→127°)。**修折返之前不要做这一步**。
- **折返"手术"(自交处切边→删中间小段→焊接 / 删段→焊两端) — 两次都否决**: 修掉 2 处后环反而烂掉
  (102 顶点 / **109 处自交** / 冒出 3 度顶点)。局部手术会让边界顶点度数瞬时非 2, 之后取环/量测/渲染全乱。
  ⇒ 折返只能**成片重建**(删掉折返附近一小带面, 用干净轮廓重新桥接皮肤)。**已实现并实测(部分成功, 未达干净)**:
  自动定位环的自交簇 → 以该簇为圆心删一小片皮肤面(圆盘) → 该处边界变成"轮廓段 + 圆盘外弧" →
  沿手描轮廓重建内圈(深度按弧长低通, 偏离原表面上限 ~0.3mm) → 内圈按外弧点数重采样后条带缝回。
  结果: 折返 6→1 处、环 395 顶点度数全 2、vision 判正视/俯视下睑边缘"更圆顺无台阶";
  但轮廓 XZ 偏差 0.161→0.328mm、环上残留一条 4.3mm 长边、第二簇需 R≈10.5mm 圆盘(被安全闸挡住)。
  ⇒ 机制成立但**还没到可直接交付的干净度**; 要做干净需: 圆盘周长先细分均匀、内圈与外弧点数严格配对、
  两簇一次覆盖、四条硬指标(折返数=0 / 顶点度数全 2 / 轮廓 XZ 偏差≤0.2mm / 开放边数一致)全过。
  **别把上面这套当"已验证可用流程"直接复用**。
- 分诊最终仍可能落回那三条路(接受 / 用户自己在 GUI 挪手描点 / 允许那处表面改 ~1mm): 折返能消失的只有后两条。

## 诊断脚本的两个坑
- **读到的日志可能是上一轮的**: 脚本崩了(如 `Vector - ndarray` 类型错)就不会重写日志文件,
  你会把上次的数据当成本次结果。读之前先确认日志刚被重写(mtime / 末尾 DONE), 并让脚本一崩就显式报错退出。
- **产物路径一改, 所有诊断/渲染脚本里硬编码的老路径都要同步改**: 否则它们静默读上一版文件,
  给你一份"毫无变化"的旧数字(实测因此误判过一次)。改路径时把项目里全部 `_*.py` 一起 grep。
- **给用户核验前先确认他打开的是新文件**: 中间件用规范名 + 明确绝对路径, 并附"自查三判据"
  (文件名与时间 / 材质槽或开放边这类结构特征 / 该看什么), 同时提醒关掉 GUI 里开着的旧标签(不保存)再打开——
  用户多次贴着旧 tab 的截图反馈, 会白跑一轮。红色面片尤其容易误判: 材质分区的红 vs 眼球对象的红是两回事。
  **反向同样成立——用户报缺陷时, 先查他看的文件与 mtime, 再查几何**: 实测用户截图里的"黑面/穿插"来自
  **两天前的下游阶段产物**(眼球摆入 01_2), 而最新上游(01_1)已经干净; 先把 mtime 量出来能省掉整轮瞎修。
  **下游"给用户看"的阶段要用最新上游重跑一次**(旧件先备份), 否则用户永远在审旧状态。
- **环追踪过岔口**: 环上出现度数 >2 的顶点时, 追踪必须"直行优先"(选与入射方向最接近的邻边),
  否则会拐到同一网格上别的开放边界, 量出十万顶点的假环。
- **bmesh 里不要用 `bm.verts[i]` 索引取顶点**: 任何 bmesh op 之后查表失效, 会抛 `KeyError: <大整数>`;
  改成每次操作后重建 `{v.index: v}` 字典再取, 并先判 key 在不在。
  **5.x 的确切报错是 `IndexError: BMElemSeq[index]: outdated internal index table`**, 解法是 `index_update()` **之后还要** `ensure_lookup_table()`
  (只做前者仍抛, 本轮因此连挂两次); `dissolve_degenerate` / `remove_doubles` / `subdivide_edges` 之后一律重新执行这两步。
- **环追踪循环写成 `while cur in nadj`**: 中途出现度数≠2 的顶点时 `nadj[cur]` 直接 KeyError,
  会把"只修坏了一点"变成"整个脚本崩掉"(崩了就不重写日志/不存盘, 见上面那条"读到上一轮日志")。
- **改产物的实验前先备份当前产物, 失败即从备份拷回; 不要重跑期望复现**: ①本轮两次修复把环弄烂, 全靠备份回拷才没把坏产物留在工作目录; ②01a 的 rim 带重建和 QR 外挂引擎重跑存在 **run-to-run 波动** —— 同一代码同一输入, 重跑版的眼角干净度可能不如已验证的旧版(实测重跑后角部极点 1→3 个, 只好把备份的最优版直接恢复)。**备份才是可复现的"最优态"**, 回退=拷回备份, 不是重跑链路。
- **`blender -b --python` 崩了照样 exit 0**: 脚本未捕获的异常只打 Traceback, 退出码仍是 0, 而产物可能只写了一半(实测一侧跑完另一侧没跑就结束了)。
  长管线跑完**必须 `grep -nE "Traceback|Error"` 查日志**, 不能只看退出码; 新加的收尾步骤各自包 try/except(失败打印"已跳过"),
  让一个可选步骤失败不至于丢掉整条重建带。
- **`bmesh.ops.delete(context='FACES')` 会保留与存活面共用的顶点** → 想用"删面前记下顶点引用、删后判新老"
  来区分"原边界 vs 新边界"必然失败(周界顶点属于老集合); 只能按几何判据(到目标折线的 XZ 距离)分类,
  阈值取在两类之间的空档(原边界点 ≈0.35mm 内, 删面周界 ≥0.8mm)。
- **面心判据删面留下的粗周界要在缝合之前细分到均匀步长**: 粗边边长可达 5mm, 直接参与缝合会生成 5mm 长条面,
  在 XZ 上横切整圈 → 被自己的折返检测当成新折返。细分必须放在缝合前; 缝合后细分会动到 `BMVert` 引用
  → `ReferenceError: BMesh data of type BMVert has been removed`。
- **两条折线缝合：优先用原生 `bmesh.ops.bridge_loops`，别手写配对**。把两圈的边都凑齐（内圈顶点新建后用
  `bm.edges.new` 补出闭边环、外圈用现成的边界边），`bridge_loops(bm, edges=两边集合, use_cyclic=True)` ——
  官方支持**两圈顶点数不同**并自带 twist 配对。手写"逐点对拉+三角化"在两侧地形不同时必然拉出细长/扭曲面
  （实测一侧明显更差，用户先报的就是那只眼）。桥接**不改变内圈**（=手描轮廓）→ rim 环本身不受影响，
  只有圈间面型变化，所以可以放心替换。
  **必须带安全闸**：返回面数 < K/2 或出现 >12mm² 的巨大面（配对跑偏的特征）→ `delete(context='FACES')` 后回退手写路线。
  手写路线的最低要求：自由那条沿目标折线**按 K 重采样**（两端保持原顶点）再逐段出四边形；"按累计弧长比值交替前进
  + 收尾三角形"的走法会**跳过顶点**（留下 1 度顶点把边界撕开）并留下长尾弦（假折返）。
- **闭环上的"连续段"检测必须从已知成员的索引起算**: 从 0 号索引起算时, 跨越环起点的同一段会被算成两段
  (表现为"外弧 2 段, 回退", 白白放弃修复)。
- **已算出的圆心若是绝对坐标, 别再叠加一次眼中心**: 混用"绝对 mm"与"相对眼中心 mm"会把圆盘整体偏到 40mm 外
  (那里一个面都没有 → 静默跳过, 看起来像"判据不满足")。
- **返回 `(距离, 索引)` 的辅助函数, 解包顺序要当场核对**: 接反会以
  `TypeError: 'float' object cannot be interpreted as an integer` 的形式在很远的下游炸出来。
- **自动增长的修复操作必须带硬闸**(最大半径 / 最多删面 / 最大位移), 超限就打印原因并放弃:
  实测第二轮补片自己要求 R=10.5mm、删 181 面, 没闸就会一路吞掉下睑表面。

## 碗底与放球必检
- **碗深只许来自"控制环 + 逐环线性插值到全平眼窝心", 不许逐点采样参考件的剖面** — 采样会把参考件自身的坑洼/偏心原样带进来: 碗底偏到眼球中心下方(~2mm)、带局部深坑, 且比"球面+间隙"浅数毫米(放球前测不出, 一放球后半球穿出, worst ~13mm)。
- **用户验证过的碗构造法(照做, 别再自创; 精确解码与参数见 `qr-socket-bowl.md` §窝底形状)**: 取 rim 环 → 等比缩小到"最深处环" → **该环沿 Y 打平成"眼窝心"平面(全部顶点同一 y)** → 中间 Ctrl+R 均匀补分段 → 再挤出一点合并到中心成极点。实现 = **纯线性插值** `y_k_i=(1-t_k)·rim_y_i + t_k·y_deep, t_k=k/NB`: 深度步进逐环全等、顶点波动精确按 `(NB-k)/NB` 衰减、**最深环 y 跨度=0.00**。⛔ 已证伪的中间模型(别再回头用): "每圈向本圈均值压缩 λ 0.956→0.65" / "rim 中位数基线+λ≈0.52 衰减+非线性剖面" —— 产物深度步进乱(1.5/4.5/5.7mm…)、最深环斜跨 4.5mm 不平, 用户直接判"结构错了"。
- **★深度公式(v19 定案, 全部由 rim 几何算出, 无死参数)**: `r_ref = median(rim顶点到眼心XZ距离)`(开口等效半径); `y_deep = mean(rim_y) + 2.04×r_ref`(全平的"眼窝心"平面); 分段步进 = `0.255×r_ref`; 环数 `N = clamp(round(D/步进),5,12)`(=8); 极点 = `y_deep + 0.176×r_ref`; `y_k_i = (1-t_k)·rim_y_i + t_k·y_deep, t_k=k/N`; 缩放序列线性, `_S_DEEP≈0.152`(无量纲)。五组系数虽由参考碗实测反推, 但全部无量纲、随模型随动 —— 用户明确要求"都要算出来, 不能做成死参数", 血泪: 先用的 v18 式 `y_deep=mean(rim_y)+0.675×eye_w` 被要求改成 r_ref 驱动后, 与参考碗对齐反而更好(≤0.07mm vs ±0.7mm)。参考碗实测规律(复刻必须命中): 深度步进逐环全等(+3.13mm×7)、顶点波动精确线性衰减 `(N-k)/N`、最深环 y 跨度 0.00。⛔ 被证伪的旧模型: "rim 中位数基线+λ≈0.52 衰减+非线性剖面"(深度步进乱、最深环斜跨 4.5mm 不平 → 用户判"结构错了")。
- **★结构验收 = BFS 环表逐环比对(表面级比对不够)**: 碗=四边形环带 → 从 rim 按网格边 BFS, **图距=环号**(确定性, 不依赖顶点顺序/半径估计), 逐环出 n/r/rrim/y均/std/跨度/Δ上环 —— `scripts/bowl_ring_table.py <blend>`。复刻合格硬指标: **每环 y 均值与半径比差 ≤0.1mm**。⚠ **表面级 KDTree (x,z) 比对照样会骗人**: 旧结构版曾以"Δy 均 -0.71mm"通过, 但深度步进乱/最深环不平, 用户照样判"结构错了"; 深带还会因跨环错配出现 ±2~3mm 假值 → 只能当辅助。
- **⚠ 深部细面(>10 边长比)是用户方法的固有特征, 不是回归**: 参考碗自身 R 眼 >5=204/>10=95/最差 **43.5**(同位置: 碗底中心); 复刻版 311/127/39.5 同位置同特征、最差值**更优**。别为消除它去加焊接(焊接=改结构, 用户做法里没有; 且末 3 圈在眼球内部不可见)。
- **⚠ 审计口径四坑(全部踩过)**: ①**按半径分箱/同半径圆周探针会把不同环+皮肤混样**(环是杏仁形缩放, 半径随角度变; 眼角皮肤会混入) → 判环一律用 BFS 环表(`scripts/bowl_ring_table.py`)或让构建脚本直接打印每环统计; ②**别按顶点索引切片定环** —— "创建顺序=环顺序"的假定在用户手工重建过的碗上立即失效(读数全乱); ③**用户参考版只改了屏幕右侧一只眼, 另一只是删掉的** → 量参考版必须量同一侧, 量错侧得到假数据; ④**候选顶点数=0 先查过滤条件符号**(y 方向曾写反, 把全部碗顶点排除, 白折腾一轮); 也别再逐点采样旧参考件(_eye_cup_ref)的剖面 — 其中心非单调, 会把参考件自身的坑洼/偏心搬进碗。
- 眼球放入后必做【带符号穿透检测】: 球面点 → 最近【碗面】的(最近点, 面法线), 点积<0 = 穿到碗后。⚠ **参考面必须是碗面, 不能拿整个头模做 BVH** — 眼球本来就在头体积内, 用全头的符号判据会把所有球面点都判成"陷入"(本会话真实踩过)。
- 根因口径: 逐点采样参考件剖面 → 坑洼/偏心被搬进来; 修法只能回到构造法(控制环+打平), 不要在穿模后做局部推回补丁
- 约束公式: 碗面点到眼球球心距离 ≥ R + 渐进间隙(近rim≈0.2×gap 因睑缘解剖上贴球, 碗底=1.0×gap)
- ★球心必须用【眼球球心】(bbox中心), 不能用轮廓中心 JSON['center'](y差14.8mm) —— 这个坑犯过两次
- ★逐圈加约束必须校验【环序不交叉】(环i推回量>环i+1会导致面翻转; 实测某次ny>0.1占比从0%爆到30%)。稳妥法=逐点向球面径向投影(天然保序, 不按环批量推)

# 眼角曲率: 源头在轮廓线, 不在 rim 环(用户反复要求"优化曲率"的正确解法)

- 眼角"尖"的源头 = **手描轮廓线自身的角**(72 点手描 turn max 65.7°) → 谐波平滑后角部仍只有 ~1.5mm 半径。
- **定案: 轮廓自动谐波搜索** —— 从配置 K 往下搜到【轮廓自身最小局部曲率半径 ≥ R_target = 0.07×眼宽】
  (XZ, -Y 视图口径), 全带从该轮廓重建 → 不会 fold/穿插。实测 K 12→4: 角半径 1.54/1.45 → 2.38/2.04mm, 穿插 0/0。
  调节只有**一个系数**(0.07), 随眼宽走; 嫌太圆就调小。
- 兜底 ⑦n 眼角圆化: 阈值必须**逐点**(按其自身两侧步长, 允许转角 = 2·asin(step/(2R))); 全局阈值会在步长密集处残留紧弯。
- ❌ 三条被证伪的角部修法: ①高斯平滑+等弧长重排(尖角自交 → 0.47mm 尖刺 + 7 对穿插)
  ②环低通再跑(动环必破 strip: 0.35mm → 9 对穿插) ③全局 p90×1.4 阈值(≈21°, 只碰 22-24° 的点 → 视觉无变化)。
- ❌ **第 4 条(修正版): 谐波搜索下限 4→2 —— 用户最终拍板采用 K=2, 但代价要看清**。
  实测 K=2: 角半径 1.60→2.68mm(达 0.07×眼宽 ✓), 角部最短边 0.37→0.68mm(可见眼睑边缘锯齿感明显缓解 ✓);
  代价: 碗的薄面比值在内外眼角都涨(≤9.7 → 20~30), 眼区 >5/>10 面 70/0 → 270/126。
  验收优先级=**可见区优先**: 用户验收的是"眼睑边缘的形状与线框观感"(可见 ✓), 碗内压在眼球后的薄面(不可见)次之。
  报数时要两套一起给, 不要只看聚合指标就把用户的可见优先选择回退掉(上一轮因此误回退过一次)。
- ❌ **定位可见角部缺陷必须染色渲染**: 把眼区子网格复制+wireframe modifier, 按顶点出身染色(QR 原有=蓝 v<160000, 碗新建=红 ≥160000),
  同视角渲图 —— 实测眼睑边缘的"星芒/锯齿"**全是蓝线(QR 原生边界自身)**, 不是碗造成的; 不要在没有染色图的情况下把锅往碗的环系统上扣。
  渲染注意: 相机距离 0.07m 时必须 `cam_d.clip_start=0.001`(默认 0.1m 会把整个画面裁成白图); 顶点选择用
  `v.select = bool(...)`(numpy bool 直赋会 TypeError); 删选区记得删"非目标区"(反了会把要看的区域删掉)。
  vision 对同一角部的反复判读会**互相矛盾**(本轮同一版本先后被判"仍有星芒"与"没有星芒") —— 归属类问题一律以
  染色图/PIL 定量图为准; vision 只用于二值核对("这张图里是蓝线还是红线""可见区有没有异常"), 不下结论。

## 碗(02杯工序)角部缺陷的归属与修复纪律(2026-09 实测)

**先定归属再动手**: 同一套审计(边长比 max/min、valence≥5 极点、最短边、PIL 线框正投影图)
对 ①QR 纯输出(_中间/02_qr_150k.blend) ②最终文件 各跑一遍。
实测在眼窝外角: QR 输出 = **0 极点、比≤3.0、最短边 0.82mm(干净)**; 最终文件的"星芒/压扁面"= **杯工序造的**。
- PIL 线框正投影(沿 -Y, 把区内边画成线段+顶点画点) = 最贴近用户视角的判据, vision 同图可稳定判读"星芒 vs 均匀"。
- 归属结论: 杯的放射环系统在锐角轮廓处收缩打结; 这是缩放成环法的固有行为, 轮廓越尖越明显。

**两条实测修法(都验证过)**:
1. **极点圆锥** ✗✗: 极点 y 若取"参考碗中心射线", 参考碗中心非单调(r=2mm 处 -87.6, r=0 回弹 -82.9)
   → 极点比末环朝前凸 4.7mm = 一个正对观众的圆锥尖(用户截图"像刺一样凸起"就是这个)。
   修: 极点 y = **末环 y 均值 + 0.2mm**(与末环连续), 不信参考件中心那根射线。
   → 修后极点 y -82.9→-84.6, 眼区 >10 尖面 52→0。
2. **深部环焊接必须限定范围** ✗: 深环等比缩小继承 rim 密度 → 密集点 0.2mm 配 3~5mm 扇骨 = 15:1 细长面。
   焊接(remove_doubles 0.65mm)能消除细长面, **但每合一对顶点就抬一次 valence** —— 全环焊把角部极点从 1 个变成 9 个(用户立刻圈出来报"捏皱了")。
   修: 焊接**只做末 3 圈**(0.65mm) —— 末环 34→19 点、扇骨比≤3, 而角部外圈保持 QR 干净原样。
   依据: 碗的末 3 圈全部在眼球球体内部(点到球心距离 < R), 是**不可见区**, 怎么焊都看不见;
   可见区 = rim→首圈缝合带。焊前先算可见性(距离球心 < R 即隐藏)。
3. **可见区(rim→首圈)的密集点来自 QR 边界的局部间距**, 不许焊(会直接改用户珍视的 rim 观感) —— 先报告用户再议。

## ⚠ 静默失败陷阱(致"汇报与现实脱节", 必须根治)

- 子函数引用 derive_scale 的产物必须用明确容器 **CUR['eye_w']**, 禁止裸名依赖作用域 ——
  裸名 `eye_w` 让环低通整块 NameError 被 `except` 吞掉, **连续 6 个版本从未执行**, 而汇报却一直声称它生效。
- 同类第二形态: **定义在历次编辑里丢了、引用处照旧**(如 02 驱动脚本的 `WORK_01A`) → 运行时 NameError;
  blender 崩了也照样 exit 0 只留 Traceback。改完任何管道脚本要**实跑一遍 + 逐项 grep 预期的成功打印**:
  "该出现的打印没出现"与报错同等严重, 只 grep `Traceback|Error` 不足以宣布通过。
- 规则: ①每个 try 块打印**执行值**(不只是失败信息); ②汇报前 grep 日志回读每个 pass 的打印, 确认真的跑了;
  ③不要因"代码存在"就假定生效; ④try/except 兜住异常后必须能在日志里看见+计数;
  ⑤宣布"优化了"之前先做**可见性自检**(量级 ÷ 结构尺度; 见 working-conventions §4)。

## 用户交"手工调好的参考版"时: 反推做法, 不是抄数值
用户会交手工调过的 .blend(常把另一侧删掉防看错)并要求"找原因找做法"。固定流程:
1. **先对拓扑**: 比顶点/面数 — 差值恰好等于"某一侧的碗面面数/顶点数" ⇒ 结论 = 只动了顶点或只删了一部分, 不是重建。
2. **不要用 KD 最近点匹配做差分**: 两边拓扑只要稍有不同, 最近点就错位一格, 位移读数 ≈ 顶点间距 = 纯噪声, 会让人以为"用户随手挪了一堆点"。改用与拓扑无关的**射线探针三件套**:
   ①网格图(从前方沿 +Y 首命中的表面 y: x × dz 二维表) ②圆周探针(同半径绕一圈的 y 均值/标准差) ③环带均值(相邻环带的表面宽度)。⚠ ①②在**杏仁形环**上会把不同环+皮肤混样("深部波动被压小 0.65×"的旧读数即混样假象) —— 碗的**环结构**一律改用 **BFS 环表**(`scripts/bowl_ring_table.py <blend>`: 从 rim 按网格边 BFS, 图距=环号, 确定性), 实测能直接读出参考碗真规律(8环+极点/步进+3.13×7全等/波动线性衰减/最深环全平)。
3. **把规律写成比值/相对量再复刻**: 例 "深部圈 y 波动被压到 ~0.65×、外圈 ~0.96×"、"最深处归位到眼球中心高度" —— 随尺寸随动的规则; 参考版的绝对 mm/坐标一律不得进代码(用户明确要求不是写死参数)。
4. **自检用参考版的同一套探针**: 比指标(同半径 y std、Δ 网格、带宽比)而不是比顶点坐标; 再出同机位 A/B 渲图, 判读"局部深坑 vs 平滑浅盘"这类宏观差别是否消除。
5. **只动用户指的那一项**: 复刻时不要顺手"优化"别的地方——会把已认可的状态一起改坏并被直接打回。
直问用户"你是怎么调的"永远比猜快; 拿到原话后仍要用上面的探针验证一遍——描述的是手法, 几何里的才是结果。

## 眼球生命周期: 02 摆入、全程携带、3B 重摆跟随(现行定案)

- **顺序(2026-09-17 更新)**: 01a 只做眼窝; 02 = QR → 碗(纯 rim 几何, 深度/环数由脚本自算) → 眼球摆入并**直接并入碗输出(正典)**; 眼球随 03 UV / 04 烘焙 / 05 绑定 / 导出全程携带。碗构造**不含任何眼球几何**("不去管眼珠"用户口径) —— 别在碗脚本里残留 BALL 依赖(曾因 "若 01_2 无眼球就 skip" 的残留把整个眼跳过); 碗底与眼球后极的设计性重叠 = 用户参考碗固有(被眼球遮挡, 预期状态, 不要去修)。
- **3B 重摆的跟随条件**: 05_3B(normalize, rest 对齐 Mixamo)的 LBS 只处理"顶点组非空 + 有 Armature 修改器"的网格 —— 眼球必须在 3B 之前完成 Head 蒙皮, 否则被判"无权重"原地不动、与重摆后的网格错位。`_resolve_bone` 已容忍 `mixamorig:` 前缀(无它眼球同样被跳过); 蒙皮 = 顶点组 `mixamorig:Head` 权重 1 + Armature 修改器(rest 态下修改器不产生位移, 3B 改的是 rest 并把位移烘进网格)。
- 实测: 眼球在 3B 里 Σw = 1.000000, 随头做**刚体**位移(左右眼逐分量完全一致 = 无扭曲); 眼球并入 05 要**幂等** —— 网格已带 `Eye002_*` 就直接用, 只在缺失时 link, 否则出现两对眼; 蒙皮循环必须写在 if/elif **之外**两路共用(补丁时最容易把它缩进进单个分支, 新路径就漏蒙皮)。
- **验证纪律(每一级都做, 别只看日志)**: 打开**实际文件**列 对象/顶点数/uv 层/世界位置; 日志打印"成功"不等于文件里真有该对象; 位置换算成 mm 比对(输出常以 m 一位小数打印, 看不出 mm 级偏差)。
- **眼睑区权重: 已定案修复(不再是"固有残留")**: 眼球 = 100% 刚性 Head, 而 ARP 自动权重给眼睑/眼窝皮肤 ≈ Head 0.91 + Neck 0.09 → 3B 重摆时眼睑滞后眼球 ~3.9mm, 用户看到的就是"眼珠独立位移/爆出"。修法 = normalize 脚本在 LBS **之前**把眼区权重统一为纯 Head(半径由实测眼球对象推导: 1.5×R_e 核心纯 Head, 平滑衰减到 2.5×R_e), 并把"眼区刚性跟随"做成**区域级**自查(核心 ~0mm; 只查纯权重顶点会漏掉 0.91/0.09 的混合区 = 自证陷阱)。机制与验收详见 `references/rest-normalization-x-leg.md`。
- **前后对比仍必须用固定顶点索引** —— LBS 原地改写坐标, 按邻域重新选点会让集合随位移变化、指标失真(实测"附近顶点质心"给出 2.4mm 的假差值)。
- **FBX 导出**: 04 的导出选择所有剩余网格(含眼球; 之前只选低模会把眼球漏掉); `05_for_mixamo.fbx` 因此含眼球 —— Mixamo 自动绑多物体网格可能绑歪, 走 Mixamo 路时单独排除眼球(ARP 本地路不受影响)。

## 眼裂开口与"眼球爆出"观感: 先定归属, 再数值定位(vision 只做二值核对)
用户报"眼球凸出/爆出来了"时的固定诊断链:
0. **若"爆出"发生在骨骼重摆/头颈动画之后, 先查眼区权重, 再查几何**: 眼球中心在头骨局部坐标可以完美(1e-4mm 级)
   而眼睑 flesh 因 0.91/0.09 混合权重滞后 ~3.9mm —— 眼球"没动", 动的是眼眶。权重审计与修法见
   `references/rest-normalization-x-leg.md` 的眼区权重节; 几何归属只在权重干净后才谈。
1. **分阶段对比渲染**(同一正交相机, 眼高用眼球对象中心自动对准): 01 原始高模(正/侧) → 01a 切割后 → 当前版。
   "爆出"若与骨骼无关(静止 T-pose 也看得出), 多半自 ≤02 引入; 先量 03→03B 眼球在头骨局部坐标的差(应为 ~1e-4 mm 级)以排除绑定环节。
2. **数值四件套**(此类绝对描述 vision 会自相矛盾, 不可下结论):
   ① 球心/半径 = 眼球对象顶点均值 / 到心均距;
   ② 球最前 y vs **原始高模同 (x,z) 邻域(±6mm 柱)的最前 y** —— 原始高模的眼面是真值基准;
   ③ 01a 输出里孔边界(只属 1 个面的边)的 z 跨度/宽度 = 眼裂开口尺寸(人眼裂开口 ~10-12mm, 球径 ~24-26mm);
   ④ 球心到"前方睑点"(主网格上 y 前于球心、26mm 内的近点)的最短距离: < 球半径 ⇒ 球面在眼角处穿透周围几何
   (即用户截图里的"内眼角小黑点"; 区分主次: 中位距离 > 半径而仅 min 穿透 = 小范围局部，不是整体穿模)。
3. 结论口径: 静止态的"凸出"感与**开口大于原始眼裂**(眼球暴露过多)有关, 而非球靠前 —— 实测球最前点可比原始高模
   角膜面还深 ~7mm; 但若观感随头/颈骨骼运动出现(=真正的"爆出"), 主因是眼睑权重滞后(见步骤 0), 先修权重。
   剩余可选项(待用户点头): **收紧眼裂轮廓(竖直向收 1~2mm, 恢复上睑覆盖) > 动球位置**; 内眼角穿透点单独局部修。
4. ⚠ **眼睑轮廓标记 = 用户权威数据, 且 01a 全步属"绝不 headless 跑"的保护步**(重跑第①步会重检测/覆盖手调 json 的 source):
   修复要么走用户 GUI 流程, 要么先给同机位 A/B 对比图请示再改。01a 打点脚本已内置硬提示: 点贴【可见睑缘】
   (睫毛根所在的边界), 不要放到双眼皮褶/眉下/眼窝骨缘; 放偏大→眼白露多、眼球显凸, 放偏小→被眼睑盖住过多。
