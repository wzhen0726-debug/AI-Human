# 半自动打点模板 — 交付质量与用户体验教训 (2026-08-26)

用户亲自打点，助手出模板。本会话模板被用户打回多次，教训如下。

## 1. 点与文字必须可见、有颜色区分（用户实测反馈）
用户原话："你的点压根没有颜色区别，都是黑色的点跟字，没有黄色红色"。
- Blender 里 Empty 点和 font 对象**默认黑色**，不显式上色就是黑点黑字。
- 模板交付前必须**渲染一张正面图自检可见性**，不能只查数据块。
- 点按类别上色：中线点、右侧关节点、左侧（镜像）点各一色；文字牌用白字或加对比底。

## 2. 关节点不能加 Shrinkwrap 吸附（用户实测反馈）
用户原话："这个点应该有吸附吗？我的肩膀都打到前束表面了，不会有影响吗？"
- 关节点（肩/肘/腕/膝/踝）是**肢体内部的解剖中心**，不是皮肤表面点。
- Shrinkwrap NEAREST_SURFACE 会**主动阻止**用户把点拖进皮肤内部 → 点被迫停在皮肤表面 → 骨旋转轴心偏到表面 → 蒙皮变形异常。
- 01A 眼睑点用吸附是对的，因为那是皮肤表面特征；**关节点必须去掉吸附**。
- 去掉吸附前烘焙当前求值位置，防止点弹回初始值。

## 3. 中线点必须锁 X=0（根因）
- Shrinkwrap NEAREST_SURFACE 沿**不对称**的真实表面投影，会把中线点（颈根/会阴）带偏出中线。
- 修复：中线点约束栈里，Shrinkwrap **之后**追加 LIMIT_LOCATION 钳制 X=0。Blender 约束按栈顺序求值：先吸附表面、再钳制中线。
- 会阴点若偏，整个髋部+两条腿旋转轴心都跟着偏。

## 4. 文字牌/标注朝向（渲染实测验证，别靠猜）
- 正视相机在 −Y 看向 +Y（模型正面朝 −Y），文字法线须朝 **−Y** 才正面可读 → 绕X轴 **+90°**。
- 用 **−90° 会镜像**（看到的是文字背面）。
- 每次改朝向必须渲染一张正面图用 vision 确认，不要凭方向直觉。

## 5. 抽象参考图不如简明文字（用户实测反馈）
用户原话："这个标注太抽象了，而且还是只有一个肩部的啊，还不如不提供，你能改成简炼的文字提示么。"
- 肩点红圈被识图模型误读成"锁骨末端"——抽象几何符号没有歧义消除能力。
- 默认用**简明文字表格**描述每个点放哪（如"肩=肩峰下2cm、手臂厚度中间"）。
- 如必须画图，图上要有文字标签解释每个符号含义，且覆盖所有部位（不只一个）。

## 6. 用户点位是唯一事实源
- 用户打点期间不要覆盖/重读假设；用户说"我重新调X点"时等他调完再读文件。
- 绑定前必须重新读取用户最新坐标，不能用脚本缓存。
- 报告偏移用数字+方向（"偏左78mm"），用户看不出偏移时渲染正面对比图（红=用户点、绿=正确位、中线参考线）。
