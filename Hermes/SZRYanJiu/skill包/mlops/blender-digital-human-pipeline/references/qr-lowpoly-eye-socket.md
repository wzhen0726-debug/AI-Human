# QR 后低模眼窝: 按眼球同心球补碗 (02qr_socket_cup.py)

## 何时用
高模只留 rim 环+空腔("环内掏空"模式) → QR 后低模只剩开口 → 在低模上补碗状眼窝, 让眼球坐进去。
输入 = QR 输出 + 01_2 的真实眼球对象; 输出 = 新文件(如 `02_qr_150k_socket.blend`), **不覆盖 QR 原产物**。

## ⚠ 三条红线(网格手术通用, 本类任务已各踩一次)
1. **禁止对工作网格用全局 `recalc_face_normals`**: 它按连通岛整体重定向 —— 实测把左腿 245 个面翻掉
   (同一文件不跑该句时腿部翻转=0)。对**孤立的、新建的**对象(如切割棱柱)照样可以——已有区域混在一起时不行。
   定向只允许"局部 + 明确参考物", 且放在**所有**改几何的收尾 ops 之后、用当时的引用做。
2. **镜像网格 L/R 的边界环拓扑走行方向相反** → 同一套建面顶点顺序必有一侧绕序整体反。
   修: 种子法 —— 每侧取环上第一条与既有面共享的边, 按流形一致规则(共享边在两侧面的顶点环里必须反向)
   决定该侧顶点顺序。实测 L=常规 / R=反转。不要用拓扑 BFS 传播逼向内(某侧挂起 9 分钟无输出), 种子法 O(1) 等效。
   **种子管全侧、包括封底**: 该侧所有新建面共用同一约定 —— 最后封底的 n-gon 若直接用原始环序,
   必然一侧蒙对、另一侧整体翻(实测 R 封盖 220mm² 面朝后、透过眼裂可见 = 用户报"还有红面 依然在")。
3. **Blender 子进程 print 默认全缓冲** —— 卡死时日志里只有文件读取行。定位先加
   `print = functools.partial(print, flush=True)`, 再跑即可看到最后一个完成的步骤。

## 做法(全随动, 无硬编码)
1. 从 01_2 推导眼球: **球心 = 包围盒中心; 半径 = 到该中心距离的 p90**。
2. 找每个眼孔的开放边界环(按拓扑行走, 不要按角度排序)。
3. **绕序种子**(每侧一次, 建面前): 同红线 2。
4. 环带布置 = **等比缩小 + 每圈一个标量**(半径×s_k; 现行基线 **8 圈** `_SCALES=[0.90,0.80,0.70,0.59,0.48,0.37,0.26,0.15]`, s1 再由下面的单标量二分微调)。
   深度 = 逐点采样(优先高模旧碗 ray_cast, 回退同心球深度)**再逐圈"沿 Y 打平"**(用户手调参考版解码出的必做步骤: 每圈 y 向该圈自身均值压缩, 压缩率随深度渐强: 外圈≈0.956 → 深部≈0.65, 随模型走不写死; 细则见 `qr-socket-bowl.md` 的"窝底形状 = 用户方法的解码规则"。不打平会留下偏低约 2mm 的深坑 → 用户判"完全不对")。
   圈数与收口形态 = 用户已认可的量(8 圈 + 极点收口 = "整体是对的") —— **未被点名不得加圈/改收口/改点分布**。
   用户点名"某圈沿 Y 平移"时照做, 见下文"指定圈沿 Y 平移"专节。
   ❌ 禁止任何**逐点/逐射线重排**布置环带(见"均匀化禁区"节; 实测被用户判"面都出现了错位穿插")。
   "让蓝线均分 1 和 2"的正解 = 只调**第一圈的径向标量 s1**(全圈统一 → 环严格嵌套, 结构上不可能交叉):
   对 s1 二分, 使 band1(rim→环1) 与 band2(环1→环2) 的**表面宽度均值**(逐点 3D 距离的均值)相等;
   界限 s1 ∈ (s2+0.005, 0.995); 二分前后各打印两带宽度与比值。
   实测 s1 0.900→0.867: band1=band2=2.18mm(L) / 2.28mm(R), 比值 **1.000**。
   - ❌ 纯固定量内缩 d_k=(k/N)×r_min: 形状不收敛, 到不了极点。
   - ❌ **多标量反馈调参发散**: 按各带宽度均值迭代改多个 s_k → s_k 退化成非单调
     (0.417/0.020/0.463/0.869/…, 环序交叉)。自动搜索只允许"单标量 + 单调性可证 + 有界"。
5. **末环 → 单极点收口**(用户规格: 眼窝内都是环线, 随 rim 环逐圈变小, 最后成为一个点):
   极点 = 1 个新顶点(深度 = 参考碗在该点 y / 球面回退), 末环边 → 三角扇, 绕序跟本侧种子。
   ❌ n-gon 平封盖 = 用户所见"花生仁"(拉长平板)被否。
   实测(8 圈基线): 351/423 面, 朝后 0.0%/0.0%, 腿部 0, band1=band2=1.000; 用户判"整体是对的"。
   ❌(未采用, 不得擅自再做) 把圈数 8→10(追加 0.09/0.05)+深部最后 2 圈半径向圆: 当时是为"对齐参照图"做的,
   后经用户澄清参照图实为"同一条环线沿 Y 挪动", 该改动被整体回退 —— 加深圈数属"改收口", 必须用户明确要求才做。
   (该变体顺带暴露的坑: 末环缩到 0.05×r 时短轴点距被压到 0.02mm 级 → 边长比 116:1 极细条;
   若将来真要缩这么小, 深部只能**动半径向均值过渡**, 绝不改角度/点序。)
6. 碗面打 face int 层 `qrbowl`=1 —— **建面时立即打 tag**(事后遍历 BMFace 引用会失效, 只剩个位数)。
   tag 只标脚本新建的面; 不要用"孔内/孔后侧"启发式补标(会把睑内面混进来)。
7. smooth shading; 保存。

## ⚠ 球体拟合的坑(用户报"完全不对 / 深洞里一条胶囊"的根因)
- ❌ **顶点均值当球心**: 角膜侧顶点更密 → 均值被带偏 ~3.8mm → 半径谱虚胖成 6.9~18.7mm(含内部假象)。
- ❌ **再取 max 当半径**: 在虚胖谱上取 max=18.68 → 碗面球 20.2mm, 比可见眼球表面(~14.9)深 5mm+
  → "眼窝过深", 透过眼裂只看到深处一条扁胶囊。
- ✅ **bbox 中心 + p90**: 实测谱 [10.6~14.9] 紧致, 半径 14.91 ≈ 配置文件里独立标定的 14.56(交叉验证通过)。
- 自检: 半径谱应紧致且与标定值一致; 碗底深度应 = 球心y + (半径+间隙)。

## 多轮自检口径(用户明确要求"多轮自检")
1. 球体拟合: 半径谱紧致 + 与配置标定值交叉验证。
2. 碗底深度 = 球心 + (R+间隙)。
3. 碗面朝向: 先跑粗筛"法线朝后(ny>0.1)占比 + 左右中位 ny 一致"(修后 L 0.0% / R 0.4%, 中位 −0.86 / −0.85);
   **最终判据 = 相机判据渲图**: 逐面 `normal·(相机−面心)<0 → 红`, 用用户机位(正前+略俯视)出图。
   ny 粗筛**抓不到侧倾壁面**(碗壁法线基本横置, 翻没翻 ny 都≈0); 且只认"看得见的红"——数值标记里被遮挡的面不是缺陷。
   渲染注意: Workbench `color_type='MATERIAL'` 取的是 `mat.diffuse_color`, 只设节点 Base Color 会渲出全灰。
4. 全身: 与邻域平均相反的翻转面 = 0(腿等远离眼区的区域也要查 —— 全局 ops 的伤在那里)。
5. 视觉: 正视/侧视/3⁄4 渲图, 碗面给独立材质便于辨认 —— 判据"能容纳眼球的碗状窝、眶缘过渡自然"。
6. 环带均匀度(改圈位后必报, 用户口径的那个量): 相邻带表面宽度均值与比值(目标 1.0) +
   碗面最小内角分布(中位 / p1 / <20° 面数 / 边长比>3 面数)。
- ⚠ **测"眼球→碗面最小距离"时 BVH 只能含碗面(tag)**: 头模自己的睑内面本来就贴着眼球,
  混进 BVH 必然报 0.01mm 级假穿插(反复栽在这)。
- ⚠ **线框密集区的 vision 绝对描述不可当缺陷证据**: 本轮多次出现"渲染看着乱/褶皱/错位、甚至把正常收口说成星形缺陷",
  而数值逐项干净(质量三数不变、真穿插 0、红面 0)。据此重建之前先跑三个数(四边面质量 / 真穿插对数 / 面朝向红色可见性);
  数值不动 → 收手, 等用户口径。
- ⚠ 边界环与头模共享顶点、眼球表面天然贴近睑缘(01_2 既有关系) —— 报"贴近/穿插"前先区分归属。

## 环带宽度不均的定位与 rim 归属(用户: "让蓝线尽量均分 1 和 2"; 动碗内环安全、rim 绝不能动)
- 用户标"1/2 宽度不均"通常指**相邻两圈环带之间的径向带宽**("蓝线" = 两带之间那条环线 = 要挪的那条)。
  **等半径比例 ≠ 等表面宽度**(表面宽度含深度落差, 谁宽谁窄以实测为准, 不要先验断定) →
  用"做法 4"的**单标量二分**调平 s1; 改完先按用户口径量"两带表面宽度比值"(目标 1.0)再出图, 数值自证不算通过。
- 定位前先确认维度(环向点距 / 径向带宽 / 带的比例), 按用户标注的数字与蓝线口径理解, 不要自己换维度去修
  (把"带宽不均"当环向点距或深层环问题修 → 白改一轮)。
- 动**碗内环**安全(用户: "动这根线压根不会影响到 rim 环"); rim 环自身(与头模共享顶点)**一个都不能碰**。
- 细长面/尖角面的诊断顺序: **先查圈位与重排, 再谈固有**。碗面四边面(688 个)两种状态实测 ——
  逐点重排版: 最小内角 p1=3.3°、<20° 面 **267** 个; 纯标量版: p1=18.6°、<20° 面 **11** 个、中位 51.2°。
  ⇒ "线不均匀"的相当一部分是**重排/圈位**造成的可修项, 不是 rim 固有; 报告必须给三个数
  (中位最小内角 / <20° 面数 / 边长比>3 面数), 单看尖角数会把可修项报成固有。
  - 仅剩的少数才与 rim 顶点间距(0.3~1.5mm 不均, QR 输出且与头模共享)有关; 若要继续治只有
    **纯切向松弛 rim 顶点**(只重排点距、不改形状) —— 会碰 rim, 必须先问用户, 不擅自做。

  ## 指定圈沿 Y 平移(曾点名一次; 该实现已随用户重做而删除 —— 勿再按此机制添加)
  - 教训形态: 用户报过"最近的点 +0.001688 m 朝正 Y; 其他少一点 ~0.001267 m"(= 某圈沿 +Y 平移、前大后小)。
    当时以 `_SHIFT = {圈idx: (max_m, min_m)}` 表实现; 后用户交回**重做版**参考 blend 并给出自己的做法,
    该位移块即被删除 —— **用户说"重做"后, 此类旧手调补丁一律作废**, 以新方法规则从源头重实现, 不在补丁上叠补丁。
  - 仍然有效的口径: **圈号从 rim 数起、rim 算第 1 圈**(用户说"第 3 圈" = `_SCALES[1]`, "第 4 圈" = `_SCALES[2]`);
    本项目 y 越负越靠前 → "朝正 Y / 沿 +Y" = 向头内/眼窝深处; 量以米报(如 0.001688m)。

## 形状参考: 用户要"之前那种眼窝形状"→ 采样旧版高模碗, 不要自己从球面推
用户看图说"形状不对 / 我需要之前那个眼窝形状"时, 参考物 = 旧版 `make_eye_cup` 在高模上建的碗(代码还在 socket_ops):
1. **先 cp 一份高模再跑 cup**(它会改文件; 1.9M 面上约 10 分钟 → 后台跑 + 通知, 不要前台等)。
2. 旧碗面按 face int 层 `v44tag_{side}==2` 识别, 建 BVH。
3. 低模碗每圈每个 (x,z): 从脸前(`y_face−60mm`)沿 +Y `ray_cast` 到旧碗面 → 取命中 y; 打不到再回退同心球深度。
4. 结果: 低模碗剖面 = 旧碗剖面(实测"带外翻上缘、向后收窄"与旧碗一致)。
5. 教训: 两个深度体系数值接近(球后+1.5mm)时差别在**剖面形状** —— 拿"深度数字一致"汇报"形状一样"会被用户直接否;
   形状类反馈一律**同机位渲图对渲图**比较, 不要靠数字近似。

## 用户给两张参照图(从图一改成图二)时的读图法
⚠ 实测翻车点: 曾把两图"结构差异"(vision 读数: 圈数不同/收口不同)当成诉求, 改了圈数与收口
   → 用户"**你再乱改啥呢**", 全部回退。真实差异 = **同一条环线沿 Y 挪了 1.3~1.7mm**
   (用户原话"黄色的是同一环线, 只是挪动了一下在 Y 轴的位置")。
⇒ 默认假设 = **极小的定点操作**(某圈平移 / 某圈标量微调), 不是拓扑/圈数/收口改造。
1. 读文件名条(各裁左上角、上下拼一张让 vision 逐字读)只能确认"同一个资产", 推不出"图二是另一阶段/目标形态" —— 仍可能只是同一文件被改了一处。
2. 拼左右并列对照图让 vision 做 A/B **只当线索**: 线框密集时它的"圈数/收口/均匀度"读数会漂
   (实测把"环线深度位置不同"读成"圈数不同、收口不同")。
3. 候选差异按此顺序排查: ①某条环线被平移(看它相对前后圈/rim 的位置) ②某圈径向标量变化(看相邻带宽)
   —— 这两类才是主流诉求; "加深圈数/改收口"是被证伪的解释, 未经用户明确要求不得动。
4. 仍不确定就直接问用户序号与数值 —— 他们会给出"第 3 圈 / 0.001688m"这类精确量, 一次问清胜过三轮瞎改。

## ❌ 均匀化禁区: 环带布置只允许"每圈一个标量"(同类已连踩三次)
①固定角度+变半径 → 点距塌陷(0.01mm sliver);
②"角度解绕(unwrap)后向均布过渡 + 半径向圆过渡" → 环线被打断、放射线乱冲中心、中心挤成一团,
  用户判"问题更大了, 还不如上一版";
③**逐条射线按累计弧长重新布点**(即使环点角度不动) → 用户判"面都出现了错位穿插"。
机理: 环与环靠**同索引点一一对应**成面, 任何逐点位移(改角度、改沿路径位置)都会打破对应 → 面扭/交叉/穿插。
⇒ "让线更匀"只能改**每圈一个标量**(整圈统一缩放/移动 → 环严格嵌套); 环点角度、点序、圈内相对位置
必须逐圈同索引保持。判断某方案安不安全只看一条: 它是否会改变"点与点的对应关系"。

## 用户判"不如上一版"= 立即精确回退, 别在坏版上继续修
- `git checkout <已认可 commit> -- <脚本路径>` 还原脚本(不要手工改回), 重建后把**几何数值与已认可版逐项核对**
  (极点坐标/面数/朝后占比/腿部翻转全一致)才算"回到那版"; 实验若未提交, 先 `git status` 确认没固化。提交时**只 add 脚本/产物路径** —— `logs/` 在 .gitignore 里,
  把 logs 加进 `git add` 会让整条命令直接失败、提交静默不发生。
- "你再乱改啥呢" = 同类信号且更严厉: 把**未被点名**的改动(加圈/改收口/换算法)整体回退到用户认可的 commit,
  再只做被点名的那一处; 汇报里明确"哪些是被要求做的、哪些已撤回"。
