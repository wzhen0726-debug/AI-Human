# Eye rim 环重建(把 boolean/洪泛边界换成手描轮廓)

适用: 眼窝洞口边界=网格边环, 继承扫描面噪声/折返/锯齿; 需要一条「XZ 严格贴手描轮廓、3D 又光滑」的 rim 环。
轮廓贴手描线 ≠ 环就干净: 折返必须以 XZ 自交数验收(见下)。

## 顺序(每一步都别跳)

1. **先细分带区域内的大面**: 沿轮廓 W(≈1.2mm)± 范围内、边长 >0.8mm 的边先 `bmesh.ops.subdivide_edges` 若干轮。
   WHY: 粗面区不细分, 删带后的边界离轮廓很远, 缝回去的面被拉长成尖刺(用户会说「拉伸出去了」)。
2. **删带用精确判据, 三条并列**(满足任一即删):
   - 面心到轮廓 XZ 距离 < W;
   - 面的**边真的与轮廓折线相交**(逐边 × 逐段线段求交);
   - 顶点贴近轮廓 **且** 面心 < 2.5W(粗面小跨界)。
   WHY: 只用「任一顶点贴近轮廓就删」会在粗面区连续吃掉一片皮肤 —— 实测在眼角外侧啃出 ~10mm 的第二个洞(边界分裂成 210+118 两个环)。
3. **取带外缘边界环, 且必须自纠正**: 边界常常不是单一闭环(有分叉/死端) → 把问题顶点周围 1.6W 内的面删掉重试(≤6 轮)。
   排不动时打印「环清单(顶点数, 质心 dx/dz)」定位副环 —— 副环质心落在眼角外侧就是第 2 步判据过宽。
4. **内圈 = 手描轮廓按外圈顶点数 K 重采样**(单调、不跨洞口), 并**建出一圈闭合边**。
5. **缝条带用 Blender 原生 `bmesh.ops.bridge_loops`**(内圈边 + 外圈边界边一起传), **不要手写逐点配对+三角化**:
   WHY: 手写配对在两侧地形不同时必然拉出细长/扭曲面(用户实测右眼明显更差→报修); 原生桥接官方支持「两圈顶点数不同」, 自带 twist 最优配对,
   且**不改变内圈位置**(内圈仍是手描轮廓), 只决定两圈之间的面型。
   安全闸: 返回面数 < K/2 或最大面 >12mm² → `delete(context='FACES')` 后回退手写路线(每格两三角; 三角失败建整块四边形)。
   死路别重走: 手写「整体等弧长重采样硬对齐」→ 条带自我重叠盖住半边 rim; 「绕眼中心角度配对」→ 洞口整个盖住(开放边归 0);
   「换另一条对角线再试」→ rim 盖到自己身上并留 1 度顶点(看着缝好了、实际撕裂)。
6. **定向**: 朝外基准取**眼周皮肤面的多数法线**(先平均 → 只保留与平均同向的再平均, 排除少数异向面)。
   判定用「与多数基准相反」**或**「法线朝后 y>0.1」(后者与用户的面朝向显示同义, 更保险)。
   不可用共顶点邻面平均 —— 邻面本身不一致时会跟着错(表现为 rim 周围一圈反面)。
   眼区过滤别写成 `面心 y < 眼中心 y`: 眼周皮肤常常在眼中心**之后**(实测 −98~−106mm, 而眼中心 −105.75mm),
   这样写会把大部分皮肤排除在外、收尾定向形同虚设 → 用「只排后脑」(如 `c.y > -0.02` 才跳过)。
   收尾要扫**全部**眼区前表面面(含原网格自带与编辑连带产生的), 不要只扫本次新建的 `new_faces` 子集。

## 深度(y)的唯一正确来源: 原边界真值

内圈顶点的 y **绝不要自己采样**:
- `ray_cast` 沿 Y: 洞口范围内射线直接穿透打到后脑(y≈+99mm) → 缝出 200mm 长刺(环上最大边长从 0.2mm 变 204mm)。
- `closest_point_on_mesh`: 取到眼窝深处内壁 → rim 被拽深 ~10mm(实测 −112~−123mm vs 真值 −96~−115mm), 用户描述为「Y 轴拉平 / 眼眶变形」。
- ✅ **沿用原 rim 边界在相同角度上的 y**(角度插值): 原边界就在表面上, 是真值 → rim 的 3D 形态 100% 不变, 只有 XZ 换成平滑的手描线。
  实现: 删面前 `bmesh.new()+from_mesh(mesh)` 存快照 → 取眼周开放边顶点的 (θ, y) → 按 θ 排序 → 周期化(±2π 拼接)后插值。

## bmesh 坑

- `bmesh.ops.delete(context='FACES')` **保留**与存活面共用的顶点 → 用「顶点是否在删前集合里」判新旧会失效, 改用几何判据。
- 任何 ops 之后 `bm.verts[i]` 的索引/引用可能失效(`ReferenceError: BMesh data of type BMVert has been removed`) → 每次操作后重建 `{v.index: v}` 映射; 事后细分/拆分一律挪到最后一步。
- 函数内闭包取环时数组下标快照会过期 → 取环前 `ensure_lookup_table()`, 并用 `while cur in nadj:`(而不是 `while True:`)防止 KeyError 直接崩管线。
- 存盘前切回对象模式(`if bpy.context.mode != 'OBJECT': bpy.ops.object.mode_set(mode='OBJECT')`), 否则 .blend 以编辑模式保存, 用户 GUI 打开就是编辑态。
- `bm.faces.new()` 之后 `f.normal` 是**惰性/旧值**: 不先 `bm.normal_update()` 就读, 定向判据会「全部通过」而存盘后绕序仍是反的(实测判据报 0 个需翻转, 文件里 628/728 面朝后)。定向前后各 update 一次。
- 定向逻辑里绝不写 `ref = -ref`、也不要用面自身方向当基准 —— 等价于永不翻转。
- `Vector.angle()` 遇**零长度法线**直接抛异常 → try/except 兜住会**单侧静默跳过**(实测只处理了右眼、左眼没做, 违反两眼同步) → 夹角一律 `acos(clamp(dot))` + 先判 `normal.length > 1e-9`。

## 不许为了指标改形状(用户一眼就能看出来)

- 指标(转角/抖动/平滑度)变好 ≠ 形状对。曾为了让环的 3D 转角 max 从 37.7° 降到 28.7°, 把轮廓在某处局部内收 1.5mm ——指标变好, 但正视图下眼睑洞口被拽出一个生硬缺口, 用户当场否掉。
- 动「用户定义的形状」(手描轮廓线、皮肤表面)之前必须先问; 宁可留着局部折角, 也不要擅自改轮廓/表面。
- 反过来: 内圈顶点的 XZ 必须严格贴手描轮廓 —— 它是最不该动的东西; 平滑/去噪只能作用在自己新造的几何(缝合面)上。

## 验收判据(每轮都跑, 别只看一个数)

- 环: 顶点**度数全为 2**(闭合) / 环最大边长 ≤1mm / 3D 转角 mean, max, >30° 个数。
- 折返: 环的 XZ 自交对数 = 0(这是「缺口」的真身, 不是深度起伏)。
- 轮廓: 环 XZ 到目标轮廓的偏差 中位/p90/max(≤0.2mm)。
- 面朝向: 眼周反面面数 + 其**距离范围**(判据用「法线朝后」, 见下节)。深处(≥6mm, 洞口以内)= 后脑反面, 属正常; 落在皮肤上 = 翻面 bug。
- 面朝向**渲图自查**(用户指定的验收方式, 每版必做): 对**两眼**出叠加图 —— 特写(内眼角/下睑)+**全眼**(倍率要盖得住整只眼, ≥~0.05m) × **正前方 + 俯视 18°/32° 掠射角**。
  WHY: 台阶/折痕/红面在正前方常常看不见, 要「往上旋转」才现形(用户实测); 镜头方向用相机矩阵算(`cam.matrix_world.to_3x3() @ Vector((0,0,-1))`), 别用世界 -Y 近似。
  红只允许出现在洞口内部; 蓝色皮肤上一旦有红点/红条/红碎片或红蓝碎屑交错 = 面反了或面乱了。脚本: `scripts/face_orientation_close.py` + `scripts/graze_angle_check.py`。
- **折痕(台阶感)判据**: rim 周围相邻面**二面角剖面**(>60° 计数 + 逐条位置/距轮廓距离)。判「是不是我造的」用三态对比(输入/改动前备份/当前)——
  实测用户圈的下睑台阶在**输入文件里一模一样**(109°@距轮廓6.42mm) = 模型自带睑褶, 不是缝合带产物。
  软化用**自适应**规则: 眼周 9mm 内折痕角 >p99 且 >50° 的边, 端点小步拉普拉斯(上限=0.25×皮肤边长, 10 轮) → 实测 L109°→86°、>60° 折痕 17→8、R 18→8, 无回归。
  残留的**0 面积退化面**渲染里虽不可见, 但 QR 会在上面出错 → 收尾必须 `dissolve_degenerate` 清掉(见 `eye-socket-boolean-cut.md` 的面型清理节);
  有实体面积的小面(>0.05mm²)还要查是不是缝合留下的窄条。
- **两眼必须同一套规则/参数**(用户明确要求「两个眼同步改, 怕又出现单只眼问题」); 两眼地形不同就靠**随动**解决 —— 所有阈值从 头bbox/眼宽/实测皮肤边长 推导,
  不写死 mm、不按眼分设开关。历史教训: 曾用 `{L:True,R:False}` 按眼特判, 结果一眼修好、另一眼单独出问题。报数时两眼并列给。

## 复现用户看到的「面朝向」叠加显示

用户说的「红色」常常是 Blender 的 face orientation 叠加(蓝=正面, 红=反面), 不是材质。先确认显示模式, 再动几何。
**核验判据必须与叠加显示同义**: 正视相机(沿 +Y 看)下「法线朝后(+Y)」= 红 → 逐面按 `f.normal.y > 0.05~0.1` 赋红、其余赋蓝, workbench `color_type='MATERIAL'` 渲染;
斜下视角 + 特写各渲一张, 直接看红块落在洞口内还是皮肤上。
⛔ 不要用「与共顶点邻面平均法线比较」做核验 —— 它与修复判据同源, 侧倾的面能同时骗过两边(实测该判据报 0 个反面, 而用户一看就是一圈红)。修复判据与验证判据必须相互独立。

## 已知残留(最后一次实测)

定案态(bridge_loops 桥接 + 环3D低通 + 锐折痕软化): 两眼**单一闭环**(L180/R160 顶点全 2 度)、折返 0、真穿插(BVH) **0/0**、n-gon 0、
细长面(长宽比>6) ≤3、转角 max L24.2°/R20.1°、面朝向叠加图两眼皮肤无红点。
完整收尾顺序与全部判据见 `eye-socket-boolean-cut.md` 的「定案流水线」节(bridge_loops→n-gon→长边细分→退化清除→局部松弛→3D低通→折叠翻转→smooth→面朝向自查)。
(每次改完必跑五项：环度数 / 折返 / 轮廓偏差 / 面朝向 / 面型体检(`scripts/mesh_health_check.py`), 再渲面朝向叠加图给用户看。)
