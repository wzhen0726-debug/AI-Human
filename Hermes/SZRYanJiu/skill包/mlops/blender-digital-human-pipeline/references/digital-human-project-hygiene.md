# Digital Human Project: Record-Keeping and Folder Hygiene

User standing requirements (stated repeatedly, incl. 2026-08-21): 交付文件夹与方案md记录必须同步更新,
记录要全(对的错的思考尝试都记), git 及时 push, 定案后清理工程垃圾/过期文件. Blends NEVER enter git
(repo-root .gitignore: `*.npz`, `*.blend`); scripts + docs + data JSONs do.

## Wrap-up checklist after a variant is user-approved

1. Backup: `cp <live>.blend <live>_v<N>_final.blend` in models/.
2. Append a chapter to the step's 技术方案详细记录.md — must include: requirement, design
   principle, parameters, bugs hit + root causes, verification table, known residue, user's
   verdict verbatim, lessons. Update the doc's 目录 section too.
3. Update the skill reference baseline marker (which variant is CURRENT).
4. `git add scripts/ + doc`, commit with style `01A眼窝v<N>: <what/why>`, push
   (proxy 127.0.0.1:7897 configured repo-wide).
5. Purge junk (table below), then commit the cleanup separately.

## Junk to purge (periodically, or when the user asks to "optimize the project")

| Junk | Where | Notes |
|---|---|---|
| `*.blend1` | models/ | Blender autosave, same size as the real file, always safe to delete |
| Superseded version blends (`_v35`, `_v37_backup`, ...) | models/ | Keep: live + `_vN_final` backup + user-approved comparison variants + next-step outputs + marker blend. Pipeline can regenerate any version from scripts. |
| `__pycache__/`, `*.pyc` | scripts/ | always |
| `*.npz` intermediates | scripts/ | regenerated by export scripts |
| Root-level `*.txt` logs inside scripts/ | scripts/ | real logs live in scripts/logs/ |
| Old-version logs | scripts/logs/ | `mkdir logs/archive && mv` old ones there (git tracks as rename, fine) |
| Old-version screenshots (version-prefix names v35..v47) | screenshots/ | Keep: INPUT_*, current-version renders, basecolor texture, 3ddfa/*.json, eyeball renders |

Measured impact (01A step, 2026-08-21): models 801M→371M, screenshots 75M→41M.

## Pitfalls

- screenshots/ contains git-tracked data files (3ddfa/*.json) — prune by version-prefix
  patterns, never `rm -rf screenshots/*`.
- `git add -A <step dir>` after pruning is safe: blends/npz are gitignored and won't sneak in.
- Don't delete the marker blend (01A_markers_eyelid.blend): it holds the user's hand-placed
  eyelid contour points and is NOT regenerable.
