# 眼窝 rim 环重构 + 碗深/宏观形状定案 — 基线对比 + 否决路线

场景: 用户报「眼窝/rim 不对」要求重做。改 `socket_ops.py` 的 `make_eye_cup`/`make_eye_socket`、
或改碗深/材质分区前必读。

## 铁律 1: 改既有逻辑前先跑基线对比

用同一套判据量【旧产物备份】和【新产物】，再决定改什么。
真实代价: 曾判定旧「3D 松弛×12 w=0.3」形同虚设而删除（理由: 其后那个径向投影只动了 6/84 个顶点），
实测删除后 L 侧前视转角 5.93° → 68°（恶化 11 倍）。**平滑全靠松弛，无效的是投影，不是松弛。**
凭单点观察删代码 = 猜。

## 铁律 2: 先确认用户在看哪个阶段的产物，再看装配态

眼窝是分步的: `01_1`=只有碗(无眼球) → `assign_socket_material` → `02QR` → `run_eyeball_v2` 出 `01_2`(碗+眼球)。

- **空窝态(01_1/材质分区文件)**: 碗是**空腔**，正面看天然是「粉色盘 + 中心亮盖」，像贴了个盘。
- **装配态(01_2)**: 眼球(直径 29.1mm)只填满**上下**；开口宽(=手描轮廓 width_mm，本工程 35.06mm)大于眼球 ⇒ **内外眼角各露出约 3mm 碗面**（属开孔宽度的真缺陷，要靠眼球尺寸/眼睑皮肤几何解决，不是 rim 问题）。
  ⚠ 「零红像素 / 碗被完全遮住」是**按材质名涂红**渲染得出的**假通过**，别再引用；见「诊断陷阱·验证渲染按 tag 上色」。

判读用户截图: 皮肤有照片贴图 + 红盘 + 放射/同心布线 ⇒ 碗态文件。此时先渲染装配态给人看，再决定要不要重做；
别拿空窝态的外观当缺陷去改几何。报告两种态的渲染，不要只给空窝。

## 判据表（区分「前视可见」与「3D 无害」）

必须分开量，混在一起会误判:

| 判据 | 含义 | 用途 |
|---|---|---|
| **转角XZ(前视所见)** | 环投影到 XZ 后量相邻边转角 | 红区边界形状，**主判据** |
| 转角3D | 空间转角 | 含 y 起伏，会虚高 |
| y 跨度 | 环的深度范围 | ≠伪影。手描曲线是**眼睑缘**(y浅)，删面边界环是窝底切口(y深)，本就不同 |
| XZ 偏离手描曲线 | 到用户权威曲线的距离 | 贴合度 |
| rim 邻接皮肤带翻面/退化面 | 改动的副作用 | 必须=0 或 ≤ 基线 |

图像空间独立验证（防自证陷阱）: 同机位渲染（**基线定机位，新版复用同一 lens/距离**），
PIL 提红区 mask → 连通域 → 边界转角/径向残差/圆形度 4πA/P²，归一化到平均半径（与缩放无关）。

## 宏观形状判据 — 边线全过 ≠ 形状对

上表全是**边线指标**；用户看的是宏观形状（凹不凹、像不像眼窝）。实测: 边线指标全部优于基线后
用户仍报「还是不对」——因为碗骑在原始扫描的**闭眼鼓包**上，碗底比同高度太阳穴平面还凸出，
是「贴在脸上的圆盘」而非凹坑。验收形状前必测:

| 量法 | 判读 |
|---|---|
| 世界 Y 直方图（单眼 XZ<12mm 面心，1mm 分箱；**越负越靠前，越大越深**) | rim/碗底/鼓包/周边皮肤的 y 分层是否合理 |
| 碗底 y vs 脸面基准 y（同高度太阳穴/脸颊） | 碗底必须比脸面基准更靠颅内，否则=凸出浅碟 |
| rim→碗底实测深度 vs 配置值 | 配置值≠产物值，永远量产物 |
| 侧视正交渲染（相机沿 ±X，ORTHO 小视场） | **前视渲染无深度线索**；凹凸只能侧视/剖面看 |

## 碗深按眼球几何反推（不要拍固定值）

碗是给眼球当背景的，深度必须由**眼球几何**定，而不是「够深就行」的固定毫米数。

```
球心 y   = 眼睑开口平面 y(手描 center) + 角膜顶点距 − 凸出量(0.1mm)
球半径   = 14.56mm（直径 29.1mm，取自眼球 asset）
碗底 y   = 球心 + 球半径 + 间隙(2mm)          # ≈ 开口平面后 31.8mm

**角膜顶点距必须取 `run_eyeball_v2.py` 运行时实测值（本 asset = 15.31mm）**：用眼球顶点质心反推会得 11.2mm，
质心被角膜侧密集顶点拉偏约 4mm，按它定的碗深会系统性偏浅 4mm。等价地：装配后从产物 `01_2` 里眼球顶点的
**y 极值(bbox)**复核，而不是用质心或公式反推。
遗留待办：配置常量 `BALL_CORNEA_DIST` 仍是 0.0112，应同步为 0.01531；当前靠末环逐顶点下沉的富余量
勉强包住（实测余量仅 1.4~1.6mm），属于「判据过但常数不对」的状态。
```

- 实现: `socket_ops.make_eye_cup` 的 `max_depth = SOCKET_CUP_DEPTH`（配置里带推导注释）。
- 判据（实测口径，眼中心柱内 tag 碗面）：**碗底 − 球后极 > 0**（碗包住眼球）、**碗底 − 脸面基准 > 0**（真凹进脸里）。
- 旧固定 15mm 的实测后果: 碗底 −93mm，球后极 −82.7mm **戳穿碗底 10.7mm**，且碗底仍在脸面基准(−82~−90)之前 ⇒ 浅碟。
- 加深后同时要查: 开放边/非流形边不变、眉毛区(z>1680)面数不变、ring M 不变。

## 诊断陷阱（每条都真踩过，代价是错误结论）

- **先查代码路径的激活门，再赖它造成症状**。v47 碗内松弛被怀疑「吃掉 5.5mm 碗深」，其实它只在
  `SOCKET_VARIANT == "chamfer_relax"` 分支里跑，而当前是 `inward_fillet` ⇒ 根本没执行；实测碗深就是配置值。
- **统一 y 符号约定并写下来**: 越负越靠前(脸外)，越大越深(颅内)。曾因此把单调变深的正常碗读成「中心穹顶」。
- **任何按 XZ 距离取面/顶点的量都要加 y 过滤**。眼中心柱不加 `y<0` 会抓到颅后壁(y≈+94mm)，
  算出「碗深 +202mm」这种荒谬值；「XZ 环带周边皮肤」同理。
- **宣布几何是「漂浮碎片」前先查它是否接在边界环上**：比较它与环自身的坐标范围。实测环自身 y 就探到 −115mm，
  那些面是接在环上的**睑缘面**（删了破坏眼睑），不是碎片。判据「面心在轮廓多边形内」也抓不到它们。
- **按眼单独分析**；合并双眼红区会让质心落到鼻梁、PCA 轴全错，中心区 n=0。
- **PCA 最薄轴 ≠ 前后轴**（眼区薄方向≈碗法向）；直接用世界 Y 分箱，别猜轴。
- **红面距手描 rim >2mm 不全是 bug**: 横向 margin 2mm/外眼角 4mm 是历史设计（保 UV/避眉毛）；
  报「红牙」前先扣掉设计 margin，只把真外溢算缺陷。
- **深漏斗 + 平盖在前视/正面光下读成凸起**（盖正对镜头最亮、碗壁在阴影里 = 空心面具错觉）。
  vision 和人都可能报「中心凸起」；用深度剖面定案，剖面单调变深就是正常碗。
- **先探针后改产线**: 01A 单次 headless 跑约 8 分钟。定新判据（如清理某类面）前，先在**产物文件**上跑只读探针
  确认它抓到的正是目标；否则会白跑一轮才发现「补删 0 个」。
- **headless Blender 重定向到日志时输出有缓冲**，长时间没有新行不等于卡死；先看进程 CPU 时间是否在涨，
  再决定是否重跑。一次无效重跑 = 白花一轮，且会覆盖掉上一轮的产物备份。
- **验证渲染按拓扑 tag 层上色，不要按材质槽名**。装配态 `01_2` **没有** `EyeSocket` 槽（材质分区只加在
  `01_1_*_qr` / QR 输入上）⇒ 按材质名涂红会把碗面涂成皮肤色 ⇒ 渲染出「零红像素、眼球填满开口」的**假通过**，
  正好掩盖眼角露碗这类真缺陷。用 `v44tag_L/R == 2` 上色，并在装配文件上量 bbox 复核。
- **`git status` 里手调数据文件（标记点 blend / 轮廓 json）显示被改 → 先查 mtime 是否落在自己本次运行窗口内**；
  落在窗口内才是管线写的，否则是用户自己的标记更新 —— 不要回滚、也不要替他提交。
- 一次性复核脚本: `scripts/verify_eye_socket_geometry.py`（tag 碗面 + y<0 过滤量碗深、眼球 bbox 算包围、
  侧视正交 + tag 上色渲染），改路径即可直接跑。

## 材质边界「红溢出到 rim 环外」= 补红面的顶点戳出轮廓（v61）

用户截图见「红色三角片溢到眼窝外皮肤」时的定案链（别再从几何重做碗，先查材质分区）:

1. 用「面心是否在轮廓内」判定 → 环外红面 **0**（面心没跑出去）。
   旧脚本用「到轮廓折线的距离」判溢出是**假警报**：折线距离分不了内外，天然把轮廓内部的面也算「超」。
2. 上色调试渲染（tag 碗面=红 / 补红=橙 / 皮肤=灰）→ **橙色面片正是戳在红灰交界皮肤上的小三角** = 用户所见红牙；
   红区自身边界（不含橙）是平滑的。76 个补红面里 52(L)/59(R) 个有顶点戳出轮廓 >0.5mm。
3. 根因: `assign_socket_material.py` 补红闸门只判【面心】在轮廓内 + 到轮廓折线 3D 距离 ≤2mm；
   大皮肤三角常见「面心在内、顶点戳出」，整面染红就溢出成红三角片。
4. 修: 补红面的**【所有顶点】**必须在轮廓内（容差 0.3mm）→ 补红 76→18；红面顶点戳出的 52/59 → **0/0**；
   材质边界到轮廓 XZ 距离中位 0.151/0.222 → **0.091/0.122mm**（p90 0.45/0.44 → 0.30/0.34）。
5. 无回归: QR 眼区灰楔=0（QR 自己还有 8.5d 灰楔消除兜底）、红区连通块=2、非流形 0、quad 99.99%。

残余上限: 材质边界仍受**网格量化**限制 —— 眼洞边界只能是网格边环，到轮廓偏差最大 0.9mm；
眼角再叠上手描轮廓自身的尖角 ⇒ 仍可见 ~1mm 级尖角。要更平滑必须沿光滑曲线重切网格（knife/boolean 已否决），
或请用户把眼角画圆一点。

规则: **判「内/外」必须用点在多边形内(射线法)，不能用「到折线距离」**；
**判「整块面会不会溢出」必须遍历它的所有顶点** —— 只看面心（会漏顶点戳出）、只看单顶点（会误收大三角）。

## 三个真根因与修法

1. **触 rim 的 sliver 被溶解 → rim 顶点爆炸**。溶解产生 ngon → 三角化重铺 → 材质边界改道。
   实测 R 侧 rim 76→104 顶点、前视转角 max 137.7°。修: 触 ring0 顶点的 sliver **只 `reverse_faces` 翻法线，不 dissolve**。
2. **全局扫描式三角化误伤别侧成果**。`dissolve_faces` 后「扫 `bm.faces` 三角化所有 ngon」，
   在 L/R 顺序处理下，cup R 的 pass 会把 **L 已建好的碗底 ngon 盖**打碎
   （L 盖带 `v44tag_L==2` 但 `v44tag_R==0`，按本侧 tag 排除不掉）。实测 L 碗面多出 232 个三角面。
   修: 只三角化本次 dissolve 返回的 `region` 产物 → region-local。
3. **碗底单极点放射扇** = 中心黑洞 + 放射布线。修: 末环收缩到 25%（半径≈3mm）后
   直接 `bm.faces.new(tuple(last))` 用**单 ngon 平面盖**收尾（眼球遮挡，QR/FBX 会自行三角化）。

## 否决路线（全部 spike 实测，别重复踩）

| 方案 | 失败证据 |
|---|---|
| `knife_project` | headless 返回 `FINISHED` 但 **0 切割边**（视口投影矩阵退化） |
| boolean EXACT/MANIFOLD | 原始扫描网格**非流形** → MANIFOLD 0.4s 拒绝执行、面数不变 |
| 顶点墙/面心管带 + BFS 洪泛 | 墙有缝 → **泄漏删光 193 万面** |
| 吸附网格顶点 + 测地线补全成环 | 补全路径**自交** |
| 弧长等距重排 | 位移 mean 15.9mm / max 29mm |
| 全量 snap 到手描曲线 | y 位移 mean 2.4 / max 7.3mm → 眼睑被拉出坑 |
| **XZ 投影到曲线折线** | 82 顶点投 72 段折线 → 弧长非单调 → **转角 5.93°→39°/max180° 尖刺** |
| 洞内补删（迭代删多边形内面） | 边界环被删出缺口（现度1顶点，环不再闭合） |

规律: 该网格**非流形 + 眼区双层重复面**，依赖流形假设（boolean）或视口（knife）的算子都不可用；
「把顶点搬到别处」的方案位移都过大。有效的是**只修拓扑事件**。

## 诚实上限: QR 红区边界锯齿有下限

高模 rim 修平滑后（转角 4.4°、每边 1.02mm），QR 输出的红区边界**仍是阶梯状**:
QR 网格边长约 1.5mm 且材质**逐面**赋 → 边界只能沿 quad 边走。
数学验证: 单闭合环 53 顶点若平滑，平均转角应 ≈360/53=6.8°；实测 55.8°=总无符号转角 8.2 圈 = 阶梯。
要降只能提高 QR 目标面数或沿材质边界加密，**不是 rim 的问题**。报告时说清，别声称已消除。

## 眼中心必须读生产源

`eye_socket_config.py` 的 `IRIS_L/IRIS_R` 是**过期常量**，与生产实际用的
`iris_3ddfa.json` 的 `center_3d` **差 25mm**。用错会让 flood-fill 只删 1 个面、边界环走不出来。
