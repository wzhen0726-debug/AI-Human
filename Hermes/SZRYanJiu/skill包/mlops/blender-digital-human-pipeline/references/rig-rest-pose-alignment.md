# 骨架静止姿态对齐 Mixamo 参考（方案A, 2026-08-27 已验证）

**触发场景**: 用户给的 Mixamo FBX 动画套到自己搭的骨架上，出现手臂高举过头、小腿朝前反折、摆臂/迈步开度不对——根因几乎一定是 **rest pose（静止姿态）不一致**，不是蒙皮、不是权重、不是动画数据没绑。用户点名过："这个问题经常出现在静置姿态不同"。

**原理**: 骨骼动画旋转在每根骨的**局部空间**求值。若你的骨 Y 轴（延伸方向）/ Z 轴（roll 参考轴）与源骨架约定不同，同样数值的世界表现就错（roll 差 180° = 动作完全反向）。实测案例：47/52 根骨偏差（肩 roll 差 178°、大腿方向差 19.5°），重建后全部 0.00°。

## 方案A流程（朝向照抄参考，位置用用户打点）

1. **测参考骨架**：导入用户提供的 Mixamo FBX，选最大 armature，逐骨算 `rig.matrix_world @ b.matrix_local`：
   - `y = q @ (0,1,0)`＝骨延伸方向；`z = q @ (0,0,1)` ＝ roll 方向；存 JSON（模板：项目 C_诊断工具/measure_mixamo_rest.py）。
   - **勿再做坐标映射**：FBX 导入后 obj_rot=(π/2,0,0)，但测出的世界轴已与本项目模型同朝向（都面朝 −Y / Z-up），直接用。教训：按对象旋转另行推导的映射会把目标带偏（手臂抬高假象），要以"直接世界系测量"为准。
2. **重建骨架**：每根骨 `head`=用户标记点位置；`tail = head + mixamo_y × 长度`；`b.align_roll(mixamo_z)`；父子层级照 Mixamo。整架重 build 比"逐骨修补 N 根问题骨"快且不易漏（用户选过方案A拒绝逐根修）。
3. **验收标准（硬性）**：重跑对照脚本，要求同名骨 **方向差 = 0.00°、Z轴差 = 0.00°、问题骨 = 0**。残留的位置差是模型体型比例差异（如 1.80m vs Mixamo 原型），不算错。模板：C_诊断工具/rest_pose_compare.py、mixamo_mapped_compare.py。
4. 收尾照常：ARMATURE_AUTO 权重（须 100%）、`mixamorig:` 前缀（重命名骨骼时 Blender 自动联动顶点组）、姿态纯净清零、GLB 导出。

## Mixamo T-Pose 世界轴实测摘录（本模型面朝−Y / 左=+X / 上=+Z）

| 骨 | Y(延伸) | Z(roll) |
|---|---|---|
| Hips | (0,0,1)↑ | (0,−1,0) |
| Spine/Spine1 | (0,0.12,0.99) | (0,−0.99,0.12) |
| Arm/ForeArm/Hand/四指 | (±1,0,0)沿臂 | (0,0,−1)↓ |
| Thumb1 | (0.77,−0.45,−0.45) | L:(−0.50,0,−0.87) R:(0.50,0,−0.87) |
| UpLeg/Leg | ≈(0,0,−1) | ≈(0,−1,0) |
| Foot | (0.02,−0.89,−0.46) 前 下 | (−0.05,−0.46,0.89) |
| ToeBase | (0,−1,0) | (0,0,1) |

注意 **Foot 的骨延伸方向是"踝→趾"斜前下**——脚骨若画成"踝→脚跟"则 Y 朝后，roll 约定必然对不上。

## 伴生坑（这次实际踩过的）

- **左右命名镜像**：模型面朝 −Y 时 +X 是模型自身的左＝Mixamo 的 `Left`。用户视角标的"右肩"（+X 侧）要建成 `Left*` 系，否则动画左右镜像（双手交叉式拧转）。
- **动画文件污染**：做行走测试时 FBX 会带进 Alpha_Joints/Alpha_Surface/参考 Armature，动作看着"只在参考模型上"。复制完 action 必须删参考对象，并把 `animation_data.action_slot` 绑到**装着 fcurves 的那个 slot**（比对 channelbag.slot_handle == slot.handle；action_slot 可能默认指着一个空 slot，表现为骨骼全 (0,0,0)、mesh 零变形）。
- 删 Hips 的 location 曲线（全局位移会让模型飞走），保留旋转。
- **验证变形必须用 depsgraph 求值网格**（`obj.evaluated_get(dg)` 再读 vertices）；读原始 `body.data.vertices` 永远 0 变形，曾据此误判"动画没生效"浪费大量轮次。
- 数值验收后仍建议渲染 1~2 帧＋让用户 GUI 播放确认；灰剪影下 vision 不可靠，以数值为准。
