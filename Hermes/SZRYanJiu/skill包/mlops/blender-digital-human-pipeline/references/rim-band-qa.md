# Rim 带（开孔缝合带）坏面：归因与自适应修复

适用：眼窝/开口 rim 环附近出现扭曲、细长、错面，且会被下游重网格（QR）放大。

## 1. 先归因，再动手（禁止猜）

对**输入网格**与**处理后输出**分别统计同一区域的坏面占比，并与其**同网格上未被修改的参考带**对比：

- 分区口径：面心到轮廓折线的 XZ 距离（band < 1.16×名义带宽；参考带 2.3~6.2×名义带宽）—— 窗口随推导带宽缩放；眼区半径用模块既有推导值（EYE_AREA_R＝0.86×实测眼宽），不要再引入毫米绝对值；
- 指标：最小角 < 15°、长宽比 > 4 的面占比（可选：非平面度、法向朝后）；
- 判据自参照：`band 占比 ≲ 2× 参考带占比`。若输入本身干净而输出 band 变差数倍 → 坏面是缝合带产生的，从缝合带修。

用**距轮廓直方图 + 面心深度 + 方位直方**把坏面定位到具体机制：
条带内 → 采样/参数问题；pit/壁面内（深度在 rim 之后）→ 布尔切割产物，与带宽无关（做带宽扫描可验证：不敏感即非条带问题）。

## 2. 内环配对：必须用【极角单调配对】（v87 定稿；旧的“最近邻参数+强制单调”已废弃）

旧法“外圈每顶点取轮廓点集最近邻参数 → 解绕 → 强制单调(+minstep) → 取模”在**杏仁形角尖**处会翻车：
角尖高曲率、局部半径≪带宽 → 相邻外圈点集体吸附到同一角尖 → 解绕出现小回退 → 强制单调把序列推过头 →
取模后**内环双覆盖＝自交** → 条带面互相穿插（眼角“重叠乱面”），下游 QR 再放大成退化细长面。
打点形状微变即随机触发（“每轮打点不同就会复发”的机制）。

**正解（星形环性质）**：以轮廓质心为极点，外圈按环序解绕极角；内环点＝轮廓折线上**同一极角**的插值点。
同角度即同轮廓点 → 配对天然单调、**无交叉、无双覆盖**（结构性保证，不靠参数调优）。
配套：内外环绕向自动对齐（反向则反转外圈）；轮廓点序与角度序不一致时按角重排；形状/深度仍严格取自手描轮廓（只改采样位置）。
间距正则化与强制单调随之删除（它们只是旧配对的裨补）。

**内建独立自检**：内外环折线在 XZ 平面求线段交叉数（应=0，>0＝乱面前兆），直接印日志——比任何面形指标都直接。

## 3. rim 处理块外套"检测→调参重跑→择优"（不阻断）

半自动打点每轮点不同 → 最优参数每轮不同 → 不能写死。

- 阶梯：带宽 W = [默认, ×1.45, ×0.70]（内环不动，只改外扩量）；
- **跨轮必须量同一物理区域**：QA 窗口一律按【名义带宽 base】算（不是各轮自己的 W），否则跨轮分数不可比；
- 每轮重建后测 band/参考带占比，按 (小角<15° + 长条 + **针状<5°**) 择优保留；
  针状(<5°) 是 v87 新增的**独立维度**：旧判据只有小角/长条，对眼角针状面驴感 → 出现“修复治A类、缺陷恰是B类”的盲区；以后新增修复时，必须同步新增一个**与修复机理无关的检验项**（自证陷阱第三踩教训）。
- 达 "band ≤ 2×参考带" 早停；轮内异常跳过；全部失败保留原样并告警；
- 实现：进入前 `snap = obj.data.copy()`，重试时 `obj.data = snap.copy()` 还原；
- **坑**：整体替换 mesh 数据块后，调用点下游的本地 `mesh` 变量会失效（`ValueError: The mesh must be in editmode`），必须 `mesh = obj.data` 重新绑定。

## 4. 验证

- 数值：修复后 band 占比应接近参考带（实测可从 7.2%/6.3% → 2.5%/0.9%）；下游 QR 输出同区再测一遍（11.2% → 1.6%）。
- 视觉：正交正视特写 + 平面着色即可看到外眼角拉出的**细长丝状面**；修好后消失、睑缘平滑。相对路径在原生 Blender 进程中会解析到 C:\（工作目录不同），**输出务必用绝对路径**。

## 5. 参数纪律（交付前必审计）

用户会直接追「再检查是不是死参数」。新增的每个数字必须归入三类之一，归不进的找出推导：

1. **模型实测推导**：带宽＝0.035×实测眼宽；内环均距＝环周长/K；QA 窗口＝名义带宽的倍数；眼区半径用模块既有 EYE_AREA_R。
2. **无量纲比值**：限幅 0.45~2.2×均距；阶梯 ×1.45/×0.70；早停 2×参考带；面形判据 15°/4:1。
3. **策略预算**（与尺寸无关，且最终由实测择优兜底）：迭代次数、滤波核权重、轮数上限。

审计做法：对新代码行区间拉全部数字字面量（先落盘脚本或 `sed -n 'A,Bp' f.py | grep -oE "[0-9]+" | sort | uniq -c`），逐条标来源；凡绝对毫米（窗口/半径/阈值）→ 改为随推导量缩放；改完**复跑等效性检查**（选定参数与指标应与审计前一致，不一致＝行为被改）。

耗时预期：每眼 ≤3 轮 × ~50s，达标早停 → 该步 ~1 分钟变 ~5-6 分钟属预期，主动向用户说明，免得以为卡死。

## 6. 环线平滑度（与坏面是两条独立轴，别用一个指标糊过去）

“rim 环不平滑 / 波浪 / 锯齿”指的是**开口边界折线**，不是面形——坏面指标全过也照样成立。先取环、再量、后修
（脚本 `scripts/rim_ring_smoothness.py`）。

- **取环**：`edge_keys` 计数 = 1 的边即边界；按眼心 + `EYE_AREA_R`、前向窗口筛出该眼，用邻接表串成闭环
  （串不成单环说明该区还有别的开放边，先查清再量）。闭合壳上出现边界边＝这些开口，数量应约等于环长×2。
- **指标（xz 投影，与轮廓定义平面同口径）**：边长 中位/最小/最大 + CV；转角 中位/p95/max + `>15°`/`>25°` 顶点数；
  另列最差 5 个顶点的坐标与两侧边长（热点基本落在内/外眼角）。
  校准值：L 环 161 顶点 CV 38%、max 18.5°、`>15°` 4 个；R 环 169 顶点 最小边 0.069mm、max 37.5°、`>15°` 28 个
  —— 与肉眼“左眼角错、右下睑不平滑”一一对上，说明该指标能替代目视定位。
- **三类根因（按此顺序查，都能从数字/日志判定）**：
  1. **清理阈值卡在缺陷值刚好之下**：焊缝 `RIM_WELD_MM` 是绝对死值 0.06mm，而该眼退化边恰是 0.069/0.07mm → 焊不掉，
     V 形凹口每轮复现。治法：阈值改取**环自身边长中位数 × k**（0.22~0.35，下限不低于原常量）→ 只焊退化边、不误伤正常边。
  2. **修复之后还有会重建缺陷的操作**：最后一次焊接排在松弛/去刺之后 → 新尖点无人再修（日志里那次焊接只做“二次翻转”）。
     治法：把“清理→松弛”成对挪到该分支最后，或循环到稳定。
  3. **判据投影与设计平面不一致**：去刺按**三维**转角判 `>25°`，而环形状由 (x,z) 定义 → 面外微起伏把 xz 31.7° 的
     尖点稀释到阈值以下、逃过检查。治法：改 xz 投影判据，改后用同一口径复量。
- **前向模拟定量**（不必重跑整链）：把新步骤作用在**现成产物**上，印指标前/后 + 残留。校准：R 环 顶点 169→167、
  最小边 0.069→0.152mm、max 转角 37.52→32.10°、`>25°` 4→1；残留＝边长 CV 34~41% 的“波浪”，属
  **环顶点等弧长重分布 + 深度低通**范畴（存量开关 `RIM_REBUILD_RING`），去刺治不了 → 如实区分“改善”与“修好”。
- **启用长期关闭的开关走 A/B**：备份现产物当对照基准 → 只改这一处跑同一环节 → 同一套量测比对 → 再给用户看。
  别默认“关着就是没用”，也别直接打开。
  **A/B 实测（`RIM_REBUILD_RING=True`，同一轮廓下的干净对照）**：边长 CV 38.0/37.1% → **16.9/15.9%**；
  最小边 0.236/0.069 → 0.141/0.160mm；转角中位 2.71/4.81° → **0.04/0.04°**；均值 4.50/7.87° → 2.13/2.20°；
  p95 13.4/22.0° → 11.6/11.1°；`>15°` 顶点 4/28 → 10/10；`>25°` 尖点 0/4 → **0/0**；K 门控 L5/R2 → **L6/R6**。
  环顶点 161/169 → 418/418、网格边界边数随之上升是**等弧长重采样**的结果（环本身变密），不是破洞。
  验证有效后该开关**保持开启**。
- **重分布只改“间距”，不改“形状”**：日志原文 `rebuild_ring_arc_length: … XZ 一个字节没动` ——
  它把顶点沿**既有折线**等弧长重排（新点落在原线段上 → 新顶点转角≈0），曲线形状没动。
  所以重分布后残留的折角（本例两侧各 10 个 15~24°）**属于轮廓自身**（12 手描点 → 72 点采样 → K 谐波低通），
  不是网格噪声 → 下一步该动**轮廓**（K / 轮廓重采样 / 手描点），继续在网格上加平滑 pass 是治错对象。
  排查顺序固定：**间距类**（边长 CV、退化边）→ **形状类**（轮廓谐波/手描点）→ **深度类**（Y 低通/碗深）。
- **左右对称性本身就是验收维度**：轮廓是镜像来的，两侧环指标应当接近。实测修复前 `>15°` 4 vs 28、
  最小边 0.236 vs 0.069mm（R 侧差 7 倍）——不对称即缺陷信号（单侧网格/参数问题）；修复后 10 vs 10、
  CV 16.9/15.9%、p95 11.6/11.1°。汇报一律 L/R 并列给，不报合计。
- **视觉 A/B 必须同相机同光照**（脚本 `scripts/eye_closeup_ab_render.py` 可直接跑）：固定正交特写（工作台引擎 + STUDIO 光 + 腔体/曲率 + 单色，
  `ortho_scale≈0.145m` 覆盖双眼、相机在眼高、朝 +Y），**只换 blend**，两张上下叠放并在标注里带指标数字。
  否则“看起来平滑了”没有可核对的前提（视角/曝光一换，什么都能被说成修好了）。

## 7. 下游 QR 视角：rim 越细 ≠ 越好；修复红线与相邻带验收

rim 环/带是给下游重网格（QR，150k 档四边 ≈3.7mm）用的输入，**它的“精细度”本身就是一个设计变量**：

- **先算量级比**：rim 点距 0.22mm 比 QR 目标四边（≈3.7mm）细 ~17 倍；眼角曲率半径 ~1mm 又小于目标四边
  → QR 在眼角“挤/重叠”是压缩时的必然反应，不是参数没调好。评估任何加密/减密方案，先给“输入局部尺寸 ÷ QR 目标尺寸”的比值。
- **输入密度实测梯度**（高模，供换算）：贴 rim 0.5~1mm 带 0.35mm → 2~8mm 平台 ~0.87mm → 8~20mm 1.42mm，
  即处处比 QR 目标细 2.6~4 倍。
- **禁止在 QR 低模上插点/重三角化**（“修复”环形状的常见冲动）：四边面上插点必然切成三角扇/极点——
  环指标会变好、布线全毁（用户验收语：眼窝旁边重新做了布线）。实测眼周 4mm 带四边占比 98~100% → 27.8~52.7%、三角扇顶点 0→22~57。
  （细化：全局/大面积插点重划仍禁；眼角长弦/大转角处的**微量环内拆段**——每环 ≤12 点级，带守门与形态门复验——已实测通过，见 `references/canthus-boundary-shape-gate.md`。）
- **允许的形态 = 纯移动**：只挪 rim 顶点（真值轮廓按弧长重采样到同点数 / 曲率重分布），点数不变 → 拓扑逐位相等；
  验收必须用**拓扑索引数组 md5 + 度数直方图**证明位等，不是“看起来差不多”。
  物理上限：N 点环表不出比自身间距更细的曲率（38 点环上眼角 68.7°→51.7° 即极限；47 点环可到 35°）——
  点数上不去就如实说“点数不足”，不靠插点硬凑。
- **QR 抽样非确定**：同一输入各次运行的 rim 点数/自交簇/面数都不同（实测 rim 出现过 38/42/47 点）
  → rim 指标不可跨运行比较；改动评测必须同网格开关 A/B，并带“验收门 + 不达标重跑”。
- **相邻带拓扑是独立验收维度**：只量目标曲线（环转角/边长）会在相邻区域留盲区——必须同时量
  **该区域外围（如眼周 4mm 带）的四边占比/三角扇/极点/n-gon/细长面**，以及自交的**双口径**（fan 扇形 + real 真三角化）。
- 引擎侧边界/密度/面数档位的硬限制（FreezeBorders、密度图、各档代价）见 `references/qr-engine-knobs-and-boundary-limits.md`。
