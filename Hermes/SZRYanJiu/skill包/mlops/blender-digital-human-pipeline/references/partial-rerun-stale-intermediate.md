# 手动重跑阶段 = 静默串旧中间件的陷阱

## 1. 事故模式(真实发生)

改完上游(01a 眼窝 rim)要重跑链路。看控制台里 `step_02` 的第一行是 `02_qr_auto.py`, 就只跑了它 → 02 目录里的
`输出/02_qr_150k.fbx` 刷新了, **看起来成功**; 但下游 `03_auto_uv.py` 读的是 **`02QR拓扑/输出/02_qr_150k_socket.blend`**,
而那个文件由**另一个脚本**写 → 它没被刷新, 时戳还是几天前。

结果: 03/04 全链**建在旧几何上**, 但每一步 EXIT=0、日志正常、自检全过 —— 你验证到的只是“代码机制在工作”, 不是“新几何生效”。

## 2. 铁律

1. **照抄控制台该 step 的完整脚本链**, 不能只跑名字最像主流程的那个。先 `sed -n '/def step_02/,/^def step_03/p' 控制台.py`
   把该环节的 `run_blender(...)` 列表读全。(本例 step_02 = 3 个脚本: QR拓扑 → 眼窝碗 → 眼球摆入。)
2. 重跑后用**时戳**验证每一个**被下游消费的**文件都刷新了:
   `find 各阶段/输出 -newermt "<本轮开始时间>"` —— 空集才是真的重跑过了。
3. 改上游后, 要核对每个下游脚本的输入常量(通常是脚本顶部的 `XXX_BLEND = os.path.join(ROOT, ...)`),
   列一条“文件 → 生产者 → 消费者”的表再动手。

## 3. 并罚陷阱: EXIT=0 不等于成功

`blender --background --python x.py` **脚本抛异常也返回 0**。必须:

- 加 `--python-exit-code 1` 让异常反映到退出码;
- 并把 stderr 落盘再 grep(`Traceback|Error|Exception`), 不要只看日志末尾几行。

真实例: 真值层脚本因新几何触发一个未覆盖分支(`ValueError: matmul ... size 4 is different from 3`)而崩,
但外层看到的仍是 `TRUTH_EXIT=0`, 产物时戳未更新 —— 若不做时戳核对, 会把**上一次的旧产物**当成新一轮结果汇报。

## 4. 判别“产物是新一轮还是旧的”的三步

1. 时戳(`stat -c %y`) 对比本轮开始时间;
2. 内容对指纹: 在 stdout 里找几个特征数(如 texel 数/align_mean), 再到落盘 JSON 里读同字段, 逐一对上;
3. 试改一个不相关的输入重跑, 看指纹是否变化(确认脚本真的重算了, 不是读缓存)。

## 5. 几何变了要重查的代码假设

几何一变, 很久不触发的分支会被触发: 例如

- 假设“命中面一定是三角形”的取值代码 → 高模里只有少数四边形, 平时碰不到, 几何一变就崩。
  正确写法: 按面的 loop 顺序扇形三角化后取命中点所在子三角(支持任意 n-gon)。
- 直接 `w @ uv[:, 0]` 之类的形状硬编码 → 改成先按面顶点数分支。
- 同一类假设要把整条管线 grep 一遍(`loop_indices`/`polygons[i].vertices[0:3]`), 不能只修报错那处。

## 6. 整链重跑时保护手调输入（半自动管线的另一半）

需求形如“用我这次的打点, 从 01 跑到 02”——不进 GUI、沿用旧打点重跑, 但 step 列表里**不是每个脚本都该跑**:

1. **跑前分类**: 一个 step 混着 自动计算 / 自动放点 / 人工 GUI 三类脚本。自动放点与 GUI 步会**重建手调集合** ——
   实测 `place_eyelid_markers.py` 开头 `read_factory_settings(use_empty=True)` 之后再删 `LM_L/LM_R/LM_VIS` 集合,
   headless 跑一次就把用户拖好的标记点清零。**跑任何一步之前** grep 该脚本 `objects\.remove|read_factory|清除|重置`。
2. **只跑纯自动步**(镜像→读点→开孔→赋材质), 把手调 blend 当只读输入沿用; 与手调文件同目录的中间产物先备份
   (镜像步会写回那个 blend, 只改它自己产出的一侧)。
3. **核对下游的输入常量**: 每个下游脚本顶部应有 `IN_BLEND = os.environ.get("XXX_IN_BLEND") or <上游新产物>`。
   手调 blend 内嵌**旧模型副本**, 只有确认下游打开的是上游新产物时才可无视它(本例 `EYE_IN_BLEND` 默认指向新的
   `01_highpoly_repair.blend` → 旧副本无害, 不必为了“同步”去重建手调文件)。
4. **上游修复会平移/缩放模型时, 旧打点坐标带系统偏差**: 量化后如实告知(眼角曲率半径 ~1mm 尺度上 0.16mm 不算小),
   说明“重打点后自然消失”, 不要默默沿用还宣称无差异。
5. **整链做成一个后台作业 + 可观测**: 每步 `> logs/<tag>.txt 2>&1`; 进度文件逐行 `START/END <tag> rc=`;
   成功写 `_rerun_DONE`、失败写 `_rerun_FAIL`(写明哪步)并 `exit 1`; 起跑前把 step 列表与预计耗时(门控那步最久)告诉用户。
