# Blender Digital Human Pipeline

Automated workflows for preparing, cleaning, retopologizing, and rigging high-poly meshes (e.g., from Tripo AI, 3D scans) into ready-to-use digital humans in Blender. Two distinct sub-workflows live under this umbrella — pick by goal:

## A. Decimate + Rig pipeline (preserve AI mesh, add skeleton)
**Goal**: Take a raw high-poly AI/scan mesh, clean it, reduce face count, bind a rig. Keeps the original topology (decimated). Use when the AI mesh topology is acceptable.
**Entry points**: `scripts/pipeline.py` / `pipeline_v2.py` / `pipeline_v3_pro.py`.
**QR headless**: `qremesher.remesh()` is MODAL — call `xremesh.exe` via subprocess (`references/quad-remesher-headless-xremesh.md`; pre-weld fix: `qr-input-mesh-cleanup.md`). Rotation: `rotation-correction-footscore.md`. **Eyes**: 01A眼窝 `references/eye-socket-and-eyeball-integration.md`+`references/eye-socket-normals-and-fillet.md`+`references/eye-socket-normals-recalc-vs-geometric.md`+`references/eye-socket-rim-contour-v45.md`(半自动标记点定眼窝边界, 替代3DDFA). **眼球摆位规律+微调面板**: `references/eyeball-placement-laws-and-finetune-panel.md`. **眼窝rim锐化(死路+正路)**: `references/qr-rim-sharpness-eye-socket.md` — GuidesFile和锐边标记都无效, 先试法线图修复. **给外行的零安装交互blend**: `references/demo-blend-for-laypeople.md`. **Repair**: diagnose first (`references/geometric-anomaly-diagnosis.md`, `references/chest-bump-flattening.md`); headless sculpt-brush automation unreliable (`references/blender51-sculpt-brush-headless.md`).
**Steps**: Import & analysis → auto-orient (Z-up, -Y forward via vertex data) → geometry cleanup (remove doubles, fix normals, delete loose) → decimate to <500K → partial tris→quads → auto-align MetaRig / Auto-Rig Pro → parent w/ auto-weights → generate Rigify control rig → organize Collections (Character, RigWidgets) → export .blend/.glb.
**Pitfalls**:
- **Shrinkwrap structurally fails on clothed A-pose→T-pose body wrap** — all 7 methods tried (direct Shrinkwrap, rotate-then-wrap, vertex-group-limited, RBF TPS, RBF Gaussian, anchor iteration, estimated landmarks) failed. Shrinkwrap pulls arm vertices to nearest torso clothing surface; RBF bulges inter-landmark regions. See `references/body-wrap-method-comparison.md` for full analysis.
- **ARAP is the key technology to solve RBF bulging** — local rigidity constraint prevents inter-landmark bulging. Industry standard is multi-step: RBF粗对齐→ARAP刚性修正→Surface Deform贴合. Open-source: `libigl-python-bindings` (369★), `oobma/ARAP-deformer` (Blender plugin).
- **MediaPipe Pose auto-detection (2026-07-28, NEW)**: Front+Back views reliable for upper body (vis>0.98), side views fail for lower body (vis<0.1). Use MediaPipe tasks API (`vision.PoseLandmarker`), NOT `mp.solutions.pose`. 12 key joints auto-detected, 2D→3D raycast projection needed. **Hybrid approach selected**: MediaPipe (core) + bone-assisted validation + RBF+ARAP deformation. See `references/body-wrap-method-comparison.md` for full implementation details and the 3-approach comparison (skeleton-driven vs MediaPipe vs NICP).
- **MetaHuman matrix_basis has built-in 0.01 scale** (cm→m) — don't manually `v.co *= 0.01` then `transform_apply`, this double-scales and collapses vertices. Just `transform_apply` directly.
- **MetaHuman original orientation is face→-Y** (same as Tripo after 3-step rotation) — no Z-90° rotation needed. Earlier scripts incorrectly rotated, making face→-X.
- **Must import Body+Head for correct height scaling** — Body alone is 1.496m, Body+Head is 1.803m. Scale by total height.
- Avoid `bpy.ops` mesh operators in background mode where direct vertex manipulation (`v.co`) works — more stable.
- AI meshes often export Y-up; identify the height axis (max bbox range) first.
- For non-T-pose AI meshes, Auto-Rig Pro is more robust than Rigify (fallback).
- Over-decimation below ~400K destroys needed detail; user-acceptable floor is ~500K tris.

## B. Landmark-based Retopology (wrap a good-topology template onto a target shape)
**Goal**: Transfer a clean, animation-ready topology (e.g., MetaHuman `MH_Head_01.obj`, ~8K pure-quad verts) onto a high-poly target (scan or Tripo), preserving the template's edge flow. Use when you need production-grade topology, not the AI mesh's own.
**Entry points**:
- `scripts/mp_v2_final.py` — original; opens a `.blend` and grabs the `Scan_Head` object (which carries a 90°X rotation that the template must mirror). Use when the target lives in a blend with a rotated scan.
- `scripts/scan_to_template_fit.py` — **preferred for OBJ/GLB targets already in Z-up, face-toward-(-Y) orientation** (e.g., `Scan_Head_Lv5.obj`). Imports the target OBJ directly, skips rotation, centers to origin, and uses improved KDTree+local-extremum geometric landmark detection (see references). Use this when the target and template already share orientation. **12-anchor variant**: anchors only the 12 core MediaPipe facial points. Produces good surface-distance numbers but **visual QA reveals eye-socket float, nose/lip penetration** on concave features (see Bug 4 in references).
- `scripts/scan_to_template_fit_v2.py` — **contour-anchor variant**. Fixes v1's concave-region problems: maps ~81 MediaPipe contour points (32 eye-socket + 40 lip + 9 nose-ala; brows REMOVED — see Bug 5) onto the target surface and matches them to nearest template vertices, yielding ~52 effective anchors. **Shrinkwrap is all-NEAREST** (NOT PROJECT-first — PROJECT causes left/right asymmetry; see Bug 5). Anchor iterations 20→30. Use this when v1's visual QA shows sunken-feature problems (eye sockets, lips, nose tip). **Verify left/right symmetry after fitting** (`scripts/diag_asymmetry.py`).
- `scripts/detect_template_landmarks.py` (build the template vertex-index map), `create_template.py` (manual-verification file).
**Full technique detail**: see `references/landmark-retopology.md` — READ IT before touching this workflow; it contains the non-obvious bugs (MediaPipe left/right mirror), the anchor-iteration algorithm, the improved geometric-landmark detection, and Blender-5.1 API quirks. **Industry survey and paid/free alternatives**: see `references/retopology-research-2026.md` — Wrap4D, UE5 MetaHuman, FLAME/DECA, Quad Remesher, and head-to-head comparison of why our Shrinkwrap fails on thin structures (no dedicated lip/eyelid detector).
**One-line summary**: MediaPipe detects 12 facial landmarks on rendered views → raycast to 3D surface → template's 21 pre-indexed vertices aligned by centroid → 4-round Shrinkwrap → 20-round anchor-point Laplacian iteration (the key step, since Shrinkwrap alone doesn't preserve vertex-to-target correspondence) → surface correction → validate.
**Typical result**: 12 facial anchors 0.0mm deviation, mean surface distance 0.26–0.44mm, 94–99.7% within 1mm.

## Choosing orientation handling (critical)
- **Target has `rotation_euler.x ≈ 90°`** (scan-in-blend case): rotate the template the same 90°X in vertex data so both share orientation. This is what `mp_v2_final.py` does.
- **Target is already Z-up, face toward -Y** (OBJ-exported scans like `Scan_Head_Lv5.obj`, or oriented GLBs): do NOT rotate — the template `MH_Head_01.obj` is also Z-up face-(-Y). Rotating here flips the face away and breaks MediaPipe detection. `scan_to_template_fit.py` skips rotation for this reason. **Always verify orientation with a 6-view render + MediaPipe probe before fitting** (`scripts/diagnose_scan_lv5.py` is a template for this).

## C. Tripo AI Full Pipeline: High-Poly → Bound Digital Human (GLB)

**Goal**: Take a Tripo AI generated clothed high-poly model, remove clothes/hair/eyelashes, retopologize, apply ARKit 52 BlendShapes (facial) and Mixamo skeleton (body), export as `.glb`. This is the production pipeline for the user's 全流程文档 project.

**Stages**: Import GLB → Voxel Remesh → Clothes removal (AI segmentation primary, Boolean cut for tight clothes only, SMPL transplant for large gaps) → Hair removal (two approaches: remove+Groom or keep as integrated mesh — see below) → Eyeball/teeth deletion (MediaPipe locate → delete connected components, keep cavity interior walls) → Geometric hole repair (bmesh fill + Shrinkwrap to body template + Laplacian smooth) → **Symmetrize HIGH-POLY** (bmesh vertex mirror — MUST be before wrap, not after, to ensure bake correctness) → Standard low-poly full-body wrap → UV unwrap + texture bake → Body skeleton binding (Rigify+auto-weights for distributable; Auto-Rig Pro for dev) → Eye/teeth assembly → Export GLB.

**Scope note (revised 2026-07-09)**: Facial binding (ARKit 52 BlendShape) is **deferred** — current scope is body skeleton + weights only, no controllers, model goes to engine. The standard low-poly topology already has facial edge loops for future BlendShape expansion.

**Key decisions** (see `references/tripo-full-pipeline.md`, `references/clothing-hair-removal-research.md`, `references/clothing-removal-deployment-packaging.md`, and `references/blender-symmetry-uv-baking.md` for the full feasibility research):
- Only route 2 (AI gen) — route 1 (camera matrix) costs ¥10万+ in hardware, infeasible.
- **Clothes removal**: REVISED after 2026-07-08 research — volumetric Boolean cut **only works for tight clothing** (1-3cm error, needs pose alignment). It **FAILS for loose clothing** (coats/skirts/dresses) because Tripo meshes are single-surface with no body geometry under the clothes. **Recommended primary: AI segmentation** (2D multi-view → 3D face projection + voting, ~80-85% face-level accuracy). For large gaps where geometry is missing, transplant corresponding region from SMPL template. **Deployment/packaging** (verified 2026-07-08 from HuggingFace model pages — see `references/clothing-removal-deployment-packaging.md`): Best lightweight models — **SegFormer B0 Clothes** (14.9MB, MIT, 18-class clothing parsing, best for automatic pipeline) or **EdgeSAM** (38MB ONNX, Apache-2.0, complete encoder+decoder ONNX, higher accuracy than MobileSAM, needs prompts). Combined with **LaMa ONNX** (~50MB) for texture inpainting = ~108MB total, no PyTorch/GPU needed. **MobileSAM** is 40.7MB (MIT, general zero-shot, needs prompts). All export to ONNX → users only need `pip install onnxruntime` (15MB). Non-AI fallback: color+curvature+normal+distance rule fusion (50-70% accuracy, zero dependencies, works only with textured models + tight clothing).
- **Hair removal — TWO approaches (revised 2026-07-09)**: The user identified two viable strategies:
  - **Approach 1 (recommended, higher quality)**: Remove hair from AI high-poly, then generate hair separately using a grooming system (e.g., UE5 Groom, Blender Hair curves). Removal method: color-based segmentation (dark hair vs flesh-tone skin via UV texture sampling — highest reliability for dark hair) + curvature filtering (scalp is smooth/low-curvature, hair is high-curvature) + spatial position filter (only apply to head/upper region). SOTA: Pixels2Points (arXiv:2504.19718) fuses 2D+3D features for skin/non-skin segmentation.
  - **Approach 2 (simplified, lower quality but easier)**: Do NOT remove hair. Keep the AI high-poly's hair mesh and wrap it together with the head as a single integrated mesh. The hair becomes solid geometry (no strand-level dynamics), but implementation is much simpler — just include the hair region in the Shrinkwrap target. Suitable for use cases where hair dynamics are not required.
  - **Eyelashes**: Deprioritized — do not process separately. Either removed as part of hair removal or left in place. Can be addressed in a later refinement pass.
- **Pose correction vs symmetrization — two ORTHOGONAL operations (critical distinction)**: Pose correction rotates joint ANGLES (arm position, head tilt) — it does NOT fix left/right body-type differences (e.g., left shoulder 0.5cm higher than right). Symmetrization mirrors vertex POSITIONS (left/right body-type averaging) — it does NOT fix pose. They operate on different subspaces (SE(3) rotation vs vertex coordinates), are NOT interchangeable, and BOTH are required in fixed order: **Pose correction → Symmetrization**. If the AI model is already in T-pose but left/right asymmetric, pose correction is a no-op (no angles to fix) — symmetrization handles it. If the model is in A-pose but symmetric, symmetrization is unnecessary — pose correction handles it. Precision standard: ≤15° deviation from T-pose is acceptable for Rigify auto-binding; ≤5° for wrap topology transfer.
- **Symmetry + texture — CRITICAL ORDERING (revised 2026-07-09)**: You MUST symmetrize the **high-poly** BEFORE wrap and baking, NOT after. See `references/symmetrization-texture-baking-definitive.md` for the complete proof, ZBrush Smart ReSym official docs analysis, bmesh implementation, and the Pose-correction-vs-symmetrization distinction. Reason: if the high-poly is asymmetric (e.g., left arm raised, right arm down) and the low-poly is symmetric (both arms down), Blender's Selected-to-Active bake projects rays from low-poly normals outward to hit the high-poly — but the surfaces don't overlap in space, so rays hit wrong high-poly surfaces (or miss entirely), producing texture garbage. **Correct flow**: ① Symmetrize high-poly (bmesh vertex coordinate mirror) → ② Wrap low-poly template onto the now-symmetric high-poly → ③ UV unwrap → ④ Bake textures. This ensures high and low poly occupy the same space during baking. For facial micro-asymmetry (natural ~1mm differences), baking to a symmetric low-poly is acceptable — the error is sub-pixel. **The head ALSO requires mesh symmetrization** — the user explicitly stated "头部也是要做网格镜像的，不然之后需要绑定，不对称的话很难打控制点" (head also needs mesh mirroring, otherwise binding control points on an asymmetric mesh is difficult). The standard low-poly template is symmetric topology, so wrapping it onto a symmetrized high-poly naturally produces a symmetric head mesh. **ZBrush Smart ReSym (智能重新对称)** only modifies vertex positions, NOT UV (confirmed via official docs at help.maxon.net/zbr — "positions of vertices" only, "does not use UVs"; user also tested and confirmed). In documents, use "Smart ReSym" or "智能重新对称" — the user corrected this naming. Script and plugin recommendation (`mio3_symmetry`): see `references/eyes-teeth-symmetry-stitching.md` and `references/blender-symmetry-uv-baking.md`.
- **UV/baking pitfalls**: Smart UV Project is uncontrollable (seams on face, island fragmentation, no symmetry). For automated pipelines, use the dihedral-angle auto-seam pipeline (see `blender-uv-texture-baking` skill: edge-angle detection → symmetry-axis seam → Angle-Based Unwrap → pack islands). For manual workflows, mark seams manually + Unwrap. For baking after clothes/hair removal: separate high-poly source objects and bake body-only, or use small Max Ray Distance (2-5mm) to avoid projecting clothes texture onto body. ## D. Quad Remesher Simplified Pipeline (v3 — 8-10 weeks, fully automated)

**Goal**: AI-generated clothed high-poly → Quad Remesher (20-25万面) → Auto-UV → Bake → Mixamo bind → GLB. Keep clothes/hair/eyes as-is. No face binding. No MetaHuman wrap.

**When to use**: Fast, fully automated pipeline. Accept static face, rigid hair/cloth. Photography must use tight clothing.

**⚠️ Voxel Remesh size destroys fingers (critical pitfall)**: A voxel_size of 
0.005m (5mm) merges adjacent fingers into a solid blob — finger spacing is 
~2-3mm, below the voxel resolution. Use `voxel_size=0.002` (2mm) to preserve 
finger-level detail. At 0.002, the repair mesh grows from ~34K to ~218K 
vertices (6.4x) but QuadRemesher handles this fine. Reduce smooth_iterations 
proportionally (5→3) to avoid over-smoothing. **Always verify**: after 
repair, check that the arm span BBox width is preserved and finger tips exist 
at the expected Y extents (±0.4m for typical T-pose).

**⚠️ Voxel Remesh DESTROYS facial detail — do NOT use it for repair (v7 correction, 2026-07-23)**: 
The v6 approach used Voxel Remesh (voxel_size=0.005) to produce a ~34K watertight proxy. 
The user corrected: "网格修复后的面数好少啊，面部细节都快没了" and "34k模型的意义是什么？" 
Vision analysis confirmed 80-90% facial detail loss at ALL tested voxel sizes (0.003=96K, 
0.004=54K, 0.005=34K faces — all lose lips/nose/eyes). **Correct approach (v7)**: do NOT 
run Voxel Remesh. Only do geometry cleanup (remove_doubles, fill_holes, dissolve_degenerate, 
fix_non_manifold) on the original high-poly. Output preserves ~193万面 with full facial 
detail. Quad Remesher (next stage) handles face-count reduction with curvature-adaptive 
retopology that respects facial features. The repair stage's job is topology repair, NOT 
face-count reduction. **Adhesion repair is part of the same stage** — the user clarified

### Python-docx: avoid stream timeouts

When generating .docx via Python, a single large script WILL hit the ~8K token write limit and stream-timeout silently. **ALWAYS split into small sequential scripts** (<3K tokens each):

1. `gen_step1.py` — `Document()` → cover + chapter 1 → `doc.save()`
2. `gen_step2.py` — `Document(path)` → chapter 2 → `doc.save()`
3. Continue for remaining chapters, run sequentially via `terminal`, clean up scripts when done.

Each step uses load-and-append (`doc = Document(path)`). Never try to write all content in one script.
