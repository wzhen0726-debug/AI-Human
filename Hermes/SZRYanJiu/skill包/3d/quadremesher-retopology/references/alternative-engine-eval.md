# 替代引擎评测（QR 的开源替代：QuadriFlow / QuadWild-BiMDF）

用途：任何「换掉 QR 引擎」的候选都要按这份口径测，并对照已测到的闸门与硬指标。
**当前状态：没有任何开源候选达到基线——本文件不是「替换方案」，而是评测标尺 + 已排除的路线。**

## 1. 评测口径（必须复用管线自己的判据，避免自证）

| 维度 | 口径 | 基线（必须打到） |
|---|---|---|
| 卫生四件套 | quad 占比 / 非流形边 / 退化+重复面 / **自交对** | ≥99.9% / 0 / 0 / **0** |
| 密度 | 面数 + 边长均值/中位 | 160,967 面 / 边长均值 ≈3.6mm |
| 边界行为 | 边界边条数（眼洞开口是设计内） | 83 量级 |
| 细节保真 | 对高模 chamfer（KDTree，均值/p95/max） | 仅作参考 |

- **自交判据必须用管线自己的**：`02QR拓扑/scripts/selfint_clean.py` 的 `_self_pairs`（精确三角对检测，**不排除共享顶点**）。自己另写一个宽松判据 = 判据自盲，会把不合格件判过。
- 统一评测脚本：`scripts/qr_alt_eval.py`（`--in` 任意 blend/fbx/obj；`--selfint-module` 传管线 `selfint_clean.py`；`--quadriflow N` 一键跑 QuadriFlow；`--out-obj/fbx/blend` 导出产物）。
- **验前先量化输入件**（顶点/面/非流形/边界），不然无法解释候选的失败与差异。

## 2. 闸门：输入必须先满足什么，候选才跑得起来

### QuadriFlow（Blender 内置，MIT）

- **要求严格流形**：非流形边 >0 直接拒收——0.0s 返回告警 `The mesh needs to be manifold and have face normals that point in a consistent direction`，静默不改网格。
- **开放边界不是闸门**：把边界从 341 补到 2 后仍被拒，真正的闸门是那 5 条非流形边。
- 要用它必须**破坏性清修几何**（split_edges / 删面）+ 输出后**重新挖回眼窝开口** → 保底定位，不当主力。

### QuadWild-BiMDF（官方 Windows 预编译 CLI）

| 输入 | 结果 |
|---|---|
| 全分辨率 ~1.9M 面 | ❌ 场阶段 `fatal error: igl::copyleft::comiso::NRosyField::angleDefect: Division by zero!` |
| 抽面 250k 三角 | step1 ✅ / step2 ❌ `valence not handled: 2`（换 4 种 flow 配置都一样；ILP 配置需 Gurobi，未编译） |
| 抽面 250k + 强制补孔闭合 | ❌ step1 **段错误**（exit 139） |
| **抽面 100k / 150k 三角** | ✅ 跑通出结果（唯一可行档） |
| 均匀网格 + `do_remesh 0` | step1 ✅ / step2 **段错误**（8.4k 与 85.7k 两档同样） |

→ 该构建下**只有「抽面到 100~150k + 让引擎自己 remesh」能出结果**，而它的密度被内建 heuristics 钉在 ~19k remesh → **~40k 四边，密度上不去**。

## 3. 隔离实验（闸门到底是哪个属性：造最小对照件）

造**只差一个属性**的合成件（各 2 万面，秒级）逐个跑，不要拿真件试参数：

| 对照件 | step2 | 结论 |
|---|---|---|
| 闭合流形球 | ✅ 100% 四边 | 基线可用 |
| 同球挖一个孔（开放边界） | ✅ 100% 四边 | **开放边界无罪**（推翻直觉假设） |
| 同球加噪声 + 局部密化（密度不均） | ❌ 无产出 | 真因在**密度不均/规模** |

## 4. 实测结论（QuadWild 100k/150k 档，与 QR 基线同判据）

| 指标 | QR 基线 | QuadWild |
|---|---|---|
| 面数 / 四边占比 | 161,520 / 99.95% | 39,764 / **100%** ✅ |
| 非流形 / 退化 | 0 / 0 | 0 / 0 ✅ |
| **自交对** | **0** | **1,456** ❌ |
| 边界边 | 86 | 214 |
| 边长均值 | 3.63mm | 7.22mm |

- **自交集中在头部/颈**（最大单簇 464 对）——正是本项目最不能出问题的区域；全身散布 200+ 簇，不是局部毛刺。
- **管线自带清理器救不回**：把它作用到该产物上 → 1,456 → 1,198 后停滞（“无进展”早停，逐簇修复全部回退）。`selfint_clean` 是为「几十对残留」设计的，千对量级超出能力——**别把“先产出再用清理器收”当可行路线**。
- **密度旋钮不在配置里**：prep `alpha` 0.01→0.0025 内建 remesh 输出**逐字节一致**；main `alpha` 0.005→0.0015 只使四边数 +7%；内建 remesh 面数与输入面数几乎无关（100k→18,066、150k→18,912、250k→14,135）。想上密度需换构建（自带 preprocess 的封装版 / 自编译改内建密度）。

## 5. 操作坑（会直接浪费时间的那种）

- **判成败看产物，不看退出码**：`quad_from_patches` 可能**产出正常网格却返回 3**；`quadwild.exe` fatal 返回 1；`do_remesh 0` 路线是段错误 139。按退出码写流程分支会误判。（与 QR 引擎「退出码恒 0、只看 `progress.txt`」是同一类坑。）
- 二进制要在**发布目录当 cwd** 跑、输入给全路径；中间产物落在**输入所在目录**→ 每次实验用独立工作目录隔离，否则后续实验会读到/覆盖上一次的中间产物。
- 抽面用 Blender `DECIMATE`（ratio = 目标三角数 / 当前三角数）；**体素 Remesh 的 `voxel_size` 必须先扫档标定**——同一数值在不同尺度件上差量级，先跑 2~3 档看点面关系再定值。
- 预清理只需做到“让引擎能跑”：焊接无重复点时不会改变顶点数（属正常）；`bmesh.ops.holes_fill` 只补小孔（大环要编辑模式 `fill_holes(sides=0)`）。
