# “破面”= 绕向不一致 + 自交穿插：审计、归属、清理

适用：QR 重拓扑出的低模出现尖角/台阶/发黑暗面，用户称“破面”，但边界边/非流形边看起来正常。

## 1. 先定性，别猜

| 指标 | 脚本 | 判读 |
|---|---|---|
| 边界边（孔洞） | `_audit_defects.py` | 0 → 不是洞 |
| 非流形边（≥3面）/退化面 | `_audit_defects.py` | 0 → 不是拓扑破损 |
| **绕向不一致边** | `_audit_defects2.py` | >0 → 渲染发黑，像黑洞 |
| **自交三角面对** | `_audit_defects2.py` | >0 → 尖角/台阶/薄片重叠 |

前两项 0 而后两项 >0 ⇒ 缺陷是**绕向 + 自交**，源头是重拓扑/程序化几何，不是扫描破损。

## 2. 判据三条铁律（踩过坑）

1. **`BVHTree.overlap(bvh)` 是精确三角-三角相交，不是 AABB 粗筛**：161k 面网格只报几十对；
   若按 AABB 粗筛会把相邻面全报进来（几十万对）。
2. **共享顶点/共享边的相交对同样是缺陷**，不能加“排除相邻面”过滤 —— 折角恰恰发生在共享顶点处。
   加了过滤 ⇒ 自检报 0、独立审计仍报十几对 = **判据自盲**（“我测 0、用户永远看得见”）。
3. **修复判据必须与验证脚本同口径**，包括三角化方式：模块用 `me.loop_triangles`、
   审计用 `[v0,vk,vk+1]` 扇形 ⇒ 同一网格 3 对 vs 14 对。统一用扇形（审计口径）。

## 3. 归属：拿“逐版本同位置计数”定位到环节

固定一个世界坐标盒（缺陷质心 ±5cm），对**每个中间产物**各跑一次局部自交计数，看哪一步从 0 变正：

```
高模(上游输出) → QR原始 → QR+程序化几何(眼窝碗等) → 最终
```

真实案例：大腿衣摆 `高模=0 → QR=34 → 建碗后=39`（QR 产生）；
右眼窝外眦 `高模=8 → QR原始=0 → 建碗后=1`（建碗产生；高模那 8 对已被 QR 抹平）。
⇒ **哪个环节从 0 变正，就在哪个环节清**。

## 4. 清理算子：顶点级微焊接（首选）

“破面”处的自交多是**两层近共面微折**（衣摆/袖口折边、衣服壳与身体壳在交界处的重拓扑过渡），
不是深穿插。

- **微焊接**：`bmesh.ops.remove_doubles(verts=<缺陷簇顶点>, dist=d)`，`d` 从 0.8mm 逐档到 5mm，
  取**第一个清零的最小档**。实测 34 对 → 0 对、只少 ~30 顶点（0.02%），衣摆形状肉眼无变化。
- **删同顶点集重复面**：焊接会造重复面 ⇒ 非流形边的主因，焊接后必删。
- **绕向不一致**：贪心翻转相关面直到 0（本例焊接后 3 条 → 0）。
- **限幅平滑只当兜底**：`smooth_vert(factor=0.3)` + 每顶点位移硬上限 0.3mm。
  不加限幅会位移到 2mm ⇒ 可见凹陷；且对微折不收敛（实测 34→25 就停）。
- **不要用**整体 `recalc_face_normals`（按连通岛重定向会把腿等区域翻掉）。

## 5. 守门约束（防“修一个坏一个”）

每次尝试后必须同时满足，否则**回退该档**：

1. 本簇自交清零；
2. 非流形边/退化面**不变多**；
3. **不在别处新生缺陷簇**（>25mm 外出现新簇 = 我们造的）。

全档失败 → 限幅平滑 → 仍失败就**如实报告残留**，不许假装通过。

## 6. 脚本层三个必踩坑

1. `blender -b <blend> --python x.py -- args`：**`<blend>` 必须写在 `--python` 之前**。
   写错时 Blender 用**默认启动场景**跑，脚本正常结束、场景里只有一个 Cube ⇒ 审计得出
   “零缺陷”的**假通过**。审计脚本一律**自己 `bpy.ops.wm.open_mainfile(argv_blend)` 并打印实际打开路径**。
2. 焊接会**删顶点使索引移位**：每个缺陷簇开始前按盒**重新取顶点**；沿用旧索引 = 焊到错误顶点
   （症状：某簇反复报“11→11”不清零，而其他簇正常）。
3. `bmesh` 按索引取元素前 `ensure_lookup_table()`（否则 `bm.faces[i]` 报 outdated internal index table）。

## 7. 看图验证

**补一条：手动重跑某环节必须照抄控制台该 step 的完整脚本清单**（一个环节常 2-3 个脚本，且可能
分居两个目录——本例“眼球摆入”在 `01a眼窝眼球/scripts/` 而不在 02 的 scripts）。
`blender -b --python <缺失文件>` **只打一行、退出码仍是 0** ⇒ 下游静默建在缺对象的网格上
（症状：04 的“眼窝碗心清理”整段跳过，日志里根本没那一行）。
**验收**：不要只看 EXIT/“跑完了”，要同时核 ①对象清单（Eye002_L/R 在不在）②该环节里程碑日志行。

- 灰面 + 线框 + **自交三角标红**（沿法线外扩 0.6mm 免得共面看不见）→ 一眼分辨“薄双层”还是“深穿插”。
- **渲染时必须隐藏眼球等其它对象**：眼球是无光照的独立对象，在眼窝里会渲染成一团黑，
  很容易被误读成“破面”（踩过）。
- 焊接前后同角度渲染并排比，确认形状没被抹平。

## 8. 配套：贴图后处理的“可见性判据”

眼窝碗心清理这类贴图后处理，判据不能用“到眼球中心的距离 < 倍数×半径”：
bbox 角半径 ≈ √3× 真实球半径 ⇒ 会覆盖眼球周围**可见**的眼睑/睫毛根（用户判“倒退”）。
正确判据 = **从多视角打射线看是否被眼球挡住**（全部被挡才涂），球半径用顶点距离**中位数**。
实测改动像素 63,577 → 6,382（-90%），眼区与 raw 的渲染差异 3.95% → 0.17%。
