# 版本二：镜像对称测试 — 完整技术档案（上）

## 环境
- Blender 5.1，路径 `D:\Program Files\Blender Foundation\Blender 5.1\blender.exe`
- 测试路径：`test_mirror\`
- 测试模型：`test01\原始GLB\Scan_head\Male_Body_Morphs_Lv2.obj`
- 运行方式：`--background --factory-startup --python`
- Python lib：numpy, scipy（cKDTree, sparse.linalg.spsolve, linear_sum_assignment）

## 测试模型
- 128,306顶点，128,304面，带UV层和8192×8192 BMP纹理
- 左右顶点差13个（正侧63,127/负侧63,201），索引对称性0%
- 角色右侧（X<0）有大量雕刻形变，ZBrush Smart ReSym可10秒完美对称

## 核心原理
- bmesh中`vert.co`（顶点坐标）和`loop[uv]`（UV数据）是完全独立的数据层
- 修改`vert.co`不会触碰任何UV layer——架构上天然支持
- 所有测试版本UV差异均为0.000000000000000，已验证

## 方案1：空间匹配（v2, v6, v13）
- 方法：cKDTree全局双向最近邻（正→负且负→正）+ 法线X分量验证 + 邻居数量验证
- 结果：71.4%匹配率，29%未匹配→保持原位→撕裂
- 问题：空间匹配无法区分跨部位错误对应（手臂顶点匹配到腿）

## 方案2：拓扑BFS（v3, v12）
- 方法：从中轴顶点出发，沿边BFS扩散，每层用镜像空间最近邻匹配邻居
- 结果：种子仅144-205个，匹配率6-68%
- 问题：中轴种子不足，BFS扩散极慢，每步只匹配1个邻居

## 方案3：Blender内置symmetry_snap（v15, v18）
- 方法：`bpy.ops.mesh.symmetry_snap(direction, threshold, factor, use_center)`
- 结果：50,157对匹配/31,048失败，匹配率约39%
- 问题：Blender算法不如ZBrush鲁棒，多轮迭代无改善

## 方案4：删半镜像+UV恢复（v11）
- 方法：删除负侧→Mirror Modifier→cKDTree匹配正侧顶点恢复UV
- 结果：完美对称，无破面，UV恢复99.8%
- 问题：负侧UV是正侧UV的复制（非原始负侧UV）

## 方案5：删半镜像+负侧UV还原（v29）
- 方法：保存负侧原始UV→删除负侧→Mirror→负侧新顶点用abs(X)+Y+Z匹配原始负侧顶点→恢复负侧原始UV
- 结果：完美对称，无破面，65.9%负侧UV独立保留，34.1%降级正侧复制
- 问题：有形变区域（Y/Z偏移）负侧新顶点找不到原始负侧对应

## 方案6：拉普拉斯变形约束（v23, v24, v32）
- 方法：71%匹配顶点作硬约束（镜像位置），29%自由顶点解Laplacian最小二乘（scipy.sparse.linalg.spsolve）
- 结果：约束误差0，UV未变，求解0.1秒
- 问题：71%匹配中有错误对→拉普拉斯放大错误→局部拉伸
- 矩阵构建：用numpy批量构建COO→CSR，128K顶点稀疏矩阵nnz~200K

## 方案7：曲率+测地线+拉普拉斯（v25, v26）
- 方法：曲率计算（相邻面法线变化率，4.9秒）→提取曲率极大值点（左右各100个）→曲率相似度匹配超级种子（69对）→Dijkstra测地线距离（30个种子，17.2秒）→测地线+空间联合BFS→拉普拉斯变形
- 结果：72.7%，34秒，比纯空间匹配仅提升1.3%
- 问题：测地线距离在身体不同部位间可能产生跨区域错误路径

## 方案8：匈牙利指派（v27, v28）
- 方法：kNN限定候选数（每个正侧顶点10个候选）→numpy广播构建代价矩阵（空间距离+法线+邻居数）→按Y坐标分10块→每块用scipy.optimize.linear_sum_assignment
- 结果：62.2%，45秒，比双向匹配差
- 问题：分块破坏全局性，全量匈牙利63K×63K矩阵内存不够（32GB）

## 方案9：纯拓扑BFS局部邻居（v30, v31）
- 方法：从中轴出发→已配对顶点(pv,nv)的邻居局部匹配（4-6个候选）→BFS扩散
- 结果：74.4%，0.1秒（纯拓扑），1.5秒（加空间引导）
- 问题：仍有25.6%未匹配，推断阶段产生破面

## 关键技术发现

1. **bmesh只改vert.co完全不动UV**：所有版本UV差异均为0.000000000000000。vert.co和UV layer是独立数据层，架构上天然支持。

2. **拓扑严格对称的模型可100%完美镜像**：用Blender UV球体（482顶点，拓扑对称）测试，匹配率100%，对称差异0.00000000，UV未变。

3. **拓扑不对称模型的匹配率天花板74.4%**：无论空间匹配、测地线、曲率特征点、匈牙利指派、还是纯拓扑BFS，匹配率都在62-74%之间。

4. **拉普拉斯变形约束可行**：scipy.sparse.linalg.spsolve求解128K顶点稀疏矩阵0.1秒，约束误差0。消除了"未匹配顶点保持原位导致撕裂"的问题。但74.4%中的错误匹配对会通过拉普拉斯放大到自由顶点。

5. **烘焙是纯空间操作与高模UV无关**：烘焙光线从低模法线方向发射命中高模表面采样颜色，与高模UV布局完全无关。高模UV显示错位不影响烘焙结果。

6. **正确流程顺序**：先对称化高模网格坐标（只改vert.co不动UV）→ wrap对称低模 → 低模UV展开 → 烘焙。高模和低模在烘焙时必须空间重合。

7. **ZBrush Smart ReSym原理**（Maxon官方文档确认）：只操作顶点坐标位置，不触碰UV坐标。Polypaint是逐顶点颜色自动跟随，但基于UV的纹理贴图在对称后显示错位——需要Polypaint转纹理的桥接工作流。

8. **Blender `symmetry_snap`不够鲁棒**：128K顶点模型仅39%匹配率，远低于ZBrush的100%。

## 为什么ZBrush能做到而Blender Python不能

1. **性能**：ZBrush C++可以10秒处理128K顶点，Python无法做全局密集匹配
2. **算法**：ZBrush可能使用多尺度图匹配（谱匹配/热核签名），不受局部形变影响
3. **容错**：ZBrush对拓扑不对称有专门处理机制
4. **全量匈牙利**：63K×63K矩阵在Python中内存不够（32GB），分块破坏全局性

## Blender 5.1 API要点

- `uv_layer.uv.foreach_get("vector", flat_float32_array)` — 批量读UV（必须用"vector"不能"x"/"y"）
- `uv_layer.uv.foreach_set("vector", flat_float32_array)` — 批量写UV
- `mesh.loops.foreach_get("vertex_index", int32_array)` — 批量读loop→顶点索引
- `mesh.vertices.foreach_get("co", float_array)` — 批量读顶点坐标
- `mesh.edges.foreach_get("vertices", int32_array)` — 批量读边顶点对
- `symmetry_snap`和`symmetrize`操作符在128K顶点时可能崩溃
- scipy需在Blender外安装（`pip install scipy`），Blender内置numpy但无scipy

## 最终结论

- 高模对称化建议在ZBrush中完成（Smart ReSym，10秒完美对称）
- Blender中只做低模（MetaHuman模板）对称——低模拓扑严格对称，bmesh镜像100%完美
- 如必须纯Blender方案，删半镜像+UV恢复（v29，65.9%独立UV）是唯一可行方案
- 需要ZBrush级别效果需要C++图匹配算法或libigl集成
