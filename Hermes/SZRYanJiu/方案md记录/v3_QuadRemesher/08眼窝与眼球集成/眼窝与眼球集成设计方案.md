# 眼窝制作与眼球集成设计方案

> 目标：在 v3 QR 管线中加入眼球。高模已自带浅眼窝（实测中心区比眼眶缘深约4mm），需加深为可容纳眼球的窝洞，并将 MetaHuman 眼球（eye_01.glb，双眼各802顶点/1536面，直径约29mm，自带1024贴图）摆入，最终支持眼球转动。

**关键结论：高模的眼睛是"浅凹几何 + 贴图画的虹膜"，不是平面。** 这意味着眼窝位置可以直接从贴图自动定位（已验证成功），不需要外部人脸重建模型。

## 二、3DDFA-V3 有没有用：结论是"当前不需要，留作后备"

3DDFA-V3（CVPR2024）的功能是：**单张照片 → BFM人脸网格（35,709顶点）+ 68/106/134关键点 + 8部件语义分割（含眼睛区域mask）**。

它解决的核心问题是"从照片重建带部件标注的人脸"。而我们的处境是：

1. **输入已经是3D网格，不是照片**——管线起点是Tripo高模，3DDFA-V3的主功能用不上；
2. **它真正对我们有价值的是"眼部区域定位"**——但这一点已经用更轻的方法解决了：高模贴图上有画好的眼睛，用"UV采样贴图亮度→暗像素聚类→质心"就能自动找到虹膜中心，本次已实测成功（双眼各500+暗像素顶点，质心稳定）；
3. **后备价值**：如果未来某个模型贴图上没有画眼睛（纯素模），自动定位会失败，此时 3DDFA-V3 是可靠的后备路线——渲染高模正脸图 → 3DDFA-V3 出2D眼部 landmarks/分割 → 射线反投影回网格得到眼区。这条后备路线写进方案，但不进当前管线。

另注意：3DDFA-V3 环境较重（PyTorch + nvdiffrast/cython渲染器 + 预训练权重下载），零预算下能不用就不用。

## 三、眼窝制作放在哪个环节：01高模修复之后、02 QR之前（高模上做）

管线现状：`01高模修复 → 02 QR拓扑 → 03自动UV → 04纹理烘焙 → 05骨骼绑定 → 06 GLB导出 → 07管线集成`

新增 **01.5 眼窝制作**，在高模上完成，理由：

1. **高模已有浅凹，顺势加深**——保留原有的眼睑/眼眶自然形态，比在低模上凭空造形更准；
2. **QR会自动把窝洞边缘重拓扑成干净的quad边界环**——省掉手工整理开口边缘拓扑的工作；
3. **04烘焙会把窝洞深度烘进法线贴图**——低模自动获得眼窝深度感；
4. **眼球是独立物体，全程不参与 QR/UV/烘焙**——它自带拓扑和贴图，只在05绑定、06导出时并入。

备选（如果QR处理洞口不理想）：眼窝改在02之后、QR输出的quad低模上做。quad上删面+压凹同样可行，只是失去了"QR免费整理边缘"的好处。先按主方案跑，用实测决定。

## 四、眼窝怎么做：压凹 + 开孔（掏空）

只压凹不开孔是行不通的——眼球会被皮肤完全挡住，转动无从谈起。必须是：

1. **定开口**：以虹膜中心为圆心，在眼轴垂直平面上取一个椭圆形开口，建议 **宽约24mm × 高约12mm**（略小于眼球直径29mm，让"眼睑边缘"压住眼球，视觉上眼球卡在窝里而不是掉出来）；
2. **删面成洞**：删除开口内的面片，形成边界环；
3. **压凹成窝**：开口周围半径约15mm范围内的顶点，沿眼轴向内推，平滑衰减，最深处约 **10mm**（从原始表面算），形成一个碗状窝；碗底给眼球留空间；
4. **清理**：边界环 merge by distance、法线重算、检查除两个眼洞外其余流形完好。

关于原来贴图上画的眼睛：压凹+开孔后，那块贴图区域被眼球遮挡，画上去的眼睛自然废弃，不影响观感。窝内壁贴图可以不管（被眼球挡住看不见）。

## 五、四个关键确认（实测结论）

**1. 开孔必要性：必须开孔，但按眼裂尺寸走。**
不开孔眼球被皮肤完全挡住，无法看见/转动。开孔不是掏大洞，而是按眼裂（睁眼可见范围）来开——实测眼裂可见宽约31.5mm，故开孔建议 **宽26-28mm × 高11-13mm** 椭圆，比眼裂略小，让眼睑边缘压住眼球，视觉上是"眼球被眼皮包着嵌在窝里"。尺寸做成可调参数。

**2. 拓扑对眼球的影响：眼球本体零影响，孔洞边缘会被QR重拓扑。**
眼球是独立物体，全程不进QR/UV/烘焙，保持原802顶点拓扑。QR只作用于皮肤高模，并把孔洞边界环重拓扑成干净quad——这正是"眼窝放QR之前"的目的。唯一复检项：QR后核对洞口尺寸有无被改大/改小，偏差>1-2mm时微调眼球缩进/探出量。

**3. 眼球大小：先不缩，渲染定夺，备0.85-0.9。**
29mm眼球 vs 眼裂31.5mm（余量仅2.5mm）、头宽160mm、瞳距47mm（偏小，正常成人约62-64mm）。Tripo模型五官偏小，29mm眼球可能略大。处置：先按1.0摆入渲染正面+截面，若"眼皮压不住/过凸/眼白过多"则均匀缩到0.85-0.9（约24.6-26mm）。**必须三轴等比缩，禁止压扁。**

**4. 瞳孔朝前平视：用全局前向，绝不用眼窝法线。**
实测发现陷阱：眼窝法线是外撇的（左眼x=-0.53、右眼x=+0.57），若沿眼窝法线对齐瞳孔会导致双眼外撇成斜视。正确做法：
- 位置：虹膜中心沿**全局前向(-Y)内缩约10mm**作球心（不用眼窝法线）；
- 朝向：旋转眼球使局部**+Z(瞳孔)对准全局-Y(正前方)**，即四元数 +Z→-Y；
- 结果：两眼视线平行朝前=平视；摆好后渲染正面特写验收，细微偏差绕眼轴微调。

## 六、眼球怎么摆入

1. **导入** eye_01.glb，拆成左右两个 mesh（文件里就是两个独立mesh：.002 / .003）；
2. **定位**：眼球中心 = 虹膜中心沿**全局前向(-Y)内缩约10mm**（不用眼窝法线，避免外撇，见确认4）。此时角膜顶点在原始表面外约 +4.5mm（14.5mm半径 - 10mm），正好从开口探出，被开口边缘"卡住"——这是数字人眼球的标准姿态；
3. **验证**：过眼球中心做横截面渲染，确认：球体被开口边缘遮挡下半部、角膜探出量3-5mm、球体不穿出眼睑皮肤外侧；
4. **朝向**：eye_01.glb 局部坐标原点在球心（bounds对称，实测确认），瞳孔方向为局部+Z（实测确认）。摆入时旋转使 +Z→全局-Y（正前方），实现平视。

## 七、绑定与导出（眼球转动）

1. **05绑定**：在双眼球心各建一根眼骨 `eye_L` / `eye_R`（Mixamo骨架没有眼骨，手动加，parent到head骨）。每个眼球mesh整体100%权重绑到各自眼骨；
2. **转动**：眼骨旋转即带动眼球。GLB内可以用动画轨道或运行时驱动（three.js等平台直接操作眼骨四元数）；
3. **06导出**：GLB包含 皮肤mesh + 眼球L + 眼球R + 骨架，眼球保留自己的材质和1024贴图。
