# 06 GLB导出 — 方案与实现（2026-09-17 已实现并验证）

**状态**: ✅ 已实现（演示版_终端控制端/06GLB导出）+ 交付版脚本已同步（v3_QuadRemesher_交付/06GLB导出/scripts/）
**上游**: 05骨骼绑定 → `04_动作测试.blend`（含 走/跑/跳 三个动作）
**产物**: `06GLB导出/输出/06_角色_走跑跳.glb`（约 36MB，glTF 2.0 单文件，4K贴图内嵌）

## 一、做什么

把 05 绑定+重定向后的角色（网格+骨架+4K贴图+三动作）导出为引擎可直接导入的 **GLB 单文件**：
- 贴图内嵌（Diffuse 4K + Normal 4K + 眼贴图）
- 比例正确：1 Blender 单位 = 1 米（模型静止高 ≈1.82m）
- 三个动画全部导出：Standard Walk 1.200s / Running 0.667s / Jump 1.033s（30fps，帧数按 Mixamo 参考原样：36/20/31）

## 二、导出参数（脚本 06_output_glb.py）

| 项 | 值 | 理由 |
|---|---|---|
| 导出选择 | 骨架 + 3个"产品网格"（带 ARMATURE 修改器的蒙皮网格） | 排除插件/历史遗留的显示形状 |
| 格式 | GLB（单文件） | 贴图内嵌、免散件 |
| 动画模式 | ACTIONS（每个 action 一条 glTF 动画） | 三动作各一条 |
| 帧范围 | 各自 action 自带范围 | 帧数按参考原样 |
| 轴向 | +Y up（glTF 标准） | 引擎惯例 |
| 蒙皮 | 55 关节全导出 | 与绑定一致 |
| 贴图 | AUTO（PNG 内嵌） | 4K 无损 |

脚本对导出算子做"属性过滤"（`get_rna_type().properties`），Blender 版本演进不会因参数改名而崩。

## 三、三段自查（全过才输出 06_DONE，控制台以此把关）

1. **源于文件**：fps=30（与 Mixamo 参考一致）/ 三动作帧范围 1-36、1-20、1-31 / 骨架 scale=1 / 模型高度 ≈1.82m
2. **解析 GLB 头部**（纯 Python 读 struct+JSON，不经 Blender）：动画=3（时长 1.200/0.667/1.033s）/ 网格=3 / 皮肤=1 / 关节=55 / 节点=59 / 图像=6
3. **重导入复核**（工厂干净场景、同 fps 重导入）：静止高差 **0.00mm**（米制比例正确）/ 55骨 / 4K贴图在场 / **逐帧变形包围盒签名**（源 vs 重导入，7帧）最大差 **0.07mm** = 动画正确

## 四、踩过的坑

- **glTF 导入器会给骨骼造"显示形状"**（Icosphere，42顶点±1m，非资产内容）→ 验证统计若用 `bpy.data.objects` 全量，会误判成 4 网格 / 高度 2556mm ✗。**正确做法：只统计"场景内且带 ARMATURE 修改器"的产品网格**（源、导出、重导入三处同口径）。
- 动画正确性对比必须用"变形包围盒签名"——导出会重排/合并顶点，逐顶点对比不可比。
- Blender 后台脚本失败也会 exit 0 → 以打印的完成标记（06_DONE）为准。
