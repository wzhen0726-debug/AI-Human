## 三、ARP版时间线（主要战场）

### 用户实测的起点问题（08-27）
用户自己去试ARP插件AI绑定：绑定后是控制器、导出骨骼很乱、跟Mixamo完全不一样。→ 触发全面调研。

### 调研结论（读了auto_rig_smart.py / auto_rig_ge.py源码）
1. **ARP官方流程**：`get_selected_objects` → `guess_markers`(AI三视角截图推理放标记) → 用户微调 → `go_detect`(构建) → 面板导出。
2. **AI模型文件在机器上齐全**（`C:\Users\Liyunzhong\Documents\AutoRigPro\AI\inference\`，含手指模型），AI打点实测精度很好（手腕差2cm、颈根0mm）。
3. **"绑定后是控制器"是ARP设计**：官方导出面板（auto_rig_ge.py）有HUMANOID模式烘焙去控制器，**且原生支持Godot引擎**（arp_engine_type有GODOT、rename_for_godot）。用户直接Blender导出才导致"骨骼很乱"。
4. **旧结论作废**：方案md Q1"ARP无解"是0.976m模型的事，现在1.80m正配模板。

### 做错再修复的（ARP侧）
- **自创标记命名对不上**：做过`01_骨盆中心`命名的自造模板，ARP只认固定名`root_loc/chin_loc/neck_loc/shoulder_loc/hand_loc/foot_loc`(+_sym)。
- **点样式做错**：用户两次指出"这个球怎么还是这么奇怪"——手动版是**EMPTY空对象(SPHHERE, size 0.012, show_in_front)**，我反复做成mesh材质球。教训：抄之前先dump验收过的模板真实规格。
- **AI截图三个坑**：①模型改名body_temp与ARP内部副本撞名→截图拿到黑色衣物模型→AI认不出人体（要求纯灰Emission 0.8素模）；②截图必须256分辨率（官方ratio=dim/256）；③截图补丁必须把larger_dim/midx/midz写回self，否则标记全(0,0,0)+臂角零向量崩溃。
- **go_detect对T-pose模型产出错位骨架（核心根因）**：
  - 决定性实验：完整官方流程与分步流程结果完全相同 → 不是流程编排问题。
  - 数据：参考骨arm_ref.l=(0.229,0.068,1.435)精确落在标记点（66根参考骨全对，含30根手指），但变形骨hand.l z=1.148（低29cm）——go_detect内部用A-pose模板，对T-pose模型不修正姿势，预设只有DEFAULT/UE4/UE5。
  - **抢救成功**：弃变形骨，从参考骨架提取最终骨架（extract_refs.py，55骨映射Mixamo命名）。
- **align_roll脚本多做错事**：第一版把`b.tail`改成Mixamo参考模型方向×长度（参考模型比例不同）→ 肩/肘/膝/踝全断开、手指乱飞（用户08-28截图抓到）。修复：**只align_roll(Z轴)，head/tail一律不动**（链条保持用户标记点）。
- **手指结构映射错**：把ARP的`index1_base`(掌骨段:腕→指根)并进Finger1 → 侵入掌部，手指只剩2节、手掌2节（用户08-28抓2）。修复：**Hand尾伸到中指指根（掌骨区归Hand骨），Finger1只覆盖近节指骨（指根→第2关节）**；拇指无base本来就对。
- **39/41根关节骨设use_connect**：父尾=子头的链（肩肘腕、膝踝脚）连贯显示；残留13处间隙全是解剖学正常（锁骨起于脊柱侧7cm、指根扇出、胯臼外展18cm——Mixamo官方骨架也如此）。

**本轮新踩的坑（详见 `ARP新版测试_20260831/测试记录.md`）**：
1. **读标记点用 `o.location` 是大坑**——`_sym` 点靠 COPY_LOCATION 约束镜像，`o.location` 是约束前的假值，必须 `evaluated_get(dg).matrix_world.translation`。曾因此误判"点不对称"做了多余的对称化。

3. **Hips 垂直起伏不能删**：行走动画删 Hips location 会双脚腾空+滑步。Hips 局部 **y 轴=世界垂直**（不是 z），逐帧读参考 Hips 世界 z 按腿长比缩放写回。
4. **root 点应打在骨盆上缘**（高于胯点 thigh 6-7cm），不是大腿根同高。点位指南已更新。
5. **用户打点即权威**：点打在哪骨骼就在哪，不做自动中心化/解剖修正（用户可调点）。
6. **Windows `2>nul` 会创建真实文件 nul**（保留名难删），后台脚本错误要落盘到具体文件。

**硬编码参数化**（跨体型）：黏连距离/焊接距离/排除区/baking cage 等全部改为按身高或 bbox 比例计算，见 `硬编码参数化审计_20260902.md`。
