## 一、归因（分阶段快照 diff，禁止猜）

利用 QA 轮次自动备份（`_备份/<时间>_04diffuse_处理前|v2前/`）拿到**同一轮(margin=24)的四个阶段**：
raw(纯烘焙) → v1(溢出处理后) → v2a/v2b(网格引导离群清理两遍) → final。

| 阶段 | 改动像素 | 色差中位 | 结论 |
|---|---|---|---|
| raw→v1 | 49,642 (0.296%) | 88 | **v1 = 主要改动源** ✗ |
| v1→v2a | 11,208 (0.067%) | 76 | v2 贡献次要 ✓ |
| v2a→final | 10,017 (0.060%) | 66 | 同上 ✓ |

平涂斑块检测（内部std<1.2 且 邻域梯度>25 且被修改过）：**33个连通块，5个>300px，最大748px** ✗ —— 全部落在修复改动区内 ✓ = **斑块为修复所造** ✓。

**v1 旧算法错在哪**：把候选像素**整片填成同一个"全局中位皮肤色"** ✗。皮肤明暗沿衣物边界是连续变化的，单一颜色必然与环境不符 → 可见平涂斑块（用户看到的"斑块"）。

## 二、修复 v3（`texture_fix.py`）

```
③ 逐像素填充: 每个渗出像素取【最近的未修改皮肤像素的真实颜色】(EDT return_indices)
   → 保留边界方向的明暗渐变; 距离>3×reach 的孤点跳过
③b 掩膜内扩散: NN初值 → 4邻域 Jacobi 40次迭代(边界像素固定不动)
   → 消除"最近邻拼贴"面片化, 收敛为边界连续的平滑填充
② 边缘保护环: 候选加 (dist_big > 2px) —— 衣物/毛发自己的抗锯齿边原样保留
   (旧版把 AA 边也替换 → 渲染 A/B 里边缘被啃出米色锯齿缺口, 4K特写下可见)
```

## 三、验证（数值硬判据，不靠肉眼+一次性读图）

1. **平涂斑块**：3,128px → **9px**；>300px 块 5→0；最大 748→4px ✓
2. **渲染级 A/B**（同机位，唯一变量=贴图；raw 版用同一轮 `_qa_r2` 快照）：
   总差异 0.131%→0.085%（upper）/ 1.11%→0.18%（肩特写）/ 1.40%→0.39%（胸特写）——修复影响面小且集中 ✓
3. **边缘完整性**：衣物暗掩膜(lum<48) raw vs final：684,276px 中**仅 1px 差**（chest 0px）✓ = 边缘零侵蚀 ✓
4. 裁图前后对比：渗出脏带消失、皮肤纹理保留、过渡平滑 ✓

## 四、教训

- **"整片填同色"类的修复必然制造平涂斑块** —— 凡替换像素，颜色必须**逐像素取自就近真实数据**（最近色/NN + 扩散），不允许全局统计色一刀切。
- **替换类修复必须做"保护环"**：贴着边界(≤2px)的像素属于边界自身（AA边），动了就是啃边缘。
- **成对目视(智能读图)会前后矛盾** → 高危判断一律用**独立数值判据**：分阶段 diff / 平涂度量 / 掩膜完整性，三者互相独立（本次即靠它们定案）。
- 修复与烘焙的分工：烘焙的 margin 渗出是真的（该修），但**修复的方法选择**才是斑块的来源 —— 归因必须分阶段，不可整体甩锅。
