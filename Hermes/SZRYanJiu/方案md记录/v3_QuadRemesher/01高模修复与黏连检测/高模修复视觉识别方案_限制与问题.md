# 高模修复视觉识别方案 — 限制与无法解决的问题

**日期**: 2026-07-23  
**项目**: v3_QuadRemesher 高模修复管线  
**范围**: 视觉识别引导的自动化修复（Vision-guided repair）  
**关联文档**: `高模修复操作手册_v10.docx`（算法实现细节）、`碎片溯源诊断.md`（根因分析方法）

---

## 一、方案概述

本方案尝试用 **视觉识别（Vision AI）+ 数学反投影** 替代真人视口操作，实现高模的自动化雕刻清理：

```
渲染截图 → Vision 标记缺陷像素坐标 → 相机参数反投影 → BVH raycast 定位 3D 点 → 数学模拟雕刻（Laplacian 平滑/填充）→ 渲染复查 → 迭代
```

**适用场景**: 睫毛残留清理、表面噪点平滑、小范围几何修复。

---

## 二、核心限制

### 2.1 Blender Background 模式无视口上下文

**问题**: `bpy.ops.sculpt.brush_stroke` 需要 3D 视口上下文（area/region），background 模式没有窗口系统。

**验证结果**:
- `bpy.context.area = None`（无激活区域）
- `bpy.context.screen.areas` 包含 VIEW_3D，但 sculpt 工具系统不完整

**结论**: 无法调用 Blender 自带雕刻笔刷。

---

### 2.2 自带笔刷 API 无效（Tool 系统限制）

**问题**: 即使通过 `temp_override` 绕过上下文限制，`brush_stroke` 调用成功但对网格**无实际效果**。

**根因**:
- Background 模式 `bpy.data.brushes` 仅含 1 个 Draw brush
- `tool_settings.sculpt.brush` 是 **read-only**，无法切换为 Smooth 等其他笔刷
- 从资产库加载 93 个 brush 后，仍无法设置为激活 brush

**验证数据**:
| 测试项 | 结果 |
|--------|------|
| brush_stroke 调用 | ✅ 无异常 |
| 顶点移动数 | ❌ 0/482（无效果） |
| sculpt.brush 可写性 | ❌ read-only |
| 资产库加载 | ✅ 93 brushes 加载成功 |
| 切换激活 brush | ❌ 无法设置 |

**结论**: 自带笔刷路径在 background 模式不可行，必须数学模拟。

---

### 2.3 数学模拟的功能局限

**问题**: 半径衰减 Laplacian 只能实现 **Smooth brush** 效果，无法模拟其他笔刷类型。

| 笔刷类型 | 数学模拟可行性 | 说明 |
|----------|---------------|------|
| Smooth | ✅ 已实现 | 半径衰减 Laplacian |
| Scrape/Flatten | ⚠️ 部分可行 | 需平面拟合+投影，复杂 |
| Clay/Buildup | ❌ 不可行 | 需体积增加，非纯位移 |
| Grab | ❌ 不可行 | 需拓扑变形，非局部平滑 |
| Pinch | ❌ 不可行 | 需边缘收缩算法 |
| Inflate | ⚠️ 部分可行 | 法线方向位移，易自交 |

**结论**: 仅适用于平滑类修复，复杂造型需人工。

---

## 三、无法解决的问题

### 3.1 Vision 分辨率极限（<0.2mm 不可区分）

**问题**: 1200×900 像素渲染图下，Vision 无法区分：
- 真实几何颗粒（>0.2mm）
- 正常解剖纹理（<0.2mm 微起伏）
- 渲染伪影（cavity 阴影）

**实例**: 下眼睑"黑色小点"经关闭 cavity 渲染验证为伪影，但 Vision 持续报告为缺陷。

**影响**: 过度清理风险——把正常解剖结构（卧蚕褶皱）误当缺陷平滑。

**缓解**: 网格层面检测（peaks=0）作为最终判据，Vision 仅作初始定位。

---

### 3.2 透视投影的身份误认

**问题**: T-pose 侧面视角下，左手在画面右侧，右手在画面左侧，Vision 按屏幕位置描述会左右混淆。

**实例**: 碎片实际在左手（X≈-0.47），Vision 描述为"右手异物"。

**影响**: 反投影坐标错误，清理错部位。

**缓解**: 反投影后必须验证 3D 坐标（|X| 符号），不依赖屏幕左右。

---

### 3.3 反投影精度依赖相机参数

**问题**: 像素坐标 → 3D 点的转换依赖准确的相机位置、FOV、传感器尺寸。

**误差来源**:
- 相机距离估计偏差（±5mm → 3D 偏差 ±1mm）
- FOV 计算近似（sensor=36mm 默认）
- 模型非平面（raycast 命中曲面而非意图点）

**影响**: 定位偏差导致平滑区域偏移，可能误伤正常几何。

**缓解**: 多次 raycast 取最近命中 + 候选区扩大（5mm→8mm）。

---

### 3.4 迭代收敛困难

**问题**: 第一轮平滑后，第二轮检测不到 peaks（peaks=0），但 Vision 仍报告残留。

**根因**: 
- 真实颗粒已消除（<0.2mm 低于检测阈值）
- Vision 报告的"残留"是渲染伪影或正常纹理

**影响**: 无法确定何时停止迭代，存在过度平滑风险。

**当前策略**: 网格检测 peaks=0 即停止，Vision 仅作参考。

---

### 3.5 复杂几何结构无法处理

**问题**: 以下情况数学模拟无法解决：

| 问题类型 | 原因 | 示例 |
|----------|------|------|
| 薄壁碎片 | 需删除+补洞，非平滑 | 手部刀片状碎片 |
| 穿插/自交 | 需拓扑分离 | 手指与布料穿插 |
| 翻转法线 | 需法线重算 | 局部黑面 |
| 开放边界 | 需补洞 | 破洞 |
| 多层皮肤 | 需分离+选择 | 衣物与身体贴合 |

**结论**: 视觉识别仅适用于表面平滑，复杂拓扑问题需其他算法。

---

## 四、已解决的问题（经验总结）

| 问题 | 解决方案 | 验证 |
|------|----------|------|
| 碎片根因定位 | 逐阶段 blade counting | fix_adhesion 确认 |
| 手部碎片消除 | 排除区+clamp+检测法线 | blades 160→0 |
| 睫毛残留清理 | 4 轮迭代平滑 | peaks 199→0 |
| cavity 伪影识别 | 关闭 cavity 渲染对比 | 黑点消失 |
| 反投影定位 | BVH raycast + 相机参数 | 8/9 命中 |

## 五、结论与建议

### 可行场景 ✅

- 表面噪点平滑（睫毛残留、AI 生成颗粒）
- 小范围几何修复（<5mm 区域）
- 配合网格检测的迭代清理

### 不可行场景 ❌

- 复杂拓扑修复（碎片、穿插、翻转）
- 大面积造型调整（Clay、Grab 等笔刷效果）
- 需要艺术判断的精细雕刻（面部特征优化）

### 推荐工作流

```
1. 视觉识别定位缺陷区域（初始引导）
2. 网格检测确认问题类型（尖峰/凹陷/碎片）
3. 数学模拟平滑（仅限表面问题）
4. 复杂问题标记 → 人工处理或专用算法
5. 渲染复查（关闭 cavity 排除伪影）
```

## 六、后续研究方向

1. **更高分辨率 Vision**: 4K 渲染 + 更高精度 Vision 模型，突破 0.2mm 极限
2. **多视角融合**: 6 视角渲染 + 3D 重建，消除单视角歧义
3. **笔刷 API 破解**: 研究 tool 系统 hack 或自定义笔刷引擎
4. **AI 直接生成修复指令**: 跳过反投影，Vision 直接输出顶点操作序列
