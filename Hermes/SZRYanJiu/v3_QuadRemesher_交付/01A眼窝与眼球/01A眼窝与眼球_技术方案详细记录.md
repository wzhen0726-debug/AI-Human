## 1. 项目背景与定位

**管线位置**：01高模修复之后 → 02 QuadRemesher 之前。

**输入**：高模修复后的三角网格（~193万面，Metahuman 标准身体模型 + Tripo AI 生成头部）。

**输出**：
- `01_1_eye_socket.blend`：含双眼窝开孔 + 封碗的模型
- `01_2_eyeball_placed.blend`：含眼窝 + 摆入眼球的模型

**核心约束**：
- 眼窝在**高模三角网格**上操作（不是 quad 拓扑）
- 02 QR 会把洞口边缘重拓扑成干净 quad 边界环，因此眼窝阶段的拓扑质量要求不高，但必须：
  1. 无开放边（不漏面）
  2. 无非流形边（不破坏流形性）
  3. 法线一致（不朝内）
  4. 过渡平滑（无锐利折痕）
- 眼球是独立物体，不进入 QR/UV/烘焙，只需要摆对位置

## 3. 详细步骤

### 3.1 眼部定位（3DDFA-V3 语义反投影）

**文件**：`backproject_3ddfa.py`

**原理**：
1. 将高模渲染成正脸图（正交相机，Workbench 引擎）
2. 3DDFA-V3 检测 68 个面部关键点，返回 2D 像素坐标
3. 每眼 6 个关键点（外眦·上睑×2·内眦·下睑×2）和 1 个虹膜中心
4. 射线反投影：从相机位置过 2D 关键点发射射线，求与网格的交点（bvh.ray_cast）
5. 返回 3D 坐标（角膜表面交点）

**关键数据**：
- 眼中心 L：(-0.0358, -0.1058, 1.6711)
- 眼中心 R：(0.0326, -0.1061, 1.6707)
- 眼间距：68.4mm
- 眼睑轮廓 6 点：26.8×9.7mm 杏仁形，宽高比 2.75

**注意**：3DDFA 关键点定位在**三渲二图**上，贴图已画好的眼睛区域会被 3DDFA 正确识别。

---

### 3.2 眼睑轮廓加载与加密

**函数**：`socket_ops.load_eyelid_contour(side, n_points=24, margin_x_mm=2.0, margin_z_mm=1.0, outer_extra_mm=4.0, inner_extra_mm=1.5)`

**参数演变**：
- v18（原始）：6 点折线，0.5mm 均匀 margin
- v19：margin 0.5→2.0mm（用户说红色太小，要蓝色大小）
- v22：外眼角+4mm，内眼角+1.5mm（用户标注图中蓝/红宽度比 1.296）
- v23：方向性 margin（x 2mm, z 1mm），防止 z 方向触及眉毛

**步骤**：
1. 从 JSON 读取 6 点 3D 坐标
2. 投影到 XZ 平面（忽略 Y 差异）
3. 弧长等间距插值到 24 点（样条加密，消除折线棱角）
4. 方向性扩展：`x' = x + (dx/dist) * margin_x, z' = z + (dz/dist) * margin_z`
5. 外眼角额外扩展：找到 |x| 最大的点，沿 X 方向推 +4mm（falloff 5 点窗口平滑）
6. 内眼角额外扩展：找到 |x| 最小的点，沿 X 方向推 +1.5mm

**结果**：
- 轮廓宽：L 35.5mm / R 35.3mm
- 轮廓高：L 11.4mm / R 11.1mm
- z 上沿：L 1.6774 / R 1.6775（< 1.68，不碰眉毛）

---

### 3.3 开孔（make_eye_socket）

**参数**：`y_cut = cy + 0.020`（只删 y 比眼中心更靠前的面）

**步骤**：
1. **BFS 洪泛删面**（2026-08-07 重写）
   - 建面邻接表（f2f）
   - 找离眼中心距离最近的面作种子（3D 距离，不是 xz 投影）
   - 从种子 BFS 生长，只收录面心在轮廓多边形内的邻面
   - y 限制：`fc.y < cy + 20mm`（防止误删后脑勺）
   - 一次性删除，保证删区连通成单环
2. **局部焊接**：`remove_doubles(threshold=0.0001)`
3. **Sliver 溶解**：面积 < 0.5mm² 且 xz 距离 < 15mm 且 z < 1.678 且严格内部面（所有边恰 2 面），`dissolve_faces`
4. **ngon 三角化**：溶解产生的多边面，`bmesh.ops.triangulate`

**删面结果**：
- 原始轮廓 0.5mm margin：L 455 / R 432
- 方向性 margin 2.0mm：L 608 / R 585
- 外眼角+4mm 内眼角+1.5mm：L 660 / R 661

---

### 3.4 封碗（make_eye_cup）

**核心思想**：在眼窝开口后方生成一个凹陷的碗状曲面，防止眼球后方看到头内结构。

**步骤**：

#### 3.4.1 删眼区孤岛
- 从远离眼区的种子顶点 BFS 标记主体连通分量
- 眼区内不连通的面 = 孤岛，删除

#### 3.4.2 找边界环（拓扑行走）
- 找眼区内的开放边（1 面相邻）
- 建邻接表，拓扑行走找所有闭合环
- 取最长环 = ring0（碗口沿）
- 关键：**拓扑行走顺序**，不是角度排序（角度排序破坏拓扑序，导致锯齿破面）

#### 3.4.3 ring0 松弛
- 3 次 Laplace 松弛：`v' = v*0.5 + (a+b)*0.25`
- 目的：平滑洞口边缘的锯齿（zigzag 收缩后 quad 重叠 → 非流形边）

#### 3.4.4 球面碗生成（NR=24 环）

```python
NR = 24
for j in range(1, NR):
    t = j / NR
    s = smoothstep(t) = t²(3-2t)  # 口沿坡度=0，碗底平缓收拢
    scale = 1.0 - s                # 半径收缩
    depth_frac = s                 # 深度
    x = center.x + (base.x - center.x) * scale
    z = center.z + (base.z - center.z) * scale
    y = base.y + (rim_y + max_depth - base.y) * depth_frac
```

- 球面碗共 24 环（从 ring0 到碗底平滑收缩）
- smoothstep 剖面：口沿处导数=0（与皮肤切向连续），碗底平缓收拢
- 碗深：`CUP_DEPTH = 0.015`（15mm）
- 极点使用**单个共享顶点** + 三角扇（每条边恰 2 面，构造上保证流形）

#### 3.4.5 碗面 Quad 创建
- 相邻环之间创建 quad：(a, d, c, b)，其中 a=外环 i, d=内环 i, c=内环 i+1, b=外环 i+1
- 极点三角扇：`(last[i+1], last[i], pole)`（v27 反转绕序，让法线朝外）

#### 3.4.6 碗面 UV 分配
- 新顶点（碗面内部）的 UV = ring0 对应顶点的 UV（径向继承）
- 极点 UV = ring0 UV 的平均值
- 目的：碗面颜色跟随眼周肤色，不出现 UV=(0,0) 导致贴图角落色差

#### 3.4.7 Sliver 溶解 + ngon 三角化
- 溶解封碗后变内部的反向 sliver（法线朝 +Y 的极小面）
- 参数：面积 < 0.5mm², normal.y > 0.3, xz<15mm, z<1.678
- 溶解后三角化 ngon

#### 3.4.8 皮肤面细分（拐角羽化，v29）
- 找到 ring0 外侧相邻的皮肤三角面边（排除 ring0 本身的边）
- `bmesh.ops.subdivide_edges` 做 1 切细分
- 细分后三角化 ngon
- 目的：增加 ring0 处皮肤面数，改善皮肤面 vs 碗面的法线过渡

#### 3.4.9 法线校正
- 在 OBJECT 模式 → EDIT 模式后，检查碗区（xz<14mm）面法线
- 如果 `normal.y > 0.001`（朝头内），用 `reverse_faces` 反转绕序（持久生效）
- 判断标准仅用 `normal.y > 0`，不关心"朝碗轴"（因为凹陷碗壁的朝碗轴特性是正常的几何特征）

### 3.5 法线校正（全局 fix_socket_normals）

**位置**：`run_eye_socket.fix_socket_normals`

**作用**：翻转眼窝开口（眼睑轮廓多边形 + zone）内所有朝内面，统一朝 -Y（朝眼球）。

**判据**：
```python
if fc.y < 0 and f.normal.y > 0 and (point_in_polygon(fc.x, fc.z, poly) or in_zone(fc)):
    f.normal_flip()
```

- `fc.y < 0`：只翻前脸（防止后脑勺的面被误翻）
- `f.normal.y > 0`：朝内才翻
- `point_in_polygon`：眼睑轮廓多边形内
- `in_zone`：xz 22mm 半径且 y∈[-0.116, -0.080]（碗的深度带，补多边形未覆盖的碗面）

**历史问题**（v17 修复）：
- 之前缺 `fc.y < 0` 限制，后脑勺 391 面（在眼睑轮廓 XZ 投影内，但 Y>+0.05）被误翻 → 后脑勺"穿透"
- 修复后：后脑勺 0 面被误翻

## 5. 遇到的问题与解决方案

### 5.1 破面（2026-08-06 ~ 08-13）

**问题**：眼窝渲染图出现深色条纹，看起来像"破面/漏面"。

**根因 1 — 碗面 UV=(0,0)**（v26 修复）
- 新生成的碗面顶点没有 UV 坐标
- 默认 UV=(0,0) 采样贴图角落，出现色差
- 修复：碗面新顶点 UV 径向继承 ring0 对应顶点的 UV（眼周肤色）

**根因 2 — 极点三角扇法线朝内**（v27 修复）
- 极点三角扇创建时绕序导致法线朝 +Y（朝头内）
- 用 `reverse_faces` 反转绕序，持久生效
- 法线校正放在 OBJECT 模式后（mode_set 会重算法线，覆盖 normal_flip）

**根因 3 — 碗面法线朝碗轴（面朝向错误）**（v28→v29 修复）
- 最初用 "法线朝碗轴 = 朝内 = 错误" 的判据反转碗面法线
- 实际上凹陷碗壁的朝碗轴特性是正常的几何特征
- 修正：只翻 `normal.y > 0`（朝头内）的面

### 5.2 后脑勺穿透（2026-08-13）

**根因**：`fix_socket_normals` 的 `point_in_polygon` 只检查 XZ 投影，无 Y 限制。眼睑轮廓 XZ 投影穿过头部中心，后脑勺同 XZ 位置的面（法线朝 +Y，正常朝外）被误翻。

**修复**：加 `fc.y < 0` 限制（前脸/碗全在 Y<0，后脑勺 Y>+0.05）。

**验证**：后脑勺 391 面全部朝 +Y 正常，0 面朝 -Y。

### 5.3 眉毛区 UV 错乱（2026-08-13）

**根因**：两个环节触及眉毛区域（z=1.68~1.75）：
1. 均匀 margin 2mm 使轮廓高 13.3mm，z 上沿 1.684 触及眉毛
2. sliver 溶解 XZ 20mm 半径触及 z=1.691

**修复**：
1. 方向性 margin（x 2mm / z 1mm），高降到 11.4mm，z 上沿 1.677
2. sliver 溶解加 z 上限 < 1.678

**效果**：眉毛区被删面从 390 → 0。

### 5.4 外眼角不够大（2026-08-13）

**问题**：用户多次反馈外眼角（外眦）不够大，开口与贴图/模型不匹配。

**修复**（多重迭代）：
1. 均匀 margin 0.5→2.0mm（第一次）
2. 外眼角额外 +1mm（第二次不够）
3. 外眼角+4mm，内眼角+1.5mm（第三次，基于标注图像素定量）

**验证**：标注图蓝/红轮廓宽度比 = 1.296，外眼角延伸 60px（≈21%），内眼角 23px（≈8%）。

### 5.5 开口轮廓太粗糙（2026-08-13）

**问题**：6 点折线轮廓导致开口形状不够平滑，与贴图眼睑不匹配。

**修复**：弧长等间距样条插值加密到 24 点 + 方向性 margin。

### 5.6 过渡太锐利 + 面朝向反转（2026-08-13）

**问题**：碗口沿（ring0）处皮肤面和碗面法线夹角 >90°，导致视觉上"面朝向反转"和"锐利折痕"。

**尝试过的方案**：
1. **过渡环压凹**（v24-v25）：移动 ring0 外侧皮肤顶点朝 +Y 压凹，方向 bug 修复后测试，但用户不满意（"不是移动顶点，是增加面数"）
2. **bevel 羽化**（v29 两次尝试）：对 ring0 边做 bevel（segments=2, offset=1.5mm），但在三角网格上产生开放边（96/33）和非流形边（56），不可接受

## 7. 尝试过的失败方案

### 7.1 暗像素法检测虹膜中心（已暂停，存档）

**原理**：在贴图上找最暗像素区域（瞳孔）定位虹膜中心。

**问题**：贴图质量不稳定（某些模型的贴图没有清晰的瞳孔画法），导致眼中心定位不准。

**替代**：3DDFA-V3 语义定位（更稳定）。

### 7.2 对称椭圆开孔（已弃用）

**原理**：用 `(x/rx)² + (z/rz)² ≤ 1` 椭圆判断开孔。

**问题**：椭圆太圆（宽高比 1.44），不符合真实眼睑杏仁形（宽高比 2.75）。

**替代**：3DDFA 眼睑轮廓（杏仁形）。

### 7.3 压凹（ENABLE_PUSH_IN，已关闭）

**原理**：开孔后，开口周围顶点沿 -Y 方向压凹，cosine 平滑衰减，最深 10mm。

**问题**：杏仁形尖角顶点压得最深 → 锯齿（星爆）。关闭后，凹陷由碗负责。

### 7.4 ngon 封口 + pointmerge 碗底（已弃用）

**原理**：用三角化 ngon 封口 + 合并顶点到碗底中心。

**问题**：留非流形边（碗底重复面），构造上无法保证零碎片。

**替代**：单个共享极点 + 三角扇（经典 UV 球极点拓扑）。

### 7.5 角度排序找边界环（已弃用）

**原理**：`atan2` 角度排序边界顶点。

**问题**：排序破坏拓扑顺序，quad 用跨越新边不共享原边界边 → 原边界边悬空成锯齿裂口。

**替代**：拓扑行走顺序（邻接表 BFS）。

### 7.6 过渡环压凹（v24-v25，已移除）

**原理**：移动 ring0 外侧皮肤顶点朝 +Y 压凹，cosine 衰减。

**问题**：
- 方向 bug（ring0 处压凹=0，外侧=1mm，方向反了）
- 用户不满意："不是移动顶点，是增加面数"

**替代**：皮肤面细分 + 初步法线改善。

### 7.7 bevel 羽化（v29，已回退）

**原理**：对 ring0 边做 `bmesh.ops.bevel`（segments=2, offset=1.5mm）。

**问题**：在三角网格上产生开放边（96/33）和非流形边（56）和 ngon（266）。

**替代**：皮肤面细分（不产生开放边）。

### 7.8 错误法线校正（v28，已修正）

**问题**：用"法线朝碗轴 = 朝内 = 错误"的判据反转碗面法线，但凹陷碗壁的朝碗轴特性是正常几何特征。

**修正**：只翻 `normal.y > 0`（朝头内）的面。

## 9. v38 面朝向修复定案（2026-08-18，用户确认"面朝向好了"）

### 9.1 根因（三个错误判断逐层剥开）

**错误1：`recalc_face_normals` 对混合集根本不适用。** 它按"大多数面的方向"统一翻转，但眼窝区是碗面（应朝-Y）+倒角带+皮肤的混合集，多数面方向≠眼窝正确方向，越算越乱。→ v38 起彻底跳过 recalc，改用几何定向。

**错误2："碗面法线应朝眼球"的判据是错的。** 碗面法线必须 **normal.y < 0（朝头前/-Y）**。倒角带是环带过渡，其法线自然有朝侧面的 x/z 分量，用"朝眼球"（dot 方向）判据会把倒角带误判为反向。统一判据：眼窝区所有面 normal.y>0 即翻转。

**错误3：误以为"翻转不生效"——其实是诊断脚本自己的单位 bug。** `diagnose_geometry2.py` 把 xz 坐标（米）当毫米算，圈定范围错误，报"大量+Y面"。实际产物眼窝区仅 L=3 / R=0 个+Y面。教训：**诊断脚本本身也必须校验**，不能拿诊断输出直接下结论。

### 9.2 修复实现（为什么能持久生效）

- 翻转用 `bmesh.ops.reverse_faces` + `bm.normal_update()`，**正确顺序**（先翻转再更新法线缓存）
- EDIT 模式下绕序修改是持久的（test_flip.py 验证：绕序翻转在保存/重开后保持）
- 翻转后立即自检：统计仍 normal.y>0 的面数 → 管线日志 `still wrong=0`

### 9.3 输入模型固有法线问题（非管线责任）

输入模型（FBX导入）本身 **43.4% 面法线朝+Y（朝头内）**——删除 custom_normal 数据后暴露真实绕序。这是 01 高模阶段/导入阶段的问题，与 01A 管线无关。01A 只保证眼窝区定向正确。全局法线统一属于 01 阶段，用户未要求扩展。

### 9.4 vision 灰模误判教训

法线检查材质（红=背面/绿=正面）渲染下，vision 多次对灰模误判（把输入固有43%说成"管线把模型翻烂了"）。**灰模判断一律用定量法线统计，不靠 vision；vision 只用于贴图等渲染后的定性问题，且要等贴图渲染。**

## 19. v48 内圆角平滑接缝（2026-08-21 上午，用户定案满意版本）

### 19.1 用户需求

方案A（不倒角）M 形消除后，用户提出：**脸与眼窝的接缝（rim 那圈）要平滑**，可以加线或倒角，但绝不能出现 M 形。

### 19.2 设计原则（从 M 形事故提炼）

M 形凸脊的产生条件是"先向外扩再收缩"——外扩最远处形成凸棱。因此接缝圆角**只向内收 + 下沉，全程不超过 rim 半径**，几何上不存在外凸段，不可能形成 M 形。

### 19.3 实现（`inward_fillet` 变体，eye_socket_config.py）

- `SOCKET_FILLET_RINGS = 4`：接缝处 4 环内圆角
- `SOCKET_FILLET_INWARD = 1.2mm`：径向内收（W 正值=内收，rad_dirs 指向眼中心）
- `SOCKET_FILLET_DEPTH = 0.6mm`：圆角下沉深度
- quintic smoothstep 起步斜率为零 → 与脸部皮肤切线连续，接缝无硬边
- 之后衔接碗面正常收缩（NR=16 环）

### 19.4 符号 bug（实现时及时发现）

初版误写 `W = -SOCKET_FILLET_INWARD`（以为负值=内收）。实际代码 `pos = base + rad_dirs * radial`，rad_dirs 指向眼中心，**W 正值才是内收**（原倒角自检"半径减小 2.34mm"证实）。负值会外扩——正好会造出 M 形凸脊。跑前读环生成代码发现，修正为正值。
