# 数字人资产生产管线 — 终端控制端（演示版 v2.3）

录屏汇报用：在终端输入命令，真实调用 Blender 5.1 逐环节处理，单行动态进度实时刷新，产物落到对应输出文件夹。

## 用法

```
python 控制台.py
```

| 命令 | 环节 | 说明 | 实测耗时 |
|---|---|---|---|
| `01` | 高模修复与黏连检测 | raw_model.glb → 96.5万顶点修复后高模 | ~4 分钟 |
| `01a` | 眼窝重建（**半自动打点**）| 放点→GUI手调→镜像→读取→开孔→赋材质 | ~2 分钟（+手动） |
| `02` | 拓扑重建 + 眼窝碗 + 眼球摆入 | QR自动拓扑(目标15万quad, ≤35万tris) → 碗(纯rim程序化: 深度/环数自算) → 眼球摆入(并入输出) | ~3 分钟 |
| `03` | 自动UV展开 | Smart Project + **UV浪费检测&参数自动寻优**(利用率/空块/密度 全数据计算) | ~1 分钟 |
| `04` | 纹理烘焙 | 4K Diffuse + Normal | ~30 秒 |
| `05` | 骨骼绑定与动作重定向 | **AI打点**→55骨→走/跑/跳（交付3个bl：未标准化/标准化/动作） | ~1.5 分钟（含手动） |
| `06` | GLB导出 | 从04_动作测试导出**单文件GLB**(4K贴图内嵌·米制比例·走/跑/跳三动画) + 重导入复核 | ~10 秒 |
| `all` | 全流程顺序执行 | 01→01a→02→03→04→05→06 | ~12 分钟 |
| `clean [环节/all]` | 清理输出(递归) + 中间件 | 保留脚本/手调文件/原始文件 | 即时 |
| `status` | 查看各环节产物状态 | — | 即时 |

## 演示特性

1. **单行动态进度**：旋转符 + 进度条 + 百分比 + 用时 + 实时阶段名，原地刷新不刷屏；详细数据写 `logs/`
2. **内容连续显示**：不主动清屏，历史可上下翻看；每环节以分隔线+摘要框收尾（详细数据写 `logs/`）
3. **打点环节开 Blender GUI**：01a 眼裂轮廓、05 关节点位，自动打点后**打开 GUI 让你手动微调**，调整完关窗即自动继续——展示半自动人工介入能力
4. **05 自动弹出《点位指南.md》**：手动调点时同步参考
5. **噪声过滤**：Better FBX 等插件后台注册的红色 Traceback 自动隐藏（真实报错照常显示），录屏画面干净

## 手动打点环节（演示重点）

| 环节 | 打点内容 | 流程 |
|---|---|---|
| 01a | 眼裂轮廓（右眼12点） | 自动放点 → GUI手调 → 镜像到左眼 → 样条加密72点轮廓 |
| 05 | 17关节标记 | AI自动打点 → GUI手调（镜像约束同步左右）→ go_detect建骨架 |

> 跳过GUI（用现有点位）：设环境变量 `DEMO_SKIP_GUI=1`（仅自动化测试用，正式录屏别设）

## 目录

- `原始文件/` — 输入资产：Tripo高模GLB、**眼睛模型002(Eye.fbx + Textures)**、Mixamo动画FBX×4、眼位检测JSON、修复贴图
- **无 交付/ 目录**（2026-09-17 用户定）：测试期产物一律写各 stage 的 `输出/`（`01a眼窝眼球/输出`、`02QR拓扑/输出` …），中间件收各 stage 的 `_中间/`；脚本在各 stage 的 `scripts/`；定稿后才另行整理交付
- `01高模修复/输出` ~ `06GLB导出/输出` — 各环节产物（`clean` 递归清理此处 + `_中间/`）
- `控制台.py` — 终端入口
- `logs/` — 每次运行的完整日志

## 关键说明

- 所有环节**真实运行**，输出数字均为真实处理数据
- 眼球用 **Eye.fbx**（眼睛模型002，单只眼663顶点已合并、瞳孔朝-Y、Hazel色）：**02 环节(碗之后)摆入并直接并入输出**，且不进03/04（04烘焙用它会在多物体时选错对象）；**05 绑定阶段把眼球并入并蒙皮到 Head 骨**
- 05 动作重定向是测量驱动的 rest 补偿重定向：骨架结构与权重完全不动（41根连接、关节重叠保持），逐帧把 Mixamo 参考的世界姿态增量换算到我们的骨架上（绝对世界朝向与参考逐帧 0.000° 误差），帧数完全按参考动画原样（走36/跑20/跳31）
- **06 输出 `06_角色_走跑跳.glb`**：glTF 2.0 单文件（4K贴图内嵌），三动画 Standard Walk 1.20s / Running 0.67s / Jump 1.03s（30fps）；内置三段自查——导出 → 解析GLB头部(动画/皮肤/关节/图像) → 重导入复核（比例 1单位=1米、55骨、逐帧变形签名 ≤0.07mm）
- 每环节跑完自动落产物到输出文件夹，`status` 可随时查进度

## 录屏前自检

录屏前确认 `status` 全部"未生成"（干净状态），从 `01` 或 `all` 开始跑。若要重录，重跑会覆盖旧产物。
