# _备份/ — 历史中间产物快照

**这是什么**：迭代过程中被覆盖的 `.blend` 快照（旧的 01A/02QR/05 产物、Blender 自动备份 `.blend1`、历次 `_备份_*` 文件）。

**为什么需要它**：`.blend` 文件被 `.gitignore` 排除（单个 60~80MB），git / logs/*.md / skill 记录的是**做法、参数、判据、教训**，但没法回答"上一版几何到底长什么样"——做 A/B 基线对比时需要真实文件。所以文件级快照只能留在磁盘上。

**结构**：与项目目录一一对应的镜像。

| 目录 | 内容 |
|---|---|
| `交付/…` | 原先堆在 `交付/` 各 stage `models/` 里的历次备份（52 个） |
| `01a眼窝眼球/输出/` | 01A 工作目录里被覆盖的旧产物 |
| `02QR拓扑/输出/` | QR 工作目录里的旧产物 + `_备份_v58c_rim重构前/` |
| `01高模修复/…`、`03…/04…/05…` | 同级目录里的 `.blend1` 与旧备份 |

**可以随时整体删除**：删掉不影响任何流程，只失去"回看历史几何"的能力。想恢复某一版时，从这里取即可。

**现行规则（避免再堆乱）**
1. 测试阶段所有产物只写各 stage 顶层目录的 `输出/`（`01高模修复/输出` → `01a眼窝眼球/输出` → `02QR拓扑/输出` → …）；`交付/` 只在定稿后整理。
2. 覆盖前要留快照，就放这里（`_备份/<原路径>`），**不再堆在输出目录里**。
3. 代码/脚本/参数/判据一律走 git + `logs/*.md` + skill，不做文件备份。
4. 名字里带"权威"的文件（如 `01_AI打点_手调权威备份.blend`）任何情况都不动。
